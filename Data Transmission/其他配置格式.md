# 其他配置格式

> TOML、INI、.env、HCL、Protobuf 等——不像 XML/JSON/YAML 那么通用，但各有自己深耕的领域。

---

## TOML

TOML（Tom's Obvious, Minimal Language）比 YAML 更规范，类型歧义更少。Python `pyproject.toml`、Rust `Cargo.toml` 都用它。

### 语法

```toml
# 顶级键值
title = "My Project"
version = "1.0.0"
debug = false

# 表（对象）
[owner]
name = "Alice"
email = "alice@example.com"

# 内联表
[server]
host = "0.0.0.0"
ports = [8080, 8443]

# 表数组
[[dependencies]]
name = "flask"
version = "3.0"

[[dependencies]]
name = "requests"
version = "2.31"
optional = true

# 点分隔键
[server.tls]
enabled = true
cert_file = "/etc/ssl/cert.pem"
```

### 数据类型

```toml
# 字符串（双引号支持转义，单引号字面量）
str_double = "hello\nworld"       # 换行转义
str_single = 'hello\nworld'       # 原样 \n
str_multiline = """
多行字符串
"""

# 数字
int_val = 42
float_val = 3.14
hex_val = 0xDEAD_BEEF
oct_val = 0o755
bin_val = 0b1010
inf_val = +inf
nan_val = nan

# 日期时间
date_val = 2024-06-18
time_val = 10:30:00
datetime_val = 2024-06-18T10:30:00+08:00

# 数组
numbers = [1, 2, 3]
mixed = [1, "two", 3.0]
nested = [[1, 2], [3, 4]]

# 布尔和空
enabled = true
value = null    # 不能写 nil 或 NULL
```

### 表数组详解

```toml
# 单个表数组元素
[[products]]
name = "Hammer"
sku = 738594937
price = 12.99

# 多个元素可以分开写（TOML 会自动合并同名的表数组）
[[products]]
name = "Nail"
sku = 284758393
price = 0.99
```

## INI

最古老的配置格式，Windows `.ini` 文件和 PHP `php.ini` 经典格式。

```ini
; 分号是注释
# 有些解析器也支持井号

[server]
host = 0.0.0.0
port = 8080

[database]
driver = mysql
host = localhost
name = mydb
user = root
password = secret
```

没有嵌套、没有数组、没有类型——全部是字符串，解析全靠 `=` 切割。

**不同解析器的行为差异：**

| 解析器 | duplicate keys | 空格处理 | 大小写 |
|--------|---------------|----------|--------|
| Python `configparser` | 取最后一个值 | `key = val` 去首尾空格 | 键不敏感（默认） |
| PHP `parse_ini_file` | 取最后一个值 | 去首尾空格 | 节名和键名不敏感 |
| Windows API `GetPrivateProfileString` | | 不去空格 | 键不敏感 |

## .env

Docker、Node.js、Python（python-dotenv）中管理环境变量。

```bash
# .env（注释用 #）

# 基本格式
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASS=secret_without_quotes

# 带空格的用引号
MESSAGE="hello world"

# 多行值
CERT="-----BEGIN CERTIFICATE-----
MIIDXTCCAkWgAwIBAgIJAKl...
-----END CERTIFICATE-----"

# 引用其他变量
API_URL=http://${DB_HOST}:8080/api

# 默认值
LOG_LEVEL=${LOG_LEVEL:-info}

# 空值
EMPTY_VAR=

# 布尔习惯
DEBUG=false            # 仍然是字符串 "false"
```

**安全事项：**

| 风险 | 说明 |
|------|------|
| 提交到 Git | `.env` 误提交是最常见的密钥泄露方式之一——在 `.gitignore` 中加 `.env`，模板可用 `.env.example` |
| 容器环境变量暴露 | `docker inspect` 或 `docker compose config` 会明文显示所有环境变量 |
| `/proc` 读取 | 同一主机上其他用户可通过 `/proc/<PID>/environ` 读出容器的环境变量 |
| 子进程继承 | 容器中的所有子进程都能访问全部环境变量 |

## HCL（HashiCorp Configuration Language）

Terraform、Vault、Consul、Nomad 使用。JSON 的超集，但语法更简洁。

```hcl
# 变量定义
variable "environment" {
  description = "部署环境"
  type        = string
  default     = "development"

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "环境必须是 dev, staging 或 prod"
  }
}

# 本地值（中间计算结果）
locals {
  name_prefix = "${var.environment}-myapp"
  common_tags = {
    Environment = var.environment
    Project     = "myapp"
    ManagedBy   = "Terraform"
  }
}

# 数据源（从外部获取信息）
data "aws_ami" "ubuntu" {
  most_recent = true
  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"]
  }
}

# 资源定义
resource "aws_instance" "web" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t3.micro"

  tags = merge(local.common_tags, {
    Name = "${local.name_prefix}-web"
  })
}

# 输出
output "web_public_ip" {
  value       = aws_instance.web.public_ip
  description = "Web 服务器的公网 IP"
}
```

## Protocol Buffers（Protobuf）

Google 的二进制序列化格式，gRPC 默认序列化方式。

```protobuf
syntax = "proto3";

package myapp;

// 消息定义
message User {
    string name = 1;          // = 1 是字段编号，不是赋值
    int32 age = 2;
    repeated string skills = 3;
    optional string email = 4;
    Status status = 5;
}

enum Status {
    STATUS_UNSPECIFIED = 0;   // 枚举第一个值必须是 0
    ACTIVE = 1;
    INACTIVE = 2;
}
```

**原理：** `.proto` 文件定义消息结构，用 `protoc` 编译生成目标语言的类代码（Python/Go/Java/C++ 等），实例序列化后是二进制字节流。

**Wire Types：**

| Type | 适用于 | 说明 |
|------|--------|------|
| 0 | `int32`, `sint32`, `bool`, `enum` | 变长编码（Varint） |
| 1 | `fixed64`, `double` | 64 位定长 |
| 2 | `string`, `bytes`, `message` | 长度前缀 + 数据 |
| 5 | `fixed32`, `float` | 32 位定长 |

**字段编号规则：**
- 1-15：单字节编码（最紧凑），留给高频字段
- 16-2047：双字节编码
- 一旦用于生产，字段编号不能修改或删除（会破坏向后兼容）

## 选格式决策

| 场景 | 推荐 | 原因 |
|------|------|------|
| Web API 数据交换 | JSON | 通用、语言原生 |
| 人写配置文件 | YAML / TOML | 可读性好（YAML 注意隐式类型陷阱） |
| 程序读写配置 | JSON / TOML | 解析简单、类型明确 |
| 简单键值对 | .env / INI | 无需解析库 |
| 严格类型校验 | JSON Schema / XML Schema | Schema 成熟 |
| 企业系统对接 | XML | SOAP、SAML 生态 |
| 容器编排 | YAML | Docker Compose / K8s 标准 |
| 基础设施即代码 | HCL | Terraform 生态 |
| 高性能 RPC | Protobuf | 二进制、体积小、跨语言代码生成 |
| Python 项目元信息 | TOML | `pyproject.toml` 标准（PEP 621） |

## 安全视角总结

| 格式 | 主要风险 | 关键防御 |
|------|---------|---------|
| XML | XXE 外部实体注入、XPath 注入、Billion Laughs DoS | 禁用 DOCTYPE/外部实体、用 `defusedxml` |
| JSON | 原型污染（JS）、大数精度、JSONP 注入、JWT 算法混淆 | 用 `JSON.parse()` 不用 `eval()`、强制 JWT 算法、不信任用户 JSON 键名 |
| YAML | 反序列化代码执行、隐式类型转换 | `safe_load()`、歧义值加引号 |
| .env | 误提交到 Git、容器环境变量可被 `docker inspect` 读取 | `.gitignore` 中排除、生产环境用 Secret Manager |
| INI | 无类型校验、解析器行为不一致 | 不用于关键安全配置 |
| TOML | 目前无已知严重漏洞 | 天然安全（纯数据、有 Schema） |
| HCL | Terraform state 文件泄露敏感信息 | 加密 state 文件、远程 backend |
| Protobuf | 二进制不可审计、字段编号冲突 | 规范字段编号管理、禁止删除已用编号 |
