# 协议地图

> [!abstract] 这篇笔记是什么
> 一张从应用层到物理层的协议层级地图。学网络协议最容易乱的就是"这个协议到底在哪一层"，这张图 + 下面的表格用来随时定位。图中每个方框是一层，层内是这一层的代表协议，箭头方向就是数据封装的方向（上层协议搭载在下层之上传输）。
> 图用纯文本画的，放在代码块里，哪里看都不会变形。

```text
┌─ 应用层 · 报文(Message) ──────────────────────
│   HTTP(S)      DNS       FTP       SSH       Telnet
│   SMTP / IMAP / POP3     DHCP      Gopher
└───────────────────────────────────────────────
                     ↓  封装（接收方解封装，方向相反）
┌─ 传输层 · 段(Segment) · 端口 ─────────────────
│   TCP       UDP       QUIC（基于UDP）
└───────────────────────────────────────────────
                     ↓
┌─ 网络层 · 包(Packet) · IP地址 · 路由器 ───────
│   IPv4/IPv6      ICMP      ARP（2.5层）      IGMP
└───────────────────────────────────────────────
                     ↓
┌─ 数据链路层 · 帧(Frame) · MAC地址 · 交换机 ───
│   Ethernet 以太网      802.11 WiFi
│   PPP / PPPoE      VLAN（802.1Q）
└───────────────────────────────────────────────
                     ↓
┌─ 物理层 · 比特(Bit) · 集线器/中继器 ──────────
│   双绞线 / 光纤      无线电波
└───────────────────────────────────────────────
```

## 1. 三种分层模型对照

| OSI 七层 | TCP/IP 四层 | 教学常用五层 | 这一层的核心问题 |
|---|---|---|---|
| 7 应用 | 应用层 | 应用层 | 提供具体服务：网页、邮件、域名解析 |
| 6 表示 | （并入应用层） | （并入应用层） | 编码、加密、压缩（TLS 通常算在这附近） |
| 5 会话 | （并入应用层） | （并入应用层） | 建立/管理/终止会话 |
| 4 传输 | 传输层 | 传输层 | 端到端通信：端口、可靠性（TCP/UDP） |
| 3 网络 | 网际层 | 网络层 | 寻址与路由：IP 地址 |
| 2 数据链路 | 网络接口层 | 数据链路层 | 相邻节点通信：MAC 地址、成帧 |
| 1 物理 | （并入网络接口层） | 物理层 | 比特流如何变成电信号/光信号/无线电 |

记忆线索（自上而下）：**报文 → 段 → 包 → 帧 → 比特**，每往下走一层就加一个头部，这是"封装"；接收方反过来拆，叫"解封装"。

## 2. 各层协议清单

### 应用层

| 协议 | 端口 | 承载 | 一句话 |
|---|---|---|---|
| HTTP | 80 | TCP | 网页传输，明文 → 笔记：[[HTTPandHTTPS]] |
| HTTPS | 443 | TCP | HTTP + TLS 加密 |
| DNS | 53 | UDP（区域传输等用 TCP） | 域名 → IP → 笔记：[[DNS]] |
| FTP | 21 控制 / 20 数据 | TCP | 文件传输，明文 |
| SSH | 22 | TCP | 加密远程登录 |
| Telnet | 23 | TCP | 明文远程登录，基本只活在历史和靶场里 |
| SMTP | 25 / 587 | TCP | 发邮件 |
| POP3 / IMAP | 110 / 143（SSL 版 995 / 993） | TCP | 收邮件 |
| DHCP | 67 / 68 | UDP | 自动分配 IP 地址 |
| SNMP | 161 / 162 | UDP | 网络设备监控管理 |
| NTP | 123 | UDP | 时间同步 |
| RDP | 3389 | TCP | Windows 远程桌面 |
| MQTT | 1883 / 8883 | TCP | 物联网消息协议 |
| Gopher | 70 | TCP | WWW 之前的信息检索协议，已淘汰 → 笔记：[[Gopher]] |

### 传输层

| 协议 | 特点 |
|---|---|
| TCP | 面向连接（三次握手）、可靠、有序、流量/拥塞控制 |
| UDP | 无连接、不可靠但快，适合 DNS、视频、游戏 |
| QUIC | HTTP/3 的底座，在 UDP 上自己实现了可靠传输，降低握手延迟 |

### 网络层

| 协议 | 一句话 |
|---|---|
| IPv4 / IPv6 | 寻址和路由的主体 |
| ICMP | IP 的搭档，ping / traceroute 靠它，端口扫描的底层反馈也是它 |
| ARP | IP → MAC 解析，严格说夹在网络层和数据链路层之间 → 笔记：[[ARP]]、[[DNS与ARP的协同合作]] |
| IGMP | 组播管理 |

### 数据链路层

| 协议 | 一句话 |
|---|---|
| Ethernet（以太网） | 有线局域网的事实标准，MAC 寻址 |
| 802.11 | WiFi 的 MAC 层标准 |
| PPP / PPPoE | 点对点链路，家庭宽带拨号用 PPPoE |
| VLAN（802.1Q） | 在交换机上划虚拟局域网，打标签 |

### 物理层

没有"协议"只有规范：双绞线、光纤、无线电、编码方式、速率。设备是集线器（Hub）和中继器——它们不认识帧也不认识 IP，只放大转发电信号。

## 4. 易混的"跨层"协议（考试爱考）

- **TLS**：不属于单一层，位于传输层之上、给应用层协议套加密，OSI 里常被塞进表示层
- **ARP**：为网络层的 IP 服务，但报文直接封装在以太网帧里，所以常被画在 2.5 层
- **QUIC**：跑在 UDP（传输层）上，干的却是传输层的活
- **ICMP**：属于网络层，但它是 IP 的组成部分，不占用端口（所以 ping 没有"端口"概念）
- **路由协议位置各不相同**：OSPF 直接封装在 IP 上，BGP 跑在 TCP 179，RIP 跑在 UDP 520——协议在哪层不等于它管理哪层
