# 端口占用与进程管理

> 启动服务时报 `address already in use` 是每个开发者都会遇到的事。核心流程就两步：查谁占的端口，杀掉它。

---

 ## Linux

### 第一步：查看端口被谁占用

四种方式，选一个顺手的：

```bash
# 方式一：ss（推荐，现代 Linux 标配，速度快）
ss -tlnp | grep :8080

# 方式二：netstat（老牌工具，部分精简系统需要额外安装 net-tools）
netstat -tlnp | grep :8080

# 方式三：lsof（需要安装 lsof，但输出最详细）
lsof -i :8080

# 方式四：fuser（最简洁，直接出 PID）
fuser 8080/tcp
```

参数说明：
- `ss -tlnp`：`-t` TCP，`-l` 监听中的端口，`-n` 不解析域名（加快速度），`-p` 显示进程名
- `netstat -tlnp`：同上
- `lsof -i :8080`：列出所有使用 8080 端口的文件和进程

### 第二步：杀进程

```bash
# 先拿到 PID，然后：

# 温柔地杀（给进程清理资源的机会）
kill <PID>

# 强制终止（进程不响应时用）
kill -9 <PID>

# 一行搞定——查端口直接杀
fuser -k 8080/tcp
```

### 常见问题

**杀掉又马上出现？** 说明有守护进程（supervisor / systemd）在自动重启它。正确的做法是停服务而不是杀进程：

```bash
systemctl stop <服务名>
```

**没有 sudo 看不到进程名？** `ss -tlnp` 和 `netstat -tlnp` 在非 root 下只显示 `-` 代替进程名。加 `sudo`：

```bash
sudo ss -tlnp | grep :8080
```

## Windows

### 第一步：查看端口被谁占用

```cmd
# 查出占用端口的 PID
netstat -ano | findstr :8080
```

输出示例：
```
TCP    0.0.0.0:8080    0.0.0.0:0    LISTENING    12345
```

最后一列 `12345` 就是 PID。

### 第二步：确认是什么进程（可选）

```cmd
# 看看这个 PID 对应什么程序
tasklist | findstr 12345
```

输出示例：
```
java.exe    12345  Console    1    512,000 K
```

### 第三步：杀进程

```cmd
# 按 PID 杀
taskkill /PID 12345 /F

# 或者按进程名杀（会杀掉所有同名进程，谨慎）
taskkill /IM java.exe /F
```

参数说明：`/F` 强制终止，不加 `/F` 会走正常关闭流程。

### PowerShell 方式（Win 10+）

```powershell
# 一步到位：查端口，拿 PID，杀进程
Get-Process -Id (Get-NetTCPConnection -LocalPort 8080).OwningProcess | Stop-Process -Force
```

拆开来看：

```powershell
# 查看端口占用
Get-NetTCPConnection -LocalPort 8080

# 拿到 PID 后杀进程
Stop-Process -Id <PID> -Force
```

## 速查表

| 操作 | Linux | Windows (cmd) | Windows (PowerShell) |
|---|---|---|---|
| 查端口占用 | `ss -tlnp \| grep :8080` | `netstat -ano \| findstr :8080` | `Get-NetTCPConnection -LocalPort 8080` |
| 查进程详情 | `ps -p <PID> -o comm=` | `tasklist \| findstr <PID>` | `Get-Process -Id <PID>` |
| 正常终止 | `kill <PID>` | `taskkill /PID <PID>` | `Stop-Process -Id <PID>` |
| 强制终止 | `kill -9 <PID>` | `taskkill /PID <PID> /F` | `Stop-Process -Id <PID> -Force` |
| 一行解决 | `fuser -k 8080/tcp` | — | `Get-Process -Id (Get-NetTCPConnection -LocalPort 8080).OwningProcess \| Stop-Process -Force` |

## 补充：查看所有监听端口

有时候不确定具体端口号，需要先看看系统上都开了哪些端口：

```bash
# Linux
ss -tlnp                          # 只看 TCP 监听端口
ss -tulnp                         # TCP + UDP 监听端口

# Windows cmd
netstat -ano | findstr LISTENING  # 所有监听端口

# Windows PowerShell
Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
```

## 各环境兼容性差异

> 以下基于命令文档整理，未在所有环境实测，遇到不一致时欢迎修正。

### 命令可用性

| 命令 | Debian/Ubuntu | CentOS/RHEL | Alpine (Docker 常见) | WSL (Ubuntu) | macOS |
|---|---|---|---|---|---|
| `ss` | 自带 | 自带 | 自带（busybox 版，不支持 `-p`） | 自带 | 没有 |
| `netstat` | 需 `apt install net-tools` | 自带 | 没有（需 `apk add net-tools`） | 同 Ubuntu | `netstat -anv`，参数不同 |
| `lsof` | 需 `apt install lsof` | 需 `yum install lsof` | 需 `apk add lsof` | 同 Ubuntu | 自带，用法相同 |
| `fuser` | 自带（psmisc 包） | 自带 | 需 `apk add psmisc` | 自带 | 自带 |

### 各环境注意事项

**Alpine Linux（Docker 里最常见）**：busybox 版的 `ss` 阉割了 `-p` 参数，不显示进程信息。

```bash
# Alpine 容器内 ss -p 没用，不显示进程列
ss -tlnp

# 替代方案：装 net-tools
apk add net-tools
netstat -tlnp | grep :8080
```

**macOS**：BSD 系，和 Linux 参数不一样。

```bash
# 查端口占用
lsof -i :8080

# 列出所有 TCP 监听端口（Linux 的 ss -tlnp 等价写法）
lsof -iTCP -sTCP:LISTEN -n -P

# 一行杀掉占端口的进程（macOS 没有 fuser -k）
lsof -ti :8080 | xargs kill -9
```

**WSL**：本质就是 Linux，跟对应发行版用法一样。唯一要注意的是 Windows 宿主机占的端口在 WSL 里看不到，Windows 侧的占用需要切到 cmd/PowerShell 用 `netstat -ano | findstr :端口` 查。

**CentOS 6 / RHEL 6（老系统）**：没有 `ss` 命令，只能用 `netstat`。

### 一句话选型

| 场景 | 推荐命令 |
|---|---|
| 常见 Linux 发行版 | `ss -tlnp` |
| Docker 容器（Alpine 镜像） | `netstat -tlnp`（先 `apk add net-tools`） |
| macOS | `lsof -i :PORT` |
| 不确定环境 | `lsof -i :PORT`（最通用，但需安装） |
