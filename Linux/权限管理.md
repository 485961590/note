# Linux 权限管理

> Linux 权限分两层：DAC（自主访问控制，chmod/chown/chattr 管这层）决定谁读谁写；MAC（强制访问控制，SELinux 管这层）在 DAC 之上再加一层白名单规则。两层都通过，进程才能访问文件。

---

## 第一部分：传统权限 (DAC)

### 1.1 rwx 权限位

Linux 中每个文件有三组权限，每组三个位：

```
  rwx  rwx  rwx
   │    │    │
  所有者  组   其他人
```

| 权限位 | 字母 | 数字 | 对文件的含义 | 对目录的含义 |
|--------|------|------|-------------|-------------|
| 读 | `r` | 4 | 可以查看文件内容 | 可以列出目录内容（ls） |
| 写 | `w` | 2 | 可以修改文件内容 | 可以在目录内创建/删除文件 |
| 执行 | `x` | 1 | 可以作为程序运行 | 可以进入目录（cd） |

**数字模式**——三组权限各用一个 0-7 的数字表示：

```bash
chmod 755 script.sh            # rwxr-xr-x  (所有者全权限，组和其他人读+执行)
chmod 644 file.txt             # rw-r--r--  (所有者读写，组和其他人只读)
chmod 600 id_rsa               # rw-------  (只有所有者能读写)
chmod 700 ~/.ssh               # rwx------  (只有所有者能进入和操作，SSH 目录强制要求)
```

**符号模式**——按角色增删权限：

```bash
chmod u+x script.sh            # 所有者(u)加执行权限
chmod g-w file.txt             # 组(g)去掉写权限
chmod o= file.txt              # 其他人(o)设为无权限
chmod a+r file.txt             # 所有人(a)加读权限
chmod -R 755 /var/www/         # 递归修改整个目录
```

**权限的实践含义：**

```bash
# 目录必须有 x 才能 cd 进去，仅有 r 只能看到文件名列表
dr--r--r--  dir/    → ls dir/ 能看到文件名，cd dir 失败
dr-xr-xr-x  dir/    → cd dir 成功，ls dir 成功

# 文件必须有 r 才能读内容，有 x 才能作为程序执行
-rw-r--r--  script  → 可用 cat 查看内容，./script 失败
-rwxr-xr-x  script  → ./script 能执行
```

### 1.2 属主与属组 (chown / chgrp)

```bash
# 修改所有者
chown user file.txt
chown -R user /var/www/             # 递归

# 同时修改所有者和组
chown user:group file.txt

# 只修改组
chgrp devteam file.txt
chgrp -R devteam /opt/project/
```

**为什么属组重要：** 一个用户可以在多个组里。如果文件属组是 `dev`，且权限是 `rw-rw----`，那么 `dev` 组的所有成员都能读写这个文件——即使他们不是文件所有者。

查看当前用户属于哪些组：

```bash
groups username
id username
```

### 1.3 特殊权限 (setuid / setgid / sticky bit)

除了 rwx 三组基本权限外，还有三个特殊权限位。

#### setuid (4---)

**作用：** 在**文件**上设置后，任何人执行该文件时，都以**文件所有者**的身份运行。

```bash
# 查看 setuid 文件
ls -la /usr/bin/passwd
# -rwsr-xr-x. 1 root root ... /usr/bin/passwd
#   ↑ s 替代了所有者的 x，表示 setuid 已设置

# 设置 setuid
chmod u+s /path/to/binary
# 或数字模式：在标准三位前加 4
chmod 4755 /path/to/binary
```

`passwd` 是 setuid 的经典案例：普通用户执行 `passwd` 改密码时需要写入 `/etc/shadow`，而 `/etc/shadow` 只有 root 能写。`passwd` 二进制设置了 setuid root，所以普通用户执行它时临时获得了 root 权限，能修改 shadow 文件。

**安全风险：** setuid root 程序如果有漏洞，攻击者可以提权到 root。因此应严格控制 setuid 文件的数量。

```bash
# 查找系统中所有 setuid 文件（安全审计常用）
find / -perm -4000 -type f 2>/dev/null
```

#### setgid (2---)

**在文件上：** 执行时以文件**属组**的身份运行。

```bash
chmod g+s /path/to/binary
chmod 2755 /path/to/binary
```

**在目录上：** 目录内新建的文件自动继承该目录的**属组**，而不是创建者的主组。

```bash
chmod g+s /shared/project/
ls -ld /shared/project/
# drwxr-sr-x 2 root dev ... /shared/project/
#        ↑ s 替代了组的 x

# 谁在 /shared/project/ 下创建文件，文件属组都是 dev
```

这是一个被低估但极其有用的功能：多人协作目录，设置 `setgid + 目录属组为 dev`，确保所有新建文件都属于 `dev` 组，不会因为某人的 umask 或主组不对而导致别人无法访问。

```bash
# 查找 setgid 目录
find / -perm -2000 -type d 2>/dev/null
```

#### sticky bit (1---)

**作用：** 在**目录**上设置后，目录内的文件只有**文件所有者**和 **root** 能删除或重命名。即使目录权限是 `777`，用户也不能删除别人的文件。

```bash
# /tmp 目录的典型权限
ls -ld /tmp
# drwxrwxrwt. 10 root root ... /tmp
#           ↑ t 替代了其他人的 x

# 设置 sticky bit
chmod +t /shared/uploads/
chmod 1777 /shared/uploads/
```

经典用例：
- `/tmp` -- 所有用户都能在里面创建临时文件，但不能删别人的
- `/var/tmp` -- 同上，但跨重启保留
- 共享上传目录 -- 用户可以上传文件，不能删除别人的文件

#### 特殊权限在 ls -l 中的显示

| 权限 | 数字前缀 | 有执行权限时显示 | 无执行权限时显示 |
|------|---------|----------------|----------------|
| setuid | 4 | `rws` (小写 s) | `rwS` (大写 S，表示无效) |
| setgid | 2 | `rws` (小写 s) | `rwS` (大写 S，表示无效) |
| sticky | 1 | `rwt` (小写 t) | `rwT` (大写 T，表示无效) |

**关键细节：** 大写 S/T 表示该特殊权限位设置了但因为缺少基础执行权限而**实际上无效**。`rwS` 意味着 setuid 设置了但所有者没有 x 权限——这个 setuid 不会生效。

### 1.4 默认权限 (umask)

**作用：** 控制新建文件和目录的默认权限。umask 的值是"要屏蔽的权限位"。

```bash
# 查看当前 umask
umask
# 通常输出 0022（即 022）

# 临时修改
umask 027
```

**计算规则：**

```
目录默认权限 = 0777 - umask
文件默认权限 = 0666 - umask（文件默认不给执行权限）
```

| umask | 新建目录权限 | 新建文件权限 | 适用场景 |
|-------|------------|------------|---------|
| 022 | 755 (rwxr-xr-x) | 644 (rw-r--r--) | 默认值，组和其他人可读 |
| 002 | 775 (rwxrwxr-x) | 664 (rw-rw-r--) | 组内协作 |
| 027 | 750 (rwxr-x---) | 640 (rw-r-----) | 较安全，组可读其他人不可读 |
| 077 | 700 (rwx------) | 600 (rw-------) | 最严格，只有所有者可访问 |

永久设置：写入 `~/.bashrc` 或 `/etc/profile`。

## 第二部分：扩展属性 (chattr / lsattr)

`chattr` 设置的属性**凌驾于 root** 之上——即使是 root 也无法修改或删除被 `+i` 标记的文件，直到属性被移除。这是文件系统级别（ext4/xfs/btrfs）的强制锁，绕过了 VFS 层的所有权限检查。

### 2.1 基础用法

```bash
# 查看扩展属性
lsattr file.txt
lsattr -a /var/log/               # 包含隐藏文件
lsattr -R /etc/nginx/             # 递归
lsattr -d /var/log/               # 仅查看目录自身属性

# 设置为不可变
sudo chattr +i important.conf

# 设置为仅追加
sudo chattr +a app.log

# 移除属性
sudo chattr -i important.conf
sudo chattr -a app.log
```

### 2.2 属性列表

| 属性 | 说明 |
|------|------|
| `i` | 不可变 (immutable) -- 任何写入（包括 `rm -f`、`chmod`、内容修改、重命名、创建硬链接）都被内核直接拒绝 |
| `a` | 仅追加 (append only) -- 只能追加内容，已有内容不可修改或删除，适合日志文件防止被清除 |
| `A` | 不更新 atime（访问时间），减少磁盘 I/O |
| `S` | 修改实时同步到磁盘，类似 sync 挂载 |
| `s` | 删除时安全擦除，数据块用零填充（不是所有文件系统支持） |
| `d` | 排除在 dump 备份之外 |
| `e` | extent 格式（ext4 文件系统默认启用，不可手动设置或移除） |
| `c` | 自动压缩（文件系统需支持压缩） |
| `j` | 数据日志（仅 ext3/ext4，data=journal） |

### 2.3 典型应用场景

**保护关键配置文件不被篡改：**

```bash
sudo chattr +i /etc/ssh/sshd_config
sudo chattr +i /etc/sudoers
# 即使 root 被攻破，攻击者也无法修改这些文件
```

**保护日志文件不被清除（配合 `+a`）：**

```bash
sudo chattr +a /var/log/auth.log
sudo chattr +a /var/log/secure
# 日志只能追加写入，即使攻击者拿到 root 也无法 > 清空或 rm 删除
```

**注意：** `+i` 之后，任何写入操作都会被**内核直接拒绝**（不是返回权限错误，而是 "Operation not permitted"）。要修改文件必须先执行 `chattr -i` 移除属性。

### 2.4 chattr 与 SELinux 的关系

两者工作在不同层面，互补而非互斥：

```
用户请求写文件
  → VFS 层检查 DAC（rwx 权限、chattr 属性）
    → 如果 chattr +i，内核直接拒绝（到这层就拦住了）
    → DAC 通过
  → LSM 层检查 MAC（SELinux 标签）
    → 如果类型不匹配，SELinux 拒绝
    → MAC 通过
  → 最终允许写入
```

chattr 是第一道防线（内核 VFS 层），SELinux 是第二道防线（LSM 层）。两者结合使用是最佳实践。

## 第三部分：ACL 访问控制列表

传统的 rwx 权限只能设置所有者、组、其他人三组。ACL（Access Control List，访问控制列表）允许为**任意数量的特定用户和组**单独设置权限。

### 3.1 查看 ACL

```bash
# 查看文件的 ACL 信息
getfacl file.txt
```

输出示例：

```
# file: file.txt
# owner: alice
# group: dev
user::rw-           # 所有者权限（等价于 ls -l 的前三位）
user:bob:rw-        # 额外用户 bob 有 rw 权限
group::r--          # 属组权限
group:ops:rwx       # 额外组 ops 有 rwx 权限
mask::rwx           # 权限掩码（限制所有额外用户/组的最大权限）
other::---          # 其他人无权限
```

带 `+` 号的文件表示有 ACL 扩展：

```bash
ls -la
# -rw-rwx---+ 1 alice dev ... file.txt
#          ↑ + 号表示此文件有 ACL 条目
```

### 3.2 设置 ACL

```bash
# 给用户 bob 添加读写权限
setfacl -m u:bob:rw file.txt

# 给组 ops 添加读写执行权限
setfacl -m g:ops:rwx /shared/project/

# 移除用户 bob 的 ACL
setfacl -x u:bob file.txt

# 移除组 ops 的 ACL
setfacl -x g:ops /shared/project/

# 递归设置
setfacl -R -m u:bob:rw /shared/project/

# 清除所有 ACL（回到纯 rwx 模式）
setfacl -b file.txt
```

### 3.3 默认 ACL（目录继承）

**作用：** 在目录上设置默认 ACL 后，目录内新建的文件和子目录会自动继承这些 ACL。

```bash
# 设置默认 ACL -- 目录下新文件自动获得
setfacl -m d:u:bob:rw /shared/project/
setfacl -m d:g:ops:rwx /shared/project/

# 查看目录 ACL（会同时显示访问 ACL 和默认 ACL）
getfacl /shared/project/
```

输出：

```
# file: /shared/project/
# owner: alice
# group: dev
user::rwx
group::r-x
other::---
default:user::rwx
default:user:bob:rw-       # 新建文件默认给 bob 读写
default:group::r-x
default:group:ops:rwx      # 新建文件默认给 ops 组 rwx
default:mask::rwx
default:other::---
```

**默认 ACL 与 setgid 对比：**

| 机制 | 控制维度 | 粒度 |
|------|---------|------|
| setgid 目录 | 只控制属组 | 只能确保文件属组正确 |
| 默认 ACL | 控制权限 + 属组 | 可以给不同用户/组设置不同权限 |

实际中两者常配合使用：setgid 确保属组正确 + 默认 ACL 确保权限正确。

### 3.4 权限掩码 (mask)

ACL 中的 `mask` 字段限制了所有额外用户和组的**最大实际权限**。

```bash
# 设置 mask
setfacl -m m::rx file.txt

# 即使 user:bob:rwx，实际生效的也只是 r-x（被 mask 限制）
```

**计算方式：** `有效权限 = ACL条目权限 & mask`

这也是为什么修改文件权限时 mask 会自动调整——`chmod g-w` 会同步修改 ACL mask。

## 第四部分：SELinux (MAC)

SELinux 在传统 DAC 权限之上增加一层强制访问控制。DAC 检查通过后，SELinux 还会再检查一次。

### 4.1 为什么需要 SELinux

传统权限的致命弱点：**进程的权限等于启动它的用户的权限**。一旦进程被攻破，攻击者就能访问该用户能访问的所有文件。

SELinux 的做法：给每个进程和每个文件打上安全标签（type），然后定义白名单规则——哪个标签的进程能访问哪个标签的文件。不在规则里的操作一律拒绝。

### 4.2 核心概念速览

| 概念 | 说明 |
|------|------|
| DAC | 自主访问控制 -- rwx 权限 + chattr 属性，由文件所有者决定 |
| MAC | 强制访问控制 -- SELinux 标签 + 白名单规则，由系统管理员（策略）决定 |
| 安全上下文 | 每个文件/进程的标签：`user:role:type:level` |
| type (类型) | 安全上下文中实际起作用的部分（`sshd_t`、`ssh_home_t`、`httpd_sys_content_t`） |
| Type Enforcement | SELinux 的核心规则：源类型（进程）→ 目标类型（文件）: 操作权限 |
| Enforcing | 强制模式 -- 拒绝违规操作并记录 |
| Permissive | 宽容模式 -- 允许违规操作但记录（排障用） |
| Disabled | 关闭 -- 不安全，不推荐 |

### 4.3 日常命令

```bash
# 查看标签
ls -Z file.txt                  # 文件标签
ps -eZ | grep sshd              # 进程标签

# 修复标签
restorecon -R -v /path/to/dir   # 恢复默认标签（最常用）
chcon -t ssh_home_t file        # 手动设置

# 端口管理
semanage port -l | grep ssh     # 查看 SELinux 端口策略
semanage port -a -t ssh_port_t -p tcp 2222  # 允许 sshd 绑定 2222

# 模式切换
getenforce                      # 查看当前模式
setenforce 0                    # 临时 Permissive（排障）
setenforce 1                    # 恢复 Enforcing
```

### 4.4 排障口诀

```
服务出问题 → 先查传统权限 (ls -la) → 没问题？
→ setenforce 0 临时关 SELinux → 问题消失？
→ 确认是 SELinux 问题 → setenforce 1 恢复
→ grep denied /var/log/audit/audit.log 看具体拒绝记录
→ restorecon 修复标签，或用 semanage/setsebool 调整策略
```

> 详细内容见 [SELinux 详解](SELinux.md)，包含完整的概念解释、文件/进程标签对照表、审计日志解读、SELinux vs AppArmor 对比，以及各类服务（SSH、Nginx、MySQL）的 SELinux 配置案例。

## 第五部分：权限排障流程

三层权限从外到内依次检查：

```
权限问题
  ↓
① 传统权限 (DAC)
  ls -la → chmod / chown / chgrp 修复
  ls -l 注意 + 号（有 ACL）
  ↓ 通过
② 扩展属性 (chattr)
  lsattr → chattr -i / -a 移除属性
  ↓ 通过
③ SELinux (MAC)
  ls -Z → restorecon 修复标签
  ↓ 通过
操作成功
```

### 常见场景速查

| 现象 | 可能的权限原因 | 排查命令 |
|------|--------------|---------|
| SSH 密钥登录被拒 | auth_keys 权限不是 600 / SELinux 标签不对 | `ls -la ~/.ssh/` + `ls -Z ~/.ssh/authorized_keys` |
| Permission denied (publickey) | authorized_keys 标签是 admin_home_t 而非 ssh_home_t | `restorecon -R -v ~/.ssh` |
| 网站 403 Forbidden | 文件不是 httpd_sys_content_t 标签 | `ls -Z /var/www/html/` |
| 改不了配置文件 | 被 chattr +i 锁定了 | `lsattr /etc/config.conf` |
| rm 提示 Operation not permitted | 文件被 chattr +i 或 +a | `lsattr file` |
| 服务无法绑定新端口 | SELinux 不认这个端口 | `semanage port -l \| grep <服务>` |
| 目录共享文件属组不对 | 没设置 setgid | `ls -ld /shared/` 看有没有 s |
| 共享目录别人删了我的文件 | 没设置 sticky bit | `ls -ld /shared/` 看有没有 t |

## 快速参考

```bash
# 传统权限
chmod 755 file                   # 数字设置
chmod u+x file                   # 符号设置
chown user:group file            # 改属主属组
umask 022                        # 查看/设置默认权限掩码
chmod u+s file                   # 设置 setuid
chmod g+s dir                    # 设置 setgid
chmod +t dir                     # 设置 sticky bit
find / -perm -4000 -type f       # 找所有 setuid 文件

# 扩展属性
lsattr file                      # 查看扩展属性
chattr +i file                   # 设为不可变
chattr +a file                   # 设为仅追加
chattr -i file                   # 移除不可变属性

# ACL
getfacl file                     # 查看 ACL
setfacl -m u:user:rw file        # 给用户添加 ACL
setfacl -m d:u:user:rw dir       # 设置默认 ACL（目录继承）
setfacl -b file                  # 清除所有 ACL

# SELinux
ls -Z file                       # 查看 SELinux 标签
ps -eZ                           # 查看进程标签
restorecon -R -v /path           # 恢复默认标签
getenforce                       # 查看模式
```
