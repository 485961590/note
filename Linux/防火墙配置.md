# 防火墙配置

> 防火墙是服务器安全的第一道防线。Linux 和 Windows 各有自己的防火墙体系，但本质都是同一件事——控制哪些流量可以进、哪些可以出。日常运维中最常见的操作：放行端口、封禁 IP、查看当前规则。

---

## Linux 防火墙

Linux 有四个层次的防火墙工具，从底层到上层：

```
iptables（内核 netfilter 的用户态工具，传统方案）
  ├── ufw（Ubuntu 的简化前端，适合快速上手）
  ├── firewalld（CentOS/RHEL 的动态管理方案，支持 zone 概念）
  └── nftables（新一代替代 iptables，内核 3.13+）
```

一般原则：桌面/简单 VPS 用 ufw，CentOS/RHEL 服务器用 firewalld，复杂规则/老系统用 iptables，新项目可以考虑 nftables。

---

### iptables

iptables 直接操作内核 netfilter 规则。规则组织为**表（table）→ 链（chain）→ 规则（rule）**三层结构。

**四张表（按处理顺序）：**

| 表 | 用途 |
|----|------|
| `raw` | 连接跟踪的例外处理（最先触发） |
| `mangle` | 修改 IP 包头（TTL、TOS 等） |
| `nat` | 网络地址转换（SNAT/DNAT） |
| `filter` | 包过滤——最常用，不指定 `-t` 时默认就是这张表 |

**五条内置链（filter 表）：**

| 链 | 触发时机 |
|----|---------|
| `PREROUTING` | 包到达网络接口后，路由决策前 |
| `INPUT` | 包的目的地是本机 |
| `FORWARD` | 包经过本机转发到另一台机器 |
| `OUTPUT` | 本机发出的包 |
| `POSTROUTING` | 包离开网络接口前 |

日常最常用的是 `filter` 表的 `INPUT` 链——控制谁能访问本机。

**基本命令：**

```bash
# 查看规则（-L 列出，-n 不解析域名加速，-v 显示详情，--line-numbers 显示行号）
iptables -L -n -v
iptables -L INPUT -n -v --line-numbers

# 清空所有规则（谨慎，可能导致服务暴露）
iptables -F                  # 清空 filter 表所有链的规则
iptables -X                  # 删除所有自定义链
iptables -t nat -F           # 清空 nat 表

# 默认策略（链的兜底行为，当没有规则匹配时执行）
iptables -P INPUT DROP       # 默认拒绝所有入站——最安全的起点
iptables -P INPUT ACCEPT     # 默认允许所有入站——不推荐
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT    # 出站一般默认允许
```

**常用规则：**

```bash
# ---- 放行端口 ----
# 放行 SSH（22），没这条会被自己锁在外面
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 放行 HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 放行端口范围（例如 8000-9000）
iptables -A INPUT -p tcp --dport 8000:9000 -j ACCEPT

# 放行 UDP（例如 DNS）
iptables -A INPUT -p udp --dport 53 -j ACCEPT

# ---- 放行特定 IP ----
# 只允许特定 IP 访问 22 端口
iptables -A INPUT -p tcp -s 192.168.1.100 --dport 22 -j ACCEPT

# 放行整个子网
iptables -A INPUT -p tcp -s 192.168.1.0/24 --dport 22 -j ACCEPT

# ---- 封禁 IP ----
# 封禁单个 IP 的所有流量
iptables -A INPUT -s 192.168.1.100 -j DROP

# 封禁 IP 段
iptables -A INPUT -s 10.0.0.0/8 -j DROP

# ---- 限制连接速率 ----
# 限制 SSH 连接速率（每分钟最多 5 个新连接）
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set --name SSH
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 5 --name SSH -j DROP

# ---- 状态检测（只允许已建立连接的回包入站） ----
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# 这一条非常关键——配合 -P INPUT DROP 使用，保证本机主动发起的连接（如 curl、apt update）的回复包不被拦截

# ---- 回环接口（必须放行，否则很多本地服务会挂） ----
iptables -A INPUT -i lo -j ACCEPT

# ---- 允许 ping（可选） ----
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
```

**删除与插入规则：**

```bash
# 按行号删除（先用 --line-numbers 查看行号）
iptables -L INPUT -n --line-numbers
iptables -D INPUT 3           # 删除 INPUT 链第 3 条规则

# 按内容删除
iptables -D INPUT -s 192.168.1.100 -j DROP

# 插入到指定位置（第 1 条之前）
iptables -I INPUT 1 -p tcp --dport 8080 -j ACCEPT

# 替换第 2 条规则
iptables -R INPUT 2 -p tcp --dport 9090 -j ACCEPT
```

**保存与恢复规则：**

iptables 规则在内存中，重启后丢失。需要持久化：

```bash
# Debian/Ubuntu
sudo apt install iptables-persistent
sudo netfilter-persistent save
sudo netfilter-persistent reload

# CentOS/RHEL
sudo service iptables save       # 保存到 /etc/sysconfig/iptables
sudo systemctl enable iptables   # 开机自启

# 手动保存/恢复
iptables-save > /etc/iptables.rules
iptables-restore < /etc/iptables.rules
```

**完整的 iptables 初始化脚本示例：**

```bash
#!/bin/bash
# 安全基线：默认拒绝入站，只放行必要服务

# 清空规则
iptables -F
iptables -X
iptables -t nat -F

# 默认策略
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 回环接口
iptables -A INPUT -i lo -j ACCEPT

# 已建立连接的回包
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 放行 SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 放行 HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 允许 ping
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# 保存
iptables-save > /etc/iptables.rules
echo "iptables 规则已应用"
```

### ufw（Uncomplicated Firewall）

`ufw` 是 iptables 的简化前端，Ubuntu 默认安装。适合不熟悉 iptables 的场景——一个命令搞定常见操作。

```bash
# 启用/禁用/状态
sudo ufw enable                 # 启用防火墙（开机自启）
sudo ufw disable                # 禁用防火墙
sudo ufw status                 # 查看状态和规则
sudo ufw status verbose         # 详细模式（含默认策略、日志级别）
sudo ufw status numbered        # 带行号（方便按行号删除）

# 默认策略
sudo ufw default deny incoming  # 默认拒绝入站
sudo ufw default allow outgoing # 默认允许出站

# 放行端口
sudo ufw allow 22               # 放行 22 端口（TCP+UDP）
sudo ufw allow 22/tcp           # 只放行 TCP
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 放行端口范围
sudo ufw allow 8000:9000/tcp

# 放行特定服务（从 /etc/services 读取端口）
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# 放行特定 IP
sudo ufw allow from 192.168.1.100
sudo ufw allow from 192.168.1.100 to any port 22    # 只放行该 IP 访问 22
sudo ufw allow from 192.168.1.0/24 to any port 22   # 放行子网访问 22

# 封禁
sudo ufw deny from 192.168.1.100
sudo ufw deny from 192.168.1.0/24
sudo ufw deny out to 8.8.8.8    # 禁止本机访问指定 IP（出站限制）

# 删除规则
sudo ufw delete allow 22/tcp
sudo ufw delete 3               # 按行号删（先用 status numbered 看）

# 重置（清空所有规则回到初始状态）
sudo ufw reset

# 日志
sudo ufw logging on             # 开启日志（写入 /var/log/ufw.log）
sudo ufw logging off
sudo ufw logging low            # low/medium/high/full
```

**ufw 配置示例——只开放 SSH 和 Web：**

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
```

### firewalld

CentOS/RHEL 7+ 默认防火墙。核心概念是**区域（zone）**——不同的网络环境（家庭、公司、公共 WiFi）关联不同信任级别，切换 zone 即可切换整套规则。底层使用 iptables 或 nftables。

```bash
# 服务管理
sudo systemctl start firewalld
sudo systemctl enable firewalld
sudo systemctl status firewalld
sudo firewall-cmd --state       # 查看防火墙是否运行中

# 查看当前 zone
sudo firewall-cmd --get-default-zone          # 默认 zone
sudo firewall-cmd --get-active-zones          # 所有活跃的 zone 及其绑定的网卡
sudo firewall-cmd --list-all                  # 当前 zone 的完整配置
sudo firewall-cmd --list-all --zone=public    # 查看指定 zone

# zone 说明
# drop:      丢弃所有入站包，无任何回复（最严格）
# block:     拒绝所有入站包，回复 icmp-host-prohibited
# public:    公共网络，不信任其他计算机（默认 zone）
# external:  外部网络，开启 NAT 伪装（路由器场景）
# dmz:       隔离区，允许有限入站连接
# work:      工作网络，基本信任
# home:      家庭网络，较高信任
# internal:  内部网络，较高信任
# trusted:   信任所有网络流量（最宽松）
```

**放行端口和服务：**

```bash
# 按服务名放行（服务定义在 /usr/lib/firewalld/services/）
sudo firewall-cmd --add-service=http          # 临时生效
sudo firewall-cmd --add-service=http --permanent  # 永久生效
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --add-service=ssh --permanent

# 查看可用服务
sudo firewall-cmd --get-services

# 按端口放行
sudo firewall-cmd --add-port=8080/tcp --permanent
sudo firewall-cmd --add-port=8000-9000/tcp --permanent
sudo firewall-cmd --add-port=53/udp --permanent

# 按源 IP 放行（限定来源 IP 可以访问）
sudo firewall-cmd --add-source=192.168.1.100 --permanent
sudo firewall-cmd --add-source=192.168.1.100 --zone=trusted --permanent

# 重载使规则生效
sudo firewall-cmd --reload

# 删除规则
sudo firewall-cmd --remove-port=8080/tcp --permanent
sudo firewall-cmd --remove-service=http --permanent
sudo firewall-cmd --reload
```

**Rich Rules（复杂规则）：**

简单的 `--add-port` 不够用时，用 rich rule 表达复杂逻辑：

```bash
# 只允许特定 IP 访问特定端口
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.100" port protocol="tcp" port="22" accept'

# 限制连接速率（每分钟最多 5 个 SSH 新连接）
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" service name="ssh" limit value="5/m" accept'

# 封禁某个 IP
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.100" reject'

# 删除 rich rule
sudo firewall-cmd --permanent --remove-rich-rule='rule family="ipv4" source address="192.168.1.100" reject'

sudo firewall-cmd --reload
```

**切换 zone 与端口转发：**

```bash
# 把网卡绑定到指定 zone
sudo firewall-cmd --change-interface=eth0 --zone=internal --permanent

# 端口转发（例如 80 转发到 8080）
sudo firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080 --permanent
# 需要先开启伪装
sudo firewall-cmd --add-masquerade --permanent
sudo firewall-cmd --reload
```

### nftables

nftables 是 iptables 的继任者，内核 3.13+ 可用。语法更一致、支持集合和字典、能批量原子更新规则。Debian 10+ 和 RHEL 8+ 默认可用。

```bash
# 安装
sudo apt install nftables       # Debian/Ubuntu
sudo dnf install nftables       # RHEL/CentOS

# 查看规则
sudo nft list ruleset

# 临时用（和应用前先检查）
sudo nft -f ruleset.nft         # 加载规则文件
sudo nft list ruleset > /etc/nftables.conf  # 导出当前规则
```

**nftables 规则示例（等价于"默认拒绝+放行 SSH/HTTP/HTTPS"）：**

```bash
#!/usr/sbin/nft -f
# 清空
flush ruleset

# 定义 IPv4 和 IPv6 表
table ip filter {
    # 入站链
    chain input {
        type filter hook input priority 0; policy drop;

        # 回环接口
        iif lo accept

        # 已建立连接的回包
        ct state established,related accept

        # 放行服务
        tcp dport { 22, 80, 443 } accept

        # 允许 ping
        ip protocol icmp icmp type echo-request accept
    }

    # 转发链（默认拒绝）
    chain forward {
        type filter hook forward priority 0; policy drop;
    }

    # 出站链（默认允许）
    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

nftables 语法比 iptables 更统一，但目前市面上的资料和现有脚本还是以 iptables 为主。新部署可以选 nftables，维护老系统还是得会 iptables。

## Windows 防火墙

Windows 防火墙（Windows Defender Firewall）从 Windows XP SP2 开始内置。和 Linux 的 iptables 一样，它也是状态检测防火墙，默认阻止入站、允许出站。

有三种管理方式：图形界面、命令行的 `netsh advfirewall`、以及 PowerShell 的 `NetSecurity` 模块。日常运维优先用 PowerShell——可脚本化、可批量、可远程。

**三种网络配置文件：**

| 配置文件 | 适用场景 | 默认行为 |
|---------|---------|---------|
| **域网络（Domain）** | 加入 AD 域的工作环境 | 入站限制较少 |
| **专用网络（Private）** | 家庭或办公室可信网络 | 入站较严格 |
| **公用网络（Public）** | 公共 WiFi / 不可信网络 | 入站最严格 |

Windows 根据当前网络自动选择配置文件，也可以手动指定。

---

### 命令行：netsh advfirewall

`netsh` 是经典的 Windows 网络配置命令，无需 PowerShell，CMD 就能跑。

```cmd
:: 查看防火墙状态
netsh advfirewall show currentprofile
netsh advfirewall show allprofiles

:: 启用/禁用防火墙
netsh advfirewall set allprofiles state on
netsh advfirewall set allprofiles state off

:: 恢复默认设置
netsh advfirewall reset

:: 默认策略
netsh advfirewall set allprofiles firewallpolicy blockinbound,allowoutbound

:: 放行端口（入站）
netsh advfirewall firewall add rule name="HTTP 80" dir=in action=allow protocol=TCP localport=80
netsh advfirewall firewall add rule name="HTTPS 443" dir=in action=allow protocol=TCP localport=443
netsh advfirewall firewall add rule name="SSH 22" dir=in action=allow protocol=TCP localport=22
netsh advfirewall firewall add rule name="DNS UDP" dir=in action=allow protocol=UDP localport=53

:: 放行指定程序
netsh advfirewall firewall add rule name="My App" dir=in action=allow program="C:\app\server.exe" enable=yes

:: 放行特定 IP（限定来源）
netsh advfirewall firewall add rule name="SSH from Trusted" dir=in action=allow protocol=TCP localport=22 remoteip=192.168.1.100
netsh advfirewall firewall add rule name="SSH from Subnet" dir=in action=allow protocol=TCP localport=22 remoteip=192.168.1.0/24

:: 封禁 IP
netsh advfirewall firewall add rule name="Block 192.168.1.100" dir=in action=block remoteip=192.168.1.100
netsh advfirewall firewall add rule name="Block subnet" dir=in action=block remoteip=10.0.0.0/8

:: 删除规则
netsh advfirewall firewall delete rule name="HTTP 80"

:: 查看所有规则
netsh advfirewall firewall show rule name=all
netsh advfirewall firewall show rule name=all dir=in
netsh advfirewall firewall show rule name=all verbose           :: 含程序路径等详细信息

:: 导出/导入规则（备份）
netsh advfirewall export "C:\backup\firewall-policy.wfw"
netsh advfirewall import "C:\backup\firewall-policy.wfw"

:: 查看防火墙日志
:: C:\Windows\System32\LogFiles\Firewall\pfirewall.log
type "C:\Windows\System32\LogFiles\Firewall\pfirewall.log"
```

### PowerShell：NetSecurity 模块

PowerShell 的 `NetSecurity` 模块比 netsh 更灵活，适合脚本化管理和批量操作。

```powershell
# 查看防火墙状态和配置文件
Get-NetFirewallProfile
Get-NetFirewallProfile -Name Domain,Private,Public | Select Name,Enabled

# 启用/禁用指定配置文件
Set-NetFirewallProfile -Profile Public -Enabled True
Set-NetFirewallProfile -Profile Domain,Private -Enabled True

# 查看所有入站规则
Get-NetFirewallRule -Direction Inbound
Get-NetFirewallRule -Direction Inbound -Enabled True       # 只看启用的
Get-NetFirewallRule -DisplayName "*HTTP*"                   # 按名称搜索

# 查看规则的详细端口和地址配置
Get-NetFirewallRule -DisplayName "HTTP 80" | Get-NetFirewallPortFilter
Get-NetFirewallRule -DisplayName "SSH*" | Get-NetFirewallAddressFilter

# 创建规则：放行端口
New-NetFirewallRule -DisplayName "HTTP 80" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "HTTPS 443" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
New-NetFirewallRule -DisplayName "App Port 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private,Public

# 创建规则：放行程序
New-NetFirewallRule -DisplayName "Python Server" -Direction Inbound -Program "C:\Python311\python.exe" -Action Allow

# 创建规则：限定来源 IP
New-NetFirewallRule -DisplayName "SSH from Office" -Direction Inbound -Protocol TCP -LocalPort 22 -RemoteAddress 192.168.1.0/24 -Action Allow

# 创建规则：封禁 IP
New-NetFirewallRule -DisplayName "Block 192.168.1.100" -Direction Inbound -RemoteAddress 192.168.1.100 -Action Block

# 禁用/启用/删除规则
Disable-NetFirewallRule -DisplayName "HTTP 80"
Enable-NetFirewallRule -DisplayName "HTTP 80"
Remove-NetFirewallRule -DisplayName "HTTP 80"

# 批量删除规则
Get-NetFirewallRule -DisplayName "TestRule*" | Remove-NetFirewallRule

# 导出/导入防火墙策略
netsh advfirewall export "C:\backup\firewall-policy.wfw"
netsh advfirewall import "C:\backup\firewall-policy.wfw"
```

实际场景中，图形界面适合快速查看和手动调整：

```

2. 左侧面板：
   - 入站规则（Inbound Rules）：控制别人能不能访问你

4. 查看现有规则：点击"入站规则"，按名称/端口/程序排序
   双击某条规则可查看详细配置

5. 查看当前活动的防火墙状态：
   控制面板 → 系统和安全 → Windows Defender 防火墙
```

## 实用场景

### 场景1：Linux 新服务器初始化——只开 SSH

```bash
# 方案 A：iptables
iptables -F
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT
iptables -A INPUT -i lo -j ACCEPT
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
netfilter-persistent save   # Debian

# 方案 B：ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status verbose
```

### 场景2：网站服务器——开放 80/443

```bash
# ufw
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# firewalld
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload

# Windows (PowerShell)
New-NetFirewallRule -DisplayName "HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
```

### 场景3：Docker 部署应用——放行自定义端口

```bash
# 假设部署了一个 Web 应用在 5000 端口，需要局域网访问

# Linux (ufw)
sudo ufw allow 5000/tcp

# 注意：Docker 默认直接修改 iptables，ufw 的规则可能被绕过
# 如果 ufw 放了 5000 但外部访问不了，检查 Docker 的 iptables 规则：
sudo iptables -L DOCKER -n -v

# CentOS (firewalld)
sudo firewall-cmd --add-port=5000/tcp --permanent
sudo firewall-cmd --reload
```

```powershell
# Windows
New-NetFirewallRule -DisplayName "Docker App 5000" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow
```

### 场景4：安全加固——封禁可疑 IP

```bash
# 看 /var/log/auth.log 里暴力破解 SSH 的来源 IP，批量封禁
sudo grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -10

# 封禁单个来源
sudo ufw deny from 203.0.113.50
sudo iptables -A INPUT -s 203.0.113.50 -j DROP
```

```powershell
# Windows
New-NetFirewallRule -DisplayName "Block 203.0.113.50" -Direction Inbound -RemoteAddress 203.0.113.50 -Action Block
```

### 场景5：Kali 渗透测试时临时关闭防火墙

```bash
# ufw
sudo ufw disable
# 测试完毕后重新启用
sudo ufw enable

# firewalld
sudo systemctl stop firewalld
sudo systemctl start firewalld
```

```powershell
# PowerShell（需要管理员权限）
Set-NetFirewallProfile -All -Enabled False
# 恢复
Set-NetFirewallProfile -All -Enabled True
```

## 常用对照表

| 操作 | iptables | ufw | firewalld | Windows (netsh) | Windows (PowerShell) |
|------|----------|-----|-----------|-----------------|---------------------|
| 启用防火墙 | 内核自带 | `ufw enable` | `systemctl start firewalld` | `netsh advfirewall set allprofiles state on` | `Set-NetFirewallProfile -Enabled True` |
| 禁用防火墙 | N/A | `ufw disable` | `systemctl stop firewalld` | `netsh advfirewall set allprofiles state off` | `Set-NetFirewallProfile -Enabled False` |
| 查看规则 | `iptables -L -n -v` | `ufw status verbose` | `firewall-cmd --list-all` | `netsh advfirewall firewall show rule name=all` | `Get-NetFirewallRule` |
| 放行端口 | `iptables -A INPUT -p tcp --dport 80 -j ACCEPT` | `ufw allow 80/tcp` | `firewall-cmd --add-port=80/tcp` | `netsh advfirewall firewall add rule name="HTTP" dir=in action=allow protocol=TCP localport=80` | `New-NetFirewallRule -DisplayName "HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow` |
| 删除端口 | `iptables -D INPUT ...` | `ufw delete allow 80/tcp` | `firewall-cmd --remove-port=80/tcp` | `netsh advfirewall firewall delete rule name="HTTP"` | `Remove-NetFirewallRule -DisplayName "HTTP"` |
| 封禁 IP | `iptables -A INPUT -s IP -j DROP` | `ufw deny from IP` | `firewall-cmd --add-rich-rule='rule family="ipv4" source address="IP" reject'` | `netsh advfirewall firewall add rule name="Block" dir=in action=block remoteip=IP` | `New-NetFirewallRule -DisplayName "Block" -Direction Inbound -RemoteAddress IP -Action Block` |
| 保存规则 | `iptables-save > file` | 自动持久化 | `--permanent` + `--reload` | `netsh advfirewall export file` | `netsh advfirewall export file` |
| 重置 | `iptables -F` | `ufw reset` | `firewall-cmd --complete-reload` | `netsh advfirewall reset` | 手动删规则 |

## 检查清单——部署前必查

不管哪个系统，部署应用之前按这个清单过一遍：

```
- [ ] 确认防火墙是启用状态
- [ ] 开放了应用所需的端口（且仅开放必要的）
- [ ] 限制了对 SSH/RDP 的访问来源（只对管理 IP 开放）
- [ ] 关闭了不需要的服务端口（数据库、Redis 不应对外暴露）
- [ ] 检查了出站限制（防止反弹 shell 等）
- [ ] 规则已持久化（重启后不会丢失）
- [ ] 做了备份（iptables-save / netsh export）
- [ ] 测试了从外部能否访问（另一台机器或手机热点）
```
