# JOIN 连接查询 — 表格演变详解

> 用两张小表 + 具体数据，逐行展示每种 JOIN 的匹配过程和结果集的演变。

---

## 准备数据

两张表，数据极少但足够说明所有 JOIN 类型：

**表 A：students（学生表）**

```
+----+--------+--------+
| id | name   | city   |
+----+--------+--------+
|  1 | 张三   | 北京   |
|  2 | 李四   | 上海   |
|  3 | 王五   | 广州   |
|  4 | 赵六   | NULL   |
+----+--------+--------+
```

**表 B：orders（订单表）** — `uid` 是外键，引用 `students.id`

```
+----+------+--------+
| id | uid  | amount |
+----+------+--------+
|  1 |    1 |    100 |
|  2 |    1 |    200 |
|  3 |    2 |    150 |
|  4 | NULL |    300 |
|  5 |    9 |    400 |   <-- uid=9，students 表中不存在（孤儿记录）
+----+------+--------+
```

关键观察点：
- 张三 (id=1) 有 2 条订单 — **一对多**
- 李四 (id=2) 有 1 条订单
- 王五 (id=3) 没有订单 — **左表独有**
- 赵六 (id=4) 没有订单 — **左表独有**
- 订单 4 的 uid=NULL — **外键为空**
- 订单 5 的 uid=9 — **外键指向不存在的学生**

## 一、CROSS JOIN（笛卡尔积）— 一切 JOIN 的起点

数据库执行 JOIN 时，逻辑上先把两张表做笛卡尔积（每行 × 每行），再用 ON 条件过滤。

```
students (4行) × orders (5行) = 20 行中间结果
```

```
+------------+------------+----------+----------+--------------+
| students表             | orders表                       |
+------------+------------+----------+----------+--------------+
| s.id | s.name | s.city | o.id | o.uid | o.amount | 匹配?       |
+------+--------+--------+------+-------+----------+------------+
|  1   | 张三   | 北京   |   1  |   1   |   100    | ON 条件命中 |
|  1   | 张三   | 北京   |   2  |   1   |   200    | ON 条件命中 |
|  1   | 张三   | 北京   |   3  |   2   |   150    | s.id≠o.uid |
|  1   | 张三   | 北京   |   4  | NULL  |   300    | NULL 不匹配|
|  1   | 张三   | 北京   |   5  |   9   |   400    | s.id≠o.uid |
|  2   | 李四   | 上海   |   1  |   1   |   100    | s.id≠o.uid |
|  2   | 李四   | 上海   |   2  |   1   |   200    | s.id≠o.uid |
|  2   | 李四   | 上海   |   3  |   2   |   150    | ON 条件命中 |
|  2   | 李四   | 上海   |   4  | NULL  |   300    | NULL 不匹配|
|  2   | 李四   | 上海   |   5  |   9   |   400    | s.id≠o.uid |
|  3   | 王五   | 广州   |   1  |   1   |   100    | s.id≠o.uid |
|  3   | 王五   | 广州   |   2  |   1   |   200    | s.id≠o.uid |
|  3   | 王五   | 广州   |   3  |   2   |   150    | s.id≠o.uid |
|  3   | 王五   | 广州   |   4  | NULL  |   300    | NULL 不匹配|
|  3   | 王五   | 广州   |   5  |   9   |   400    | s.id≠o.uid |
|  4   | 赵六   | NULL  |   1  |   1   |   100    | s.id≠o.uid |
|  4   | 赵六   | NULL  |   2  |   1   |   200    | s.id≠o.uid |
|  4   | 赵六   | NULL  |   3  |   2   |   150    | s.id≠o.uid |
|  4   | 赵六   | NULL  |   4  | NULL  |   300    | NULL 不匹配|
|  4   | 赵六   | NULL  |   5  |   9   |   400    | s.id≠o.uid |
+------+--------+--------+------+-------+----------+------------+
```

**核心规则：ON 条件中的 NULL 永远不匹配任何值（包括另一个 NULL）。**

## 二、INNER JOIN — 只保留匹配成功的行

```sql
SELECT s.id, s.name, o.id AS oid, o.amount
FROM students s
INNER JOIN orders o ON s.id = o.uid;
```

演变过程：

```
第1步：笛卡尔积（20行）
        ↓
第2步：ON s.id = o.uid 过滤
        → 只保留 s.id 和 o.uid 值相等且都不为 NULL 的行
        → 命中行：上面标记了 "ON 条件命中" 的 3 行
        ↓
第3步：SELECT 投影指定列
```

**最终结果：**

```
+----+--------+------+--------+
| id | name   | oid  | amount |
+----+--------+------+--------+
|  1 | 张三   |   1  |   100  |
|  1 | 张三   |   2  |   200  |
|  2 | 李四   |   3  |   150  |
+----+--------+------+--------+
```

被丢弃的行：

| 丢弃原因 | 涉及行 |
|----------|--------|
| s.id=3 (王五) 无匹配 | 王五的 5 行全部丢弃 |
| s.id=4 (赵六) 无匹配 | 赵六的 5 行全部丢弃 |
| o.uid=NULL 不匹配 | 订单 4 的 4 行全部丢弃 |
| o.uid=9 无匹配 | 订单 5 的 4 行全部丢弃 |
| s.id ≠ o.uid 且都非 NULL | 其余不等的行 |

## 三、LEFT JOIN — 左表全保留，右表填 NULL

```sql
SELECT s.id, s.name, o.id AS oid, o.amount
FROM students s
LEFT JOIN orders o ON s.id = o.uid;
```

演变过程（逐行追踪）：

```
第1步：笛卡尔积（20行）
        ↓
第2步：ON s.id = o.uid 过滤 — 标记匹配行与未匹配行
        ↓
第3步：左表(students)每一行——
         - 如果在第2步有命中 → 保留命中行（右表有数据）
         - 如果在第2步无命中 → 保留左表行，右表列全部填 NULL
```

**逐行演变：**

```
students 的第1行 (id=1, 张三)：
  笛卡尔产生 5 行组合 →
  命中 o.uid=1 的 2 行 → 输出 2 行，右表有值
  ┌────┬──────┬──────┬──────┬────────┐
  │ id │ name │ oid  │ uid  │ amount │
  ├────┼──────┼──────┼──────┼────────┤
  │ 1  │ 张三 │  1   │  1   │  100   │  ← 来自命中组合
  │ 1  │ 张三 │  2   │  1   │  200   │  ← 来自命中组合
  └────┴──────┴──────┴──────┴────────┘

students 的第2行 (id=2, 李四)：
  笛卡尔产生 5 行组合 →
  命中 o.uid=2 的 1 行 → 输出 1 行，右表有值
  ┌────┬──────┬──────┬──────┬────────┐
  │ 2  │ 李四 │  3   │  2   │  150   │  ← 来自命中组合
  └────┴──────┴──────┴──────┴────────┘

students 的第3行 (id=3, 王五)：
  笛卡尔产生 5 行组合 →
  命中 0 行 → 保留左表，右表列全填 NULL
  ┌────┬──────┬──────┬──────┬────────┐
  │ 3  │ 王五 │ NULL │ NULL │ NULL   │  ← 左表保留，右表补 NULL
  └────┴──────┴──────┴──────┴────────┘

students 的第4行 (id=4, 赵六)：
  笛卡尔产生 5 行组合 →
  命中 0 行 → 保留左表，右表列全填 NULL
  ┌────┬──────┬──────┬──────┬────────┐
  │ 4  │ 赵六 │ NULL │ NULL │ NULL   │  ← 左表保留，右表补 NULL
  └────┴──────┴──────┴──────┴────────┘
```

**最终结果：**

```
+----+--------+------+--------+
| id | name   | oid  | amount |
+----+--------+------+--------+
|  1 | 张三   |   1  |   100  |
|  1 | 张三   |   2  |   200  |
|  2 | 李四   |   3  |   150  |
|  3 | 王五   | NULL | NULL   |  ← 保留了，右表无数据
|  4 | 赵六   | NULL | NULL   |  ← 保留了，右表无数据
+----+--------+------+--------+
```

**LEFT JOIN 口诀：左表不缺行，右表缺了补 NULL。**

## 四、RIGHT JOIN — 右表全保留，左表填 NULL

```sql
SELECT s.id, s.name, o.id AS oid, o.amount
FROM students s
RIGHT JOIN orders o ON s.id = o.uid;
```

演变过程：

```
第1步：笛卡尔积（20行）
        ↓
第2步：ON s.id = o.uid 过滤 — 标记匹配行与未匹配行
        ↓
第3步：右表(orders)每一行——
         - 有命中 → 保留命中行（左表有数据）
         - 无命中 → 保留右表行，左表列全部填 NULL
```

**逐行演变：**

```
orders 的第1行 (id=1, uid=1, amount=100)：
  笛卡尔产生 4 行组合 →
  命中 s.id=1 的 1 行 → 输出 1 行
  ┌──────┬──────┬────┬────────┐
  │ s.id │ name │ id │ amount │
  ├──────┼──────┼────┼────────┤
  │  1   │ 张三 │  1 │   100  │  ← 来自命中组合
  └──────┴──────┴────┴────────┘

orders 的第2行 (id=2, uid=1, amount=200)：
  命中 s.id=1 → 输出 1 行
  ┌──────┬──────┬────┬────────┐
  │  1   │ 张三 │  2 │   200  │
  └──────┴──────┴────┴────────┘

orders 的第3行 (id=3, uid=2, amount=150)：
  命中 s.id=2 → 输出 1 行
  ┌──────┬──────┬────┬────────┐
  │  2   │ 李四 │  3 │   150  │
  └──────┴──────┴────┴────────┘

orders 的第4行 (id=4, uid=NULL, amount=300)：
  命中 0 行 (NULL 不参与匹配) → 保留右表，左表补 NULL
  ┌──────┬──────┬────┬────────┐
  │ NULL │ NULL │  4 │   300  │  ← 右表保留，左表补 NULL
  └──────┴──────┴────┴────────┘

orders 的第5行 (id=5, uid=9, amount=400)：
  命中 0 行 (s 表没有 id=9) → 保留右表，左表补 NULL
  ┌──────┬──────┬────┬────────┐
  │ NULL │ NULL │  5 │   400  │  ← 右表保留，左表补 NULL
  └──────┴──────┴────┴────────┘
```

**最终结果：**

```
+------+--------+------+--------+
| id   | name   | oid  | amount |
+------+--------+------+--------+
|  1   | 张三   |   1  |   100  |
|  1   | 张三   |   2  |   200  |
|  2   | 李四   |   3  |   150  |
| NULL | NULL   |   4  |   300  |  ← 保留了，左表无数据
| NULL | NULL   |   5  |   400  |  ← 保留了，左表无数据
+------+--------+------+--------+
```

**RIGHT JOIN 口诀：右表不缺行，左表缺了补 NULL。**
**等价写法：把表顺序换一下就是 LEFT JOIN。**

```sql
-- 这两句结果完全一样
SELECT s.id, s.name, o.id AS oid, o.amount
FROM students s RIGHT JOIN orders o ON s.id = o.uid;

SELECT s.id, s.name, o.id AS oid, o.amount
FROM orders o LEFT JOIN students s ON s.id = o.uid;
```

## 五、LEFT JOIN + WHERE 右表 IS NULL — 找"左表独有"

```sql
SELECT s.id, s.name
FROM students s
LEFT JOIN orders o ON s.id = o.uid
WHERE o.id IS NULL;
```

演变过程：

```
第1步：先做 LEFT JOIN，结果 (5行)
        ↓
+----+--------+------+--------+
| id | name   | oid  | amount |
+----+--------+------+--------+
|  1 | 张三   |   1  |   100  |
|  1 | 张三   |   2  |   200  |
|  2 | 李四   |   3  |   150  |
|  3 | 王五   | NULL | NULL   |  ← 右表列为 NULL
|  4 | 赵六   | NULL | NULL   |  ← 右表列为 NULL
+----+--------+------+--------+
        ↓
第2步：WHERE o.id IS NULL 过滤
        ↓
+----+--------+
| id | name   |
+----+--------+
|  3 | 王五   |   ← 没有订单的学生
|  4 | 赵六   |   ← 没有订单的学生
+----+--------+
```

## 七、多表 JOIN 的演变（链式连接）

三张表：students → orders → items

```
students                    orders                      items
+----+------+         +----+------+------+        +----+----------+--------+
| id | name |         | id | uid  | amt  |        | id | order_id | product|
+----+------+         +----+------+------+        +----+----------+--------+

+----+------+         +----+------+------+        |  3 |    2     | 耳机   |
```

```
        ↓
```

## 八、FOREIGN KEY（外键）与 JOIN 的关系

外键约束本身**不影响** JOIN 的结果，它只做**数据完整性校验**。

对比：

```
情况1：有外键约束 (FOREIGN KEY) + INNER JOIN
  → 外键保证 orders.uid 要么为 NULL，要么一定存在于 students.id
  → INNER JOIN 结果干净：没有孤儿行，没有不存在的引用
  → o.uid=NULL 的行仍被 INNER JOIN 丢弃（NULL 不匹配任何值）

情况2：无外键约束 + INNER JOIN
  → JOIN 逻辑完全一样
  → 但可能出现 orders.uid=9 这样的孤儿引用
  → INNER JOIN 照样丢弃它（没匹配上）
  → 区别：没有外键约束，脏数据悄悄丢了，你不一定发现
```

**外键的作用总结：**

| | 有外键 | 无外键 |
|---|---|---|
| 插入 orders.uid=9 | 报错，阻止写入 | 允许写入，产生孤儿数据 |
| 删除 students.id=1 | 取决于 ON DELETE 设置 | 直接删除，orders 中出现悬空引用 |
| INNER JOIN 结果 | 干净（孤儿行不存在） | 可能有孤儿行被静默丢弃 |
| LEFT JOIN 结果 | 干净 | 可以暴露孤儿行（右表有，左表 NULL） |

## 九、外键级联操作 — 数据演变

```sql
-- 外键定义
FOREIGN KEY (uid) REFERENCES students(id)
    ON DELETE CASCADE    -- 删学生 → 订单一起删
    ON UPDATE CASCADE;   -- 改学生 id → 订单 uid 跟着改
```

**ON DELETE CASCADE 演变：**

```
删除前：
students                   orders
+----+------+        +----+------+--------+
| id | name |        | id | uid  | amount |
+----+------+        +----+------+--------+
|  1 | 张三 |        |  1 |   1  |   100  |
|  2 | 李四 |        |  2 |   1  |   200  |
+----+------+        |  3 |   2  |   150  |
                      +----+------+--------+

执行: DELETE FROM students WHERE id = 1;

删除后：
students                   orders
+----+------+        +----+------+--------+
|  2 | 李四 |        |  3 |   2  |   150  |
+----+------+        +----+------+--------+
                      ↑ 张三(id=1)被删，他的订单(id=1,2)也自动被删
```

**ON DELETE SET NULL 演变：**

```
外键定义: ON DELETE SET NULL

删除前：同上

执行: DELETE FROM students WHERE id = 1;

删除后：
students                   orders
+----+------+        +----+------+--------+
|  2 | 李四 |        |  1 | NULL |   100  |  ← uid 变为 NULL
+----+------+        |  2 | NULL |   200  |  ← uid 变为 NULL
                      |  3 |   2  |   150  |
                      +----+------+--------+
```

## 十、SELF JOIN（自连接）— 同一张表的演变

```sql
-- 找出住在同一城市的学生对
SELECT a.name AS 学生A, b.name AS 学生B, a.city
FROM students a
INNER JOIN students b ON a.city = b.city AND a.id < b.id;
```

```
原始表 students：
+----+--------+--------+
| id | name   | city   |
+----+--------+--------+
|  1 | 张三   | 北京   |
|  2 | 李四   | 北京   |
|  3 | 王五   | 上海   |
+----+--------+--------+

第1步：笛卡尔积（3×3=9行）

第2步：ON a.city = b.city AND a.id < b.id 过滤
        ↓
+------+----------+--------+------+----------+--------+
| a.id | a.name   | a.city | b.id | b.name   | b.city |
+------+----------+--------+------+----------+--------+
|  1   | 张三     | 北京   |  2   | 李四     | 北京   |  ← 同城且 a.id< b.id
+------+----------+--------+------+----------+--------+
  × a.id=1,b.id=1 → a.id < b.id 不成立
  × a.id=1,b.id=3 → city 不同
  × a.id=2,b.id=1 → a.id < b.id 不成立（避免重复对）
  ... 其余 6 行都不满足

第3步：最终结果
+--------+--------+--------+
| 学生A  | 学生B  | city   |
+--------+--------+--------+
| 张三   | 李四   | 北京   |
+--------+--------+--------+
```
