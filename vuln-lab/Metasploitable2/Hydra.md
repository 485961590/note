# Hydra

> **Metasploitable2 系列** -- 弱口令爆破篇。本系列按工具/攻击面分篇，本篇记录在线爆破工具 Hydra 对 Metasploitable2 各服务的实践。

---

## 概述

Hydra（THC-Hydra）是一款**在线网络认证爆破工具**，支持 50+ 种协议：SSH、FTP、Telnet、HTTP/HTTPS 表单、MySQL、SMB、SMTP、POP3、IMAP、PostgreSQL、VNC、RDP 等。

它的核心机制很直接：针对一个提供认证的服务，按字典组合逐一尝试用户名/密码，依据服务返回的"认证成功/失败"判定是否命中。

需要明确 Hydra 的能力边界：

- 它**只验证凭证**，不利用漏洞。前提是目标服务已运行、且允许登录尝试。
- 它属于**在线爆破**，必须与目标实时交互，速度受服务端约束（详见下节）。

---

## 在线爆破 vs 离线破解

这是理解 Hydra 定位的关键认知，也是新手最容易混淆的概念。

| 维度 | 在线爆破 | 离线破解 |
|------|---------|---------|
| 输入 | 运行中的服务认证接口 | 已获取的密码 hash |
| 速度瓶颈 | 网络往返 + 服务端限速/锁定 | 仅本地算力 |
| 隐蔽性 | 产生大量登录失败日志，易被检测 | 完全本地，无网络痕迹 |
| 速率量级 | 每秒数次到数十次 | 每秒数百万到数十亿次（GPU） |
| 代表工具 | Hydra / Medusa / Ncrack | John the Ripper / Hashcat |
| 适用阶段 | 渗透前期，未拿到 hash | 拿到 hash 后（如 `/etc/shadow`） |

> 本质区别：在线爆破与目标实时交互，速度被服务端的网络延迟、认证耗时、并发限制、失败锁定共同压制；离线破解是纯本地运算，只受算力约束。Hydra 永远快不过 John the Ripper -- 这不是工具优劣，而是机制差异。所以在线爆破的胜负手是**字典质量**，离线破解的胜负手是**算力**。

## 基本参数

| 参数 | 含义 |
|------|------|
| `-l LOGIN` | 指定单个用户名 |
| `-L FILE` | 指定用户名列表文件 |
| `-p PASS` | 指定单个密码 |
| `-P FILE` | 指定密码字典文件 |
| `-s PORT` | 指定目标端口（非默认端口时用） |
| `-t TASKS` | 并发线程数（默认 16） |
| `-f` | 命中第一组凭证后立即停止 |
| `-V` | 回显每次尝试，便于观察进度 |
| `-o FILE` | 将结果输出到文件 |
| `-e nsr` | 额外检查：`n`=空密码、`s`=登录名作为密码、`r`=反向登录名 |
| `-w TIME` | 每次尝试的最大等待时间（秒） |

记忆要点：小写 `-l/-p` 是单个值，大写 `-L/-P` 是文件。

## 爆破 Metasploitable2 的 SSH

### 1. 前置侦察

爆破前先确认目标 SSH 在跑、版本是什么。Hydra 不做侦察。

```bash
nmap -sV -p 22 192.168.x.x
```

Metasploitable2 上预期看到 `OpenSSH 4.7p1 Debian 8ubuntu1.2`，端口 22。若端口非默认，后面 Hydra 用 `-s` 指定。

### 2. 准备字典

Hydra 需要用户名列表 + 密码字典。

Metasploitable2 的用户名是**已知的系统账户**，用精简列表比百万级大字典高效得多。关键用户名（写入 `users.txt`）：

```
root
msfadmin
postgres
user
service
sys
klog
bind
```

密码字典用 Kali 自带的 `rockyou.txt`（默认是压缩状态，先解压）：

```bash
gunzip -k /usr/share/wordlists/rockyou.txt.gz
```

### 3. 构造命令

```bash
hydra -L users.txt -P /usr/share/wordlists/rockyou.txt -t 4 -f -V ssh://192.168.x.x
```

参数对照：

| 参数 | 此处作用 |
|------|---------|
| `-L users.txt` | 从文件读用户名 |
| `-P ...rockyou.txt` | 从文件读密码 |
| `-t 4` | 4 个并发线程（SSH 不能开大，原因见下节） |
| `-f` | 命中即停 |
| `-V` | 回显进度 |
| `ssh://192.168.x.x` | 目标协议 + 地址 |

也可写成等价形式 `hydra ... 192.168.x.x ssh`。

### 4. 结果验证

Hydra 命中后输出形如：

```
[22][ssh] host: 192.168.x.x login: msfadmin password: msfadmin
```

拿到凭证后直接登录确认：

```bash
ssh msfadmin@192.168.x.x
```

Metasploitable2 的预期结果：`msfadmin/msfadmin`（默认凭证，用户名=密码）。`root`、`postgres`、`user` 等账户大概率也是用户名同密码的形式。

## 为什么 SSH 的 `-t` 不能开大

这是 SSH 爆破最关键的原理点，也是新手常踩的坑。

OpenSSH 服务端有 `MaxStartups` 机制，专门控制**未认证的并发连接数**，防止资源耗尽。默认值 `10:30:100`，三个数字含义：

- 未认证连接数达到 **10** 之前，全部接受；
- 超过 10 后，以 **30%** 的线性增长概率开始拒绝新连接；
- 达到 **100** 时，全部拒绝。

Hydra 线程开太高（如 `-t 16`、`-t 64`），大量连接还没完成认证握手就被服务端丢弃。问题在于 Hydra 会把"连接被拒"误判成"密码错误"，于是**正确密码也可能被错过** -- 字典里有，结果却报爆破失败。

所以 SSH 爆破线程通常压到 `-t 4` 甚至更低，用稳健换准确。这与 FTP、HTTP 表单爆破可以开几十线程是本质区别，根源在 SSH 协议端的认证并发限制。

> 排查爆破异常时，先怀疑线程数。若怀疑字典含正确密码却没爆出来，把 `-t` 降到 1-4 重跑是第一反应。

## 扩展：Hydra 爆破其他服务

Metasploitable2 上多个服务都可用 Hydra 爆破，命令形式类似，但各有注意点。

| 服务 | 命令形式 | 注意 |
|------|---------|------|
| SSH | `hydra -L u -P p -t 4 ssh://IP` | 线程 ≤4（MaxStartups） |
| FTP | `hydra -L u -P p ftp://IP` | 可开较高线程 |
| Telnet | `hydra -L u -P p -t 4 telnet://IP` | 每次新建连接且响应慢，线程压低 |
| MySQL | `hydra -L u -P p mysql://IP` | 失败多次可能触发服务端限制 |
| SMB | `hydra -L u -P p smb://IP` | 适合爆 Windows 账户 |
| HTTP 表单 | `hydra -L u -P p IP http-post-form "/login:user=^USER^&pass=^PASS^:F=失败标志"` | 需指定失败时的页面特征字符串 |

HTTP 表单爆破最复杂：`^USER^`/`^PASS^` 是占位符，第三个字段 `F=...` 是登录失败时响应中出现的特征字符串（如 `F=invalid` 或 `F=登录失败`），Hydra 据此判断这次尝试是否失败。这个特征需要先手工登录一次观察响应确定。

## 实战技巧与避坑

- **先试默认凭证再爆**：Metasploitable2 这类靶机，`msfadmin/msfadmin` 直接 ssh 就能进。爆破更多是练流程。真实场景里"先手工试常见弱口令，再上工具"也是更高效的习惯。
- **用 `-e s` 跑"用户名即密码"**：很多靶机和弱配置环境存在 `用户名=密码` 的规律。`-e s` 会自动用每个登录名作为密码尝试一遍，几秒跑完，命中率往往很高。对 Metasploitable2 特别有效：
  ```bash
  hydra -L users.txt -e s -f ssh://192.168.x.x
  ```
- **先做连通性自测**：用一个只含 `msfadmin` 的 `users.txt` 和只含 `msfadmin` 的 `pass.txt` 跑一遍，确认 Hydra 配置和目标连通性没问题，再上大字典。
- **rockyou 解压**：`/usr/share/wordlists/rockyou.txt.gz` 默认压缩，使用前 `gunzip`。
- **结果存档**：用 `-o result.txt` 把命中结果落盘，避免终端翻页丢失。

## 经验沉淀

- **在线爆破靠字典质量，不靠算力**。与其上百万级大字典盲目跑，不如先基于侦察结果（系统用户名、目标性质）构造精简定向字典。针对 Metasploitable2，十几行的用户名表 + `-e s` 比直接灌 rockyou 更快命中。
- **SSH 并发限制是协议层设计，不是工具缺陷**。`MaxStartups` 的存在意味着 SSH 爆破天生慢且容错差，高并发会漏报。理解服务端机制才能正确设置 `-t`，而不是默认 16 一把梭。
- **侦察决定爆破效率**。先 nmap 确认端口、服务、版本，再据此选协议模块和参数。对着错误端口或错误服务爆，字典再好也是空跑。
- **在线爆破是高噪操作**。每次失败尝试都会写日志（`/var/log/auth.log` 等），在真实授权测试中要评估告警风险，控制节奏并做好时间窗口规划。
