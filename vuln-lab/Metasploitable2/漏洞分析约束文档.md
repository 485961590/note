# Metasploitable2 漏洞分析约束文档

> 本文档定义 Metasploitable2 系列漏洞笔记的编写标准。每篇笔记同时完成两件事：**走完从发现到利用的完整渗透流程** + **对漏洞代码做逐行级分析**。本文档既是规范也是自检清单。

---

## 1. 渗透流程约束

每篇笔记必须按以下顺序记录，不可跳过中间步骤。

### 1.1 侦察

- 端口扫描命令与输出版本号（`nmap -sV -p <port> <target>`）
- 根据版本信息给出是否存在已知漏洞的初步判断
- 禁止跳过版本确认直接利用

### 1.2 漏洞搜索

- `search <service>` 在 msf 中的结果列表
- `searchsploit <service>` 在 Exploit-DB 中的结果（如适用）
- 其他信息源（CVE、Google、GitHub PoC）的查阅记录
- 禁止不搜索直接 `use exploit/...`（除非注明"已提前知晓漏洞"）

### 1.3 漏洞评估

- 列出所有候选模块，对比目标版本是否匹配
- `info <module>` 的关键字段：Rank、Privileged、Disclosed、Description
- 明确说明选择该模块的理由
- 禁止直接选第一个搜索结果而不做对比

### 1.4 利用

- 手工利用步骤（如适用）
- 工具利用的完整参数配置与输出
- 遇到的错误及排查过程
- 禁止只写"运行 exploit"而不给出配置和实际输出

### 1.5 验证

- `id`、`whoami` 输出
- 权限级别的明确结论（root / 普通用户 / 服务账户）

## 2. 文档结构约束

每篇笔记固定 13 个章节，顺序不可调：

1. `# 标题` — 服务名 + 漏洞名
2. `> 系列标注` — `Metasploitable2 系列 -- XX 端口 XX 攻击篇`
3. `## 概述` — 一句话：漏洞是什么、危害、特别之处
4. `## 漏洞背景` — 分类：供应链投毒 / 编码缺陷 / 配置错误 / 设计缺陷
5. `## 根本原因` — 代码分析（按第 3 节约束执行）
6. `## 触发条件` — 精确技术前置条件
7. `## 影响分析` — 控制面、数据面、影响范围
8. `## 攻击流程` — 侦察 -> 触发 -> 获取 shell，完整实操记录
9. `## 同一端口的其他攻击面` — 非本篇主角的补充路径
10. `## 检测方法` — 版本指纹 / 端口异常 / 行为异常 / 流量特征
11. `## 防御方案` — 标注根本性 vs 缓解性，说明原理与局限性
12. `## 经验沉淀` — 具体可操作的教训，不写空话
13. `## 相关 CVE / 参考资料` — CVE + 模块路径 + 原始披露链接

## 3. 代码分析约束

### 3.1 分析深度

每段漏洞代码四个层次缺一不可：

1. **整体概述** — 2-3 句概括这段代码做什么、为什么恶意/有缺陷
2. **逐行注释** — 每行代码用行末注释说明作用
3. **符号溯源** — 每个函数标注类型和来源，每个变量标注类型和用途
4. **调用链** — 从触发点到最终效果的函数调用序列，标注每步权限上下文

### 3.2 符号标注格式

逐行注释中，对函数和变量使用括号尾注，格式如下：

```
socket(AF_INET, SOCK_STREAM, 0);  // [系统调用] socket() - 创建通信端点，返回文件描述符。AF_INET=IPv4 地址族，SOCK_STREAM=TCP 套接字，0=自动选择协议(即 TCP)
```

标注时遵循以下分类，直接用文字说明，不用表格：

- **系统调用** — 内核直接提供的接口，man page 第 2 节。如 `socket()`、`bind()`、`execve()`、`dup2()`。注意：`fork()` 虽经 glibc 封装，本质是系统调用，标注 `[系统调用]` 并备注"通过 glibc wrapper 调用"
- **C 标准库** — libc 提供的函数，man page 第 3 节。如 `printf()`、`malloc()`、`strlen()`、`htons()`
- **POSIX 库函数** — 不在 C 标准但在 POSIX 规范中。如 `accept()`、`listen()`
- **项目自定义** — 项目源码中定义的函数。如 vsftpd 的 `str_endstr()`、`vsf_sysutil_extra()`
- **第三方库** — 外部依赖。如 OpenSSL 的 `SSL_write()`

变量在首次出现时说明类型和用途：`sock`（`int`，存储 `socket()` 返回的文件描述符）。

### 3.3 调用链

在代码块之后，用单行箭头链表示触发路径，括号标注权限上下文：

```
[触发函数](root) -> [后门函数](root) -> fork() -> [shell 进程](root)
```

## 4. 写作风格约束

- **语言**：简体中文正文，技术术语首次出现附英文原文与中文解释。命令和代码原样保留不翻译。
- **路径与编号**：文件路径用反引号，CVE 用标准格式 `CVE-YYYY-NNNNN`。
- **IP**：通用知识用 `192.168.x.x` 占位，实操记录用真实 IP。
- **引用块（`>`）**：仅用于关键洞察、常见误解纠正、需特别强调的经验教训。
- **同系列链接**：使用 Obsidian wiki 链接 `[[Hydra]]`。
- **外部来源**：完整 URL 或标准编号（CVE / OSVDB / Exploit-DB ID）。
- **模块路径**：完整 Metasploit 路径如 `exploit/unix/ftp/vsftpd_234_backdoor`。
- **禁止 emoji**：所有 emoji 图标符号禁止使用（ASCII 箭头 `->` 除外）。
