# 伪协议文件读取 — 信息枚举清单

## 概述

当获得一个文件读取原语（file read primitive）时——无论是通过 PHP 伪协议（`php://filter/convert.base64-encode/resource=`）、路径遍历（Path Traversal）、XXE、SSRF 还是模板注入——攻击的核心目的发生了转变：**从"能否读到文件"变为"该读哪些文件以获得最大信息量"**。本文档系统性地整理了 Linux 和 Windows 两大平台下，通过文件读取可获取的信息类型及其对应的目标文件路径。

问题的本质是：文件系统是一个**状态反射面**——系统中的每个配置、进程、用户行为、网络连接都在文件系统中留有足迹。一个无限制的文件读取原语，等价于在服务器本地执行 `grep -r` 级别的情报收集。

---

## 文件读取原语的类型差异

在列出清单之前，需要先理解不同读取原语的能力边界：

| 原语类型 | 能力 | 限制 |
|---------|------|------|
| `file_get_contents()` / `file()` | 读取任意本地文件 | 受 PHP `open_basedir` 限制 |
| `php://filter/convert.base64-encode/resource=` | 读取源码（PHP 文件不会被执行） | 仅 PHP 环境 |
| `include()` / `require()` | 读取 + 执行 PHP 文件 | 非 PHP 文件仅读取 |
| `fopen()` / `fread()` | 二进制安全读取 | 依赖上下文 |
| XXE / SSRF (file://) | 读取本地文件 | 部分环境下 `file://` 被禁用 |
| 模板引擎原生文件包含（如 `{include file=...}`） | 读取模板文件 | 通常有路径限制 |

关键区别：**PHP 伪协议的威力在于可以 base64 编码输出 PHP 源码**——这是本地文件包含（LFI）中最常用的手法，因为 PHP 文件被 `include` 时会执行，但通过 `php://filter` 可以以编码形式读取其源码。

## 信息获取层次

文件读取的信息收集应当按层次进行，每一层的信息为下一层提供上下文。

### 第一层：系统基础信息（确认环境）

**目标：** 确认操作系统、内核版本、发行版、主机名、容器化情况。

| 目标文件 | 获取信息 | 备注 |
|---------|---------|------|
| `/etc/os-release` | 发行版名称、版本号 | RHEL/CentOS 7+, Debian 8+, Ubuntu |
| `/etc/issue` | 发行版标识 | 传统方式 |
| `/etc/*release` | 发行版版本（通吃） | 包含 `redhat-release`, `debian_version` 等 |
| `/proc/version` | Linux 内核版本 + GCC 版本 | 不受 chroot 限制 |
| `/proc/sys/kernel/hostname` | 主机名 | |
| `/proc/1/cgroup` | 容器化检测（docker/lxc/containerd） | 检查 `docker`/`kubepods` 字符串 |
| `/proc/1/environ` | 容器环境变量 | |
| `/etc/lsb-release` | Ubuntu 具体版本 | |
| `C:\boot.ini` | Windows 启动信息 | Windows < Vista |
| `C:\Windows\System32\license.rtf` | Windows 版本 | Windows >= Vista |

**判断容器化：** 如果 `/proc/1/cgroup` 中包含 `docker`、`kubepods`、`lxc` 等字符串，则说明运行在容器中。容器内的文件读取通常意味着一部分路径（如 `/var/log/auth.log`）不可用，但应用配置文件和源码仍可读取。

### 第二层：应用配置与服务发现（扩大攻击面）

**目标：** 找到 Web 服务器配置、虚拟主机、应用配置、数据库连接字符串。

#### PHP 配置

|---------|---------|------|
| `/etc/php/7.x/apache2/php.ini` | PHP 配置（Debian 系） | Linux |
| `/etc/php/7.x/fpm/php.ini` | PHP-FPM 配置 | Linux |

| `C:\xampp\php\php.ini` | XAMPP PHP 配置 | Windows |
| `C:\Windows\php.ini` | PHP 配置（常见路径） | Windows |
| `/etc/php/7.x/fpm/pool.d/www.conf` | PHP-FPM 池配置 | Linux |

**重点查找的配置项：**
- `disable_functions` — 被禁用的 PHP 函数列表（决定后续利用方式）
- `open_basedir` — PHP 可访问的文件系统范围
- `allow_url_include` — 是否允许远程包含
- `allow_url_fopen` — 是否允许远程打开文件
- `display_errors` / `error_reporting` — 错误信息暴露程度
- `session.save_path` — Session 文件的存储路径
- `upload_tmp_dir` — 上传临时文件路径
- `mail.log` — 邮件日志路径（可能用于写文件）

### 第六层：应用源码（业务逻辑审计）

一旦确定了 Web 根目录，应当系统性地读取应用源码以发现更多漏洞。

**策略：** 不是随机猜测文件，而是从入口点开始追踪。

```php
// 读取入口文件
php://filter/convert.base64-encode/resource=index.php
php://filter/convert.base64-encode/resource=config.php
php://filter/convert.base64-encode/resource=router.php

// 扫描 include/require 语句中的文件
include 'includes/db.php';     // -> 读取 includes/db.php
require_once 'lib/auth.php';   // -> 读取 lib/auth.php
```

**框架特定入口：**

| 框架 | 入口文件 | 关键配置 |
|------|---------|---------|
| Laravel | `public/index.php` -> `bootstrap/app.php` | `.env`, `config/app.php`, `config/database.php` |
| Symfony | `public/index.php` -> `config/services.yaml` | `.env`, `config/parameters.yaml` |
| WordPress | `index.php` -> `wp-config.php` | `wp-config.php`, `wp-config-sample.php` |
| Drupal | `index.php` | `sites/default/settings.php` |
| ThinkPHP | `public/index.php` | `config/database.php`, `.env` |
| Yii | `web/index.php` | `config/db.php`, `config/web.php` |

**源码审计时的目标模式（在代码中搜索）：**

```
// 敏感函数搜索 — 正则关键词
preg_match  // 绕过可能导致安全过滤失效
eval        // 代码注入点
include     // LFI 链路追踪
system      // 命令执行
exec        // 命令执行
shell_exec  // 命令执行
passthru    // 命令执行
popen       // 命令执行
curl_exec   // SSRF 潜在点
file_get_contents  // 文件读取（SSRF 或 LFI）
move_uploaded_file // 文件上传写入
unserialize  // PHP 反序列化
extract      // 变量覆盖
parse_str    // 变量覆盖
compact      // 变量覆盖
create_function // 代码注入（PHP 7.4 以下）
preg_replace /e // 代码注入（PHP 7.0 以下）
call_user_func  // 动态函数调用
array_map       // 动态函数调用
```

**Windows 上的挑战：** SAM 和 SYSTEM 文件在系统运行时被锁定，无法通过普通文件读取获取。但可以读取注册表文件或在后续通过卷影副本（Volume Shadow Copy）获取。

## PHP 伪协议的高级利用技术

PHP 伪协议（`php://`）不仅仅是 `php://filter` 用于读取文件，以下几个变体在特定场景下至关重要：

```php
// 编码读取 PHP 源码（最核心用法）
php://filter/convert.base64-encode/resource=index.php

// 链式过滤器（多次转换）
php://filter/convert.base64-encode|convert.base64-encode/resource=index.php

// 字符串读入（构造 payload）
php://input     // POST body 作为 PHP 代码执行（需 allow_url_include=On）
data://text/plain;base64,...  // data URI 方式注入代码（需 allow_url_include=On）

// 临时文件读取
php://temp      // 写入临时流
php://memory    // 写入内存流

// 文件描述符读取（读取已上传的临时文件）
php://filter/resource=/proc/self/fd/X   // X 从 0 开始尝试
```

**关键限制条件：**

| 功能 | 需要的配置 | 成功率 |
|------|-----------|--------|
| `php://filter` 读取源码 | 无特殊要求 | 极高（几乎总是可用） |
| `php://input` 代码执行 | `allow_url_include=On`（默认 Off） | 低 |
| `data://` RCE | `allow_url_include=On` | 低 |
| LFI -> RCE via 日志注入 | Nginx/Apache 日志路径可读可写 | 中等 |
| LFI -> RCE via `/proc/self/fd` | PHP-FPM 临时文件竞态 | 低（技术性极高） |

## 注意：规避检测与绕过考虑

1. **WAF 对路径的检测**：许多 WAF 会拦截包含 `../`、`etc/passwd`、`proc/self` 等字符串的请求。可以使用 URL 编码、双重编码、路径标准化绕过（如 `....//....//`、`..;/`）。

2. **PHP open_basedir 限制**：PHP 的 `open_basedir` 指令限制文件访问范围，使无法读取 `/etc/passwd` 或 `/proc/self/environ`。此时需要在 `open_basedir` 允许的目录内寻找突破口。

3. **文件大小限制**：某些读取原语有输出大小限制（如 `php://filter` 默认无限制但浏览器/终端可能截断），大文件需要分段读取。

4. **Nginx 禁止访问点号开头的文件**：标准 Nginx 配置会拒绝以 `.` 开头的直接访问（`.git`, `.env`），但通过伪协议读取不受此限制——因为请求路径不经过静态文件访问逻辑。
