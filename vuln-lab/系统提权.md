在获得低权限 Shell 后，系统提权（Privilege Escalation）通常基于系统配置疏漏、权限设置不当或漏洞。常见的提权途径主要分为 Linux 和 Windows 两类：

**Linux / Unix 常见提权途径**
- **Sudo 配置缺陷**：通过 `sudo -l` 查看当前用户权限。若存在无需密码（`NOPASSWD`）执行的命令，或可执行包含 Shell 逃逸功能的程序（如 `find`、`vim`、`less` 等），可能导致提权。
- **SUID / SGID 误用**：某些高权限（如 root）拥有的文件被赋予了 SUID 权限标志。若这些二进制文件本身支持执行命令或存在路径注入风险，可被用于提升权限。
- **内核漏洞**：未及时打补丁的旧版本操作系统内核可能存在本地提权（LPE）漏洞（如 Dirty COW、Dirty Pipe 等）。
- **定时任务与服务误配置**：以高权限（如 root）定期运行的 Cron Job，若其调用的脚本或路径对低权限用户可写，可通过修改脚本内容获取高权限。
- **Capabilities 权限过大**：Linux 将 root 权限细分为具体的 Capabilities。若赋予特定程序如 `cap_setuid` 或 `cap_dac_override` 等过大权限，可能引发逃逸。
- **凭据与信息泄露**：检查环境变量、历史命令（如 `.bash_history`）、配置文件、数据库连接串或备份文件中的明文密码与私钥。

**Windows 常见提权途径**
- **服务配置不妥**：
    - **未加引号的服务路径（Unquoted Service Paths）**：路径中包含空格且未加双引号，且低权限用户在路径目录下拥有写入权限。
    - **弱服务权限 / 二进制文件可写**：低权限账户对高权限服务的二进制文件或服务配置本身具备修改权限。
- **令牌模拟（Token Impersonation）**：若当前账户具备特定特权（如 `SeImpersonatePrivilege` 或 `SeAssignPrimaryTokenPrivilege`），可利用系统机制模拟高权限令牌。
- **系统/内核漏洞**：未安装关键安全更新的 Windows 系统可能存在本地提权漏洞（如针对 Win32k 或 ALPC 的漏洞）。
- **凭据提取**：从注册表（如 `AutoLogon` 键值）、无人值守安装文件（`Unattend.xml`）、SAM 数据库或内存中提取高权限账号密码。

**安全加固与防御建议**
- **最小权限原则**：严格限定 Sudo 授权与服务运行账户，避免使用 root 或 SYSTEM 权限运行非必要服务。
- **定期补丁管理**：及时更新操作系统内核及第三方组件，修复已知本地提权漏洞。
- **配置与权限审计**：清理不必要的 SUID 标志，规范服务安装路径与文件 ACL，禁止在系统文件或脚本中明文存储凭据。
