**rbash 限制（终端逃逸）：**
- 输入 `vi` 进入编辑器（或 `vi flag3.txt`）。
- 在 `vi` 界面中按下 `:` 键进入命令模式。
- 输入 `:set shell=/bin/bash` 并回车。
- 再次输入 `:shell` 并回车，此时你就会获得一个正常的 bash 终端。
- 逃逸后补充环境变量（让常用命令恢复正常）： `export PATH=$PATH:/bin:/usr/bin`
	- **`PATH` 环境变量机制**：在 Linux 中输入一个命令（如 `ls`、`cat`）时，系统不会全盘搜索，而是去 `$PATH` 变量定义的路径列表中，按顺序寻找对应的同名可执行文件。如果路径里没有，就会提示 `command not found`。
	- **rbash 的封锁策略**：为了限制你的操作，`rbash`（受限 Shell）通常会将 `$PATH` 修改为一个极度阉割的特殊目录（比如只留一两个受限软链接），把 `/bin` 和 `/usr/bin` 等存放系统常用工具的目录全部清掉。
	- **语法拆解与恢复过程**：
	    - **`$PATH`**：读取当前现有的 `PATH` 变量值。
	    - **`:/bin:/usr/bin`**：冒号 `:` 是 PATH 变量中的路径分隔符。这部分意思是把 `/bin`（存放基础系统命令）和 `/usr/bin`（存放大部分用户应用命令）拼接在旧路径后面。
	    - **`export`**：重新将修改后的 `PATH` 声明为全局环境变量，使其在当前终端会话及后续运行的子进程中生效。

**发现还是有很多命令用不了则需要设置环境变量，讲很多二进制工具加载到当前环境中**
`export PATH=/bin:/usr/bin:/sbin:/usr/sbin:$PATH`
这行命令的作用是**重置并修复 Linux 的可执行文件搜索路径（PATH 环境变量）**，将系统最核心的命令目录优先追加回搜索列表中，确保 `sudo`、`wget` 等基础命令恢复正常使用。
详细拆解如下：
- **`export`**：将定义的变量提升为“环境变量”，使其不仅在当前 Shell 生效，还会传递给当前 Shell 派生的所有子进程与子命令。
- **`PATH=`**：重新赋值 `PATH` 变量。`PATH` 决定了你在终端输入一个命令时，系统按照什么顺序去磁盘目录里寻找同名的可执行文件。
- **路径与冒号 `:`**：冒号在 PATH 变量中代表**目录分隔符**。系统会严格按照**从左到右**的顺序依次检索：
    - `/bin`：存放普通用户最基础的系统级核心命令（如 `ls`、`cat`、`cp`、`bash`）。
    - `/usr/bin`：存放绝大多数用户层面的常用应用程序（如 `git`、`wget`、`python`）。
    - `/sbin`：存放系统管理员（root）核心管理工具（如 `fdisk`、`ip`、`reboot`）。
    - `/usr/sbin`：存放系统管理员的高级服务命令（如 `sshd`、`useradd`）。
- **`:$PATH`**：保留并拼接**旧的 PATH 变量值**。把它挂在最后面，既能保留之前设置的路径，又确保了系统标准目录优先被搜索。
