## IP被锁，登陆一次成功账号就解锁IP
- 如果远程用户登录失败次数过多，则锁定其尝试访问的帐户。
- 如果远程用户在短时间内连续尝试登录次数过多，则屏蔽该用户的 IP 地址。

这两种方法都能提供不同程度的保护，但都不是万无一失的，尤其是在使用有缺陷的逻辑实施的情况下。

例如，如果您多次登录失败，您的 IP 地址可能会被屏蔽。在某些实现中，如果 IP 地址所有者成功登录，失败尝试次数的计数器就会重置。这意味着攻击者只需每隔几次尝试就登录自己的帐户，即可避免达到此限制。

## 账号被锁

在这种情况下，只需在字典中定期包含您自己的登录凭据，就足以使这种防御措施几乎失效。
例如，可以使用以下方法绕过这种保护措施：

1. 建立一个可能有效的候选用户名列表。这可以通过用户名枚举来实现，也可以简单地基于常用用户名列表。
2. 确定一个非常小的密码列表，其中只包含你认为至少有一位用户可能拥有的密码。至关重要的是，你选择的密码数量不能超过允许的登录尝试次数。例如，如果你计算出尝试次数上限为 3 次，那么你最多只能选择 3 个密码。
3. 使用 Burp Intruder 之类的工具，将每个选定的密码与每个候选用户名进行尝试。这样，您就可以尝试暴力破解每个帐户而不会触发帐户锁定。您只需要一个用户使用这三个密码中的一个即可攻破帐户。

账户锁定也无法抵御撞库攻击。撞库攻击利用一个庞大的字典`username:password`，其中包含从数据泄露中窃取的真实登录凭证。撞库攻击利用了这样一个事实：许多人会在多个网站上重复使用相同的用户名和密码，因此，字典中一些被盗用的凭证有可能在目标网站上也有效。账户锁定无法抵御撞库攻击，因为每个用户名只会被尝试一次。撞库攻击尤其危险，因为攻击者有时只需一次自动化攻击就能攻破多个不同的账户。
## 账户或密码错误没有计数器不锁定账户，存在的账户多次尝试会被限制次数导致短暂封号差异

## ## HTTP 基本身份验证

尽管HTTP基本身份验证技术历史悠久，但由于其相对简单易用，您有时仍会看到它被使用。在HTTP基本身份验证中，客户端会从服务器接收一个身份验证令牌，该令牌由用户名和密码连接而成，并以Base64编码。此令牌由浏览器存储和管理，浏览器会自动将其添加到`Authorization`每个后续请求的标头中，如下所示：

`Authorization: Basic base64(username:password)`

由于多种原因，这种方法通常不被认为是安全的身份验证方法。首先，它需要在每次请求中重复发送用户的登录凭据。除非网站也实施了HSTS（高级安全存储技术），否则用户凭据很容易在中间人攻击中被窃取。

此外，HTTP 基本身份验证的实现通常不支持暴力破解防护。由于令牌完全由静态值组成，因此很容易受到暴力破解攻击。

HTTP 基本身份验证也特别容易受到与会话相关的攻击，尤其是 CSRF 攻击，它本身无法提供任何保护。

在某些情况下，利用存在漏洞的 HTTP 基本身份验证可能只会让攻击者访问一个看似无关紧要的页面。然而，除了扩大攻击面之外，以这种方式泄露的凭据还可能在其他更机密的场景中被重复使用。
