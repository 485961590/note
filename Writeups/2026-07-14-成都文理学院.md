# 成都文理学院 SRC 漏洞挖掘 — 第一次实战

> 目标: cdcas.edu.cn
> 日期: 2026-07-14
> 方法: 三层递进模型（被动收集 -> 轻量探测 -> 定向测试）

---

## 阶段 A: 被动收集

### A2 crt.sh

- 发现学校使用 DNSPod 泛域名证书 (`*.cdcas.edu.cn`)
- crt.sh 仅泄露 4 个具体域名: `www`, `my`, `yxxt`, 裸域
- `yxxt.cdcas.edu.cn` 2015 年 WoSign 证书，后确认已下线
- **教训**: 泛域名证书会掩盖 crt.sh 的发现，必须结合 FOFA/搜索引擎

### A4 FOFA

- 突破泛域名限制，获取 23 个额外子域名
- 全部指向同一 IP `111.231.213.107`
- 同 IP 上还有云南城市建设职业学院（网站群共享服务器）

### A3 搜索引擎

- Bing/Google 搜索未发现新路径

### A5 GitHub/Gitee

- 无泄露发现

### 阶段 A 产出

- 27 个域名（crtsh 4 + FOFA 23）
- 24 个确认为成都文理学院（3 个是云南城建）

## 阶段 B: 轻量探测

### 工具链

- Kali 环境: subfinder + dnsx + httpx
- subfinder 新发现 32 个域名，合并后 56 个

### httpx 指纹结果

- 全部 24 个站点统一: `Apache + HSTS + jQuery`
- 两个异类:
  - `som.cdcas.edu.cn`: 报 WordPress 但实际上是网站群 CMS 误判
  - `sis.cdcas.edu.cn`: 有 Microsoft Word 指纹

### 关键发现: 网站群 CMS

全部 24 个学院/部门子站都是 **"博达/通元网站群内容管理系统"**：
- 纯静态 `.htm` 页面
- HTML 底部: `Produced By CMS 网站群内容管理系统`
- 无登录、无搜索、无参数 **-> 无攻击面**

## 阶段 C: 定向测试

### 1. jwc.cdcas.com — 青果教务管理系统

**技术栈**: IIS 8.5 + ASP.NET + 青果软件

**测试结果**:

| 测试点 | 结论 |
|--------|------|
| 登录 POST `_data/login_home_jd.aspx` | 防用户名枚举，通用错误消息 |
| 忘记密码 `_data/retrievePassword_one.aspx` | 防用户名枚举，存在/不存在返回一致 |
| 验证码 `sys/ValidateCode.ashx` | 默认关闭 |
| 密码加密 | 客户端 MD5，盐值 `13671` 硬编码在 JS |

**代码中发现的内网入口**:
- `http://jwc.cdcas.com/` -> 教务网络管理系统
- `http://cdcasjw.yinghuaonline.com/cdwlxy_jsxsd/` -> 教学一体化服务平台
- `http://172.22.33.151/` -> 教材征订管理系统（内网）
- `https://vgms.fanyu.com/` -> 毕业论文管理系统（第三方）
- `http://sx.cdcas.com/#/index` -> 毕业实习管理系统

### 2. sx.cdcas.com — 毕业实习管理系统

**技术栈**: nginx + Spring Boot (前后端分离)

| 测试点 | 结论 |
|--------|------|
| 登录 API `POST /internship/auth/token` | 参数: username, password, verifyCode, type |
| 认证方式 | Token header (JWT) |
| CORS | `Access-Control-Allow-Origin: *` |
| 状态 | 后端持续 500，不稳定，放弃测试 |

### 3. tushu.cdcas.com — 图书馆 OPAC 检索系统

**技术栈**: nginx + JWT 认证 + CADAL 全文检索

| 测试点 | 结论 |
|--------|------|
| 搜索 API `POST /api/tcc-opac/CDWL/cadal/search` | `q` 参数 |
| `q="大学'"` vs `q="大学"` | 单引号被当作普通字符全文搜索，无注入 |
| 认证 | `getOpenApiAccessToken` 不需要登录即可获取 token |

## 收获与反思

### 技术收获

1. **泛域名证书是信息收集的天敌**: crt.sh 查 `%.edu.cn` 时被通配符隐藏，必须用 FOFA 补全
2. **网站群 CMS 是高校通病**: 24 个外观一样的子站 = 同一个 CMS = 没攻击面，但**它们经常泄露真实系统入口**
3. **真实系统藏在 HTML 里**: jw 页面列出业务系统、lib 页面列出 OPAC 地址，都是关键入口
4. **青果教务防枚举做得比想象中好**: 登录和忘记密码都统一返回，传统用户名枚举无效
5. **OPAC 系统是全文检索不是 SQL**: cadal/search 用的是 Elasticsearch 类引擎，单引号不构成注入

### 方法论收获

- 第一二层做扎实了，但第三层很依赖运气和耐心
- 第一个学校没有直接出洞是正常的，资产收集本身已经很有价值
- 验证"没有洞"也是测试结果，不是浪费时间
