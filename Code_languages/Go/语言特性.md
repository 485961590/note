# Go 语言特性详解

> Go 的设计哲学: **少即是多**。把所有精力放在解决实际问题上, 而不是玩弄语言特性。2009 年由 Google 的 Rob Pike、Ken Thompson、Robert Griesemer 设计, 目标是对抗 C++ 的复杂性膨胀。

---

## 一、语法极简主义

### 1.1 只有 25 个关键字

```
break    default     func   interface select
case     defer       go     map       struct
chan     else        goto   package   switch
const    fallthrough if     range     type
continue for         import return    var
```

对比: Java 有 50+ 关键字, C++ 有 80+。Go 把能砍的都砍了 -- 没有 `while`(用 `for` 代替), 没有 `class`(用 `struct` + 方法), 没有 `throw` / `catch`(用 error 返回值), 没有 `extends` / `implements`。

### 1.2 短变量声明 `:=`

```go
// 类型推断 + 声明 + 赋值 一步完成
name := "hello"          // string
count := 42              // int
items := []string{"a"}   // []string
m := map[string]int{}    // map[string]int

// 等价于:
var name string = "hello"
```

`:=` 只能在函数内使用, 包级别变量必须用 `var`。

### 1.3 多返回值与 error 模式

Go 没有 try-catch 异常机制。函数通过返回 `(result, error)` 元组传递失败信息, 调用方显式检查:

```go
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("除数不能为零")
    }
    return a / b, nil
}

result, err := divide(10, 0)
if err != nil {
    // 处理错误
    return
}
// 使用 result
```

**为什么不用异常?** 异常让控制流变得隐式 -- 你不知道一个函数调用可能跳转到哪里去。`if err != nil` 虽然看起来啰嗦, 但每一条执行路径都是显式的、可追踪的。这也是 Go 代码读起来"无聊但安全"的原因。

### 1.4 命名返回值

```go
func split(sum int) (x, y int) {
    x = sum * 4 / 9
    y = sum - x
    return  // 裸 return, 自动返回 x 和 y(当前值)
}
```

返回值变量在签名中声明, 自动初始化为零值。裸 `return` 在短函数里方便, 长函数里会降低可读性。

### 1.5 `_` 空白标识符

```go
// 忽略不需要的返回值
result, _ := divide(10, 3)

// 忽略不需要的 import("_" 导入仅执行 init 函数)
import _ "net/http/pprof"

// 忽略 range 中的索引
for _, v := range items { ... }
```

`_` 不是变量, 不能读取。它就是一个黑洞 -- 写进去的东西就被丢弃了。

### 1.6 `for` 是唯一的循环关键字

Go 只有 `for`, 没有 `while` 和 `do-while`:

```go
// 标准 for
for i := 0; i < 10; i++ { ... }

// 相当于 while
for condition { ... }

// 无限循环
for { ... }
```

## 二、类型系统

### 2.1 预声明类型总览

```
bool
string
int  int8  int16  int32  int64
uint uint8 uint16 uint32 uint64 uintptr
byte      // uint8 的别名
rune      // int32 的别名, 表示一个 Unicode 码点
float32 float64
complex64 complex128
```

`int` / `uint` 大小跟随平台(32 位或 64 位)。没有 `char` 类型 -- 用 `byte`(单字节) 或 `rune`(Unicode 字符)。

### 2.2 零值(Zerovalue) -- Go 没有"未初始化"

所有类型声明后都有确定的值, 不存在未定义行为:

```go
var i int          // 0
var f float64      // 0.0
var s string       // ""(空字符串, 不是 nil)
var b bool         // false
var p *int         // nil
var sl []int       // nil, 但 len(sl)==0, 可以 append
var m map[int]int  // nil, 读取返回零值, 写入会 panic
var ch chan int    // nil, 读写都会永久阻塞
```

这是 Go 安全性的基石之一: 不存在 C/C++ 中"未初始化变量持有随机内存值"的问题。

### 2.3 类型转换 -- 必须显式, 没有隐式

```go
var i int = 42
var f float64 = float64(i)  // 必须显式转换
var u uint = uint(f)

// 下面这行编译器直接报错:
// var x float64 = i  // cannot use i (type int) as type float64
```

不存在 C 语言的隐式类型提升, 也不存在 JavaScript 的 `"1" + 1 = "11"` 这种行为。类型安全是编译期保证的。

### 2.4 类型别名与自定义类型

```go
// 自定义类型 -- 新类型, 与原类型不兼容
type Celsius float64
type Fahrenheit float64

var c Celsius = 100
var f Fahrenheit = Fahrenheit(c * 9/5 + 32)  // 必须转换

// 类型别名 -- 完全等价, 可互换
type MyInt = int  // Go 1.9+, 注意等号
var x MyInt = 1
var y int = x  // 不需要转换
```

关键在于有没有 `=` 号。`type A B` 创建新类型, `type A = B` 创建别名。

### 2.5 `const` 与无类型常量

```go
const Pi = 3.14159  // 无类型浮点常量
const Zero = 0      // 无类型整数常量

// 无类型常量可以赋值给不同类型, 不需要显式转换:
var f float64 = Pi
var c complex128 = Pi  // 合法

// 可以使用 iota 批量定义枚举式常量:
const (
    Monday = iota + 1  // 1
    Tuesday            // 2
    Wednesday          // 3
    Thursday           // 4
)
```

Go 的 const 只能用于编译时可确定的值(数字、字符串、布尔), 不能像 JavaScript 的 `const` 那样用于运行时计算。

## 三、复合类型

### 3.1 数组 -- 固定大小, 是值类型

```go
var arr [3]int = [3]int{1, 2, 3}
arr2 := [...]int{1, 2, 3}  // 编译器自动推断长度

// 数组是值类型, 赋值会复制整个数组!
a := [3]int{1, 2, 3}
b := a       // b 是 a 的完整副本
b[0] = 100   // a[0] 仍然是 1
```

> 数组长度是类型的一部分, `[3]int` 和 `[5]int` 是不同的类型。实际开发中数组使用较少, 大部分场景用切片代替。

### 3.2 切片(Slice) -- 动态数组视图

切片是 Go 最重要的数据结构。它不持有数据, 只是底层数组的一个"窗口":

```go
// 切片的内部结构(运行时):
// type slice struct {
//     ptr    *T     // 指向底层数组的指针
//     len    int    // 当前元素个数
//     cap    int    // 底层数组容量
// }

// 创建切片
s1 := []int{1, 2, 3}        // 字面量
s2 := make([]int, 3, 5)     // len=3, cap=5, 前 3 个元素为零值
s3 := arr[1:3]              // 从数组切出来, 共享底层数据

// append -- 自动扩容
s := []int{1, 2}
s = append(s, 3)        // [1 2 3]
s = append(s, 4, 5, 6)  // [1 2 3 4 5 6]
```

**扩容机制:** 当 `len` 逼近 `cap` 时, `append` 会分配一个更大的底层数组(新容量一般是原来的 2 倍), 把旧数据复制过去, 返回指向新数组的切片。原来的切片不受影响(因为切片是值传递)。

**重要陷阱 -- 切片共享底层数组:**

```go
a := []int{1, 2, 3}
b := a[:2]     // b 和 a 指向同一个底层数组
b[0] = 100     // a 变成了 [100, 2, 3]!

// 用 copy 做深拷贝:
c := make([]int, len(a))
copy(c, a)     // c 是独立副本
```

### 3.3 Map -- 哈希表

```go
// 创建
m := make(map[string]int)
m := map[string]int{"a": 1, "b": 2}

// 读取 -- 返回两个值(value 和 是否存在)
v, ok := m["key"]
if !ok {
    // key 不存在
}

// 删除
delete(m, "key")

// 遍历 -- 顺序是随机的!(设计如此, 防止代码依赖遍历顺序)
for k, v := range m {
    fmt.Println(k, v)
}
```

> nil map 可以读取(返回零值), 但写入会 panic。所以 `var m map[string]int` 后需要 `m = make(map[string]int)` 才能写入。

### 3.4 Struct -- 数据的组合

```go
type Person struct {
    Name string
    Age  int
}

// 创建
p1 := Person{"Alice", 30}          // 按顺序赋值
p2 := Person{Name: "Bob", Age: 25} // 按字段名赋值(推荐)
p3 := Person{Name: "Eve"}          // Age 为零值

// 访问
p1.Name = "Charlie"
fmt.Println(p1.Age)

// 匿名结构体 -- 一次性使用
temp := struct {
    X, Y int
}{1, 2}
```

### 3.5 Struct 嵌入(Embedding) -- 组合优于继承

Go 没有继承, 但可以通过嵌入实现代码复用:

```go
type Animal struct {
    Name string
}

func (a Animal) Speak() {
    fmt.Println("...")
}

type Dog struct {
    Animal  // 嵌入(匿名字段), Dog 获得了 Animal 的所有字段和方法
    Breed string
}

d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Golden"}
fmt.Println(d.Name)   // 直接访问嵌入类型的字段(语法糖)
d.Speak()             // 直接调用嵌入类型的方法

// 也可以"重写"方法:
func (d Dog) Speak() {
    fmt.Printf("%s: Woof!\n", d.Name)
}
```

这就是 **"组合优于继承"** 的体现。`Dog` 不是 `Animal` 的子类, 而是包含了 `Animal` 的功能。Go 的接口和嵌入结合, 做到了比传统 OOP 更松耦合的设计。

## 四、函数与方法

### 4.1 函数是一等公民

```go
// 函数赋值给变量
add := func(a, b int) int { return a + b }

// 函数作为参数
func apply(fn func(int, int) int, a, b int) int {
    return fn(a, b)
}

// 函数闭包
func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}
c := counter()
c()  // 1
c()  // 2
```

### 4.2 方法 -- 带接收者的函数

```go
type Counter struct {
    value int
}

// 值接收者 -- 操作的是副本
func (c Counter) Value() int {
    return c.value
}

// 指针接收者 -- 操作的是原对象
func (c *Counter) Increment() {
    c.value++  // 修改原对象的 value
}
```

**选择规则:**
- 需要修改接收者 -> 用指针接收者
- 接收者是大型结构体 -> 用指针接收者避免复制
- 接收者不需要被修改且是小型类型 -> 值接收者, 或为了一致性统一用指针

> 值接收者和指针接收者不应混用。如果一个类型既有值接收者方法又有指针接收者方法, 说明设计需要重新审视。

### 4.3 可变参数

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)       // 6
sum([]int{1, 2}...) // 展开切片传入
```

### 4.4 defer -- 延迟执行

```go
func readFile(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close()  // 保证函数返回前关闭文件

    // 处理文件...
    return nil
}
```

`defer` 的核心价值: **资源申请和释放写在一起**, 不会忘记。多个 `defer` 按后进先出(LIFO)顺序执行。`defer` 在 return 之后、函数真正返回之前执行。

> `defer` 对性能敏感的热路径有微小开销(纳秒级)。在普通业务代码中可以忽略, 在纳秒级优化的场合需要评估。

## 五、接口(Interface) -- 隐式实现

这是 Go 最精妙的设计之一。

### 5.1 基本概念

```go
// 定义接口
type Writer interface {
    Write([]byte) (int, error)
}

// 自定义类型
type MyWriter struct{}

// 只要实现了 Write 方法, 就自动实现了 Writer 接口
// 不需要写 implements 关键字!
func (m MyWriter) Write(data []byte) (int, error) {
    // ...
    return len(data), nil
}

// 使用 -- 任何实现了 Write 的类型都可以传进来
func save(w Writer, data []byte) error {
    _, err := w.Write(data)
    return err
}
```

**为什么隐式实现是天才设计?** 在 Java/C# 中, 你要实现一个接口, 必须在定义类时就写上 `implements`。如果一个类来自第三方库, 你无法让它"实现"你的接口。在 Go 中, 只要第三方类型有对应的方法, 它自动就满足你的接口 -- 不需要修改第三方代码, 也不需要在类型定义处耦合。

### 5.2 空接口 `interface{}`

```go
// interface{} 能接受任何类型(Go 1.18 后建议用 any 代替)
var x interface{} = "hello"
x = 42
x = struct{}{}

// 类型断言
s, ok := x.(string)  // ok 为 false 时不 panic
if ok {
    fmt.Println(s)
}

// 类型 switch
switch v := x.(type) {
case string:
    fmt.Println("字符串:", v)
case int:
    fmt.Println("整数:", v)
default:
    fmt.Printf("未知类型: %T\n", v)
}
```

> Go 1.18 引入 `any` 作为 `interface{}` 的别名: `var x any = "hello"`。两者完全等价, `any` 更可读。

### 5.3 接口的内部结构

```
interface value = (动态类型, 动态值)

具体来说:
+--------------------------+
|  itab ptr  (类型表)       | --> 包含了接口方法的函数指针
|  data ptr  (数据指针)     | --> 指向实际的值
+--------------------------+
```

**nil 接口 vs nil 底层值 -- Go 新手最常见的坑:**

```go
var w io.Writer        // w == nil(接口本身是 nil)
var buf *bytes.Buffer  // buf == nil(指针是 nil)
w = buf                // w != nil! 接口持有类型信息, 虽然值是 nil

// 判断方式:
if w != nil {
    w.Write([]byte("hi"))  // panic! 虽然接口非 nil, 但底层值是 nil
}
```

接口为 nil 的条件是: **既没有类型信息, 也没有值信息**。一旦把一个有类型的变量赋值给接口, 即使这个变量的值是 nil, 接口也不再是 nil。

### 5.4 常见标准库接口

```go
// io 包 -- 一切 I/O 的基石
type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}

// fmt 包 -- 控制打印行为
type Stringer interface {
    String() string  // 实现后, fmt.Println 会用这个方法
}

// sort 包 -- 自定义排序
type Interface interface {
    Len() int
    Less(i, j int) bool
    Swap(i, j int)
}

// error -- 最简单的接口, 只有一个方法
type error interface {
    Error() string
}
```

## 六、并发 -- Go 的杀手级特性

### 6.1 Goroutine -- 轻量级协程

```go
// 启动一个 goroutine
go func() {
    fmt.Println("在另一个 goroutine 中运行")
}()

// 带参数的 goroutine
for i := 0; i < 10; i++ {
    go func(n int) {
        fmt.Println(n)
    }(i)  // 注意: 必须传参, 不要闭包捕获循环变量
}
```

**goroutine 不是线程。** 它是用户态的轻量级协程:

| 特性 | 线程 | Goroutine |
|------|------|-----------|
| 初始栈大小 | ~1MB | ~2KB(可动态增长) |
| 创建成本 | 高(内核态切换) | 低(~几微秒) |
| 调度器 | 操作系统内核调度 | Go 运行时调度(GMP 模型) |
| 数量 | 几百到几千 | 可以轻松跑几十万个 |

**GMP 调度模型:**
- **G**(Goroutine): 待执行的任务
- **M**(Machine): 操作系统线程, 真正执行计算
- **P**(Processor): 逻辑处理器, 持有 G 的本地队列

一个 P 绑定一个 M, P 从自己的队列中取 G 交给 M 执行。当 M 阻塞(系统调用), P 会迁移到另一个 M 上继续调度其他 G。

**核心原则:** 不要人为限制 goroutine 数量。Go 的调度器就是设计来处理大量 goroutine 的。需要限流时用 channel 或 semaphore, 而不是自己控制创建数量。

### 6.2 Channel -- goroutine 之间的通信管道

```go
// 创建 channel
ch := make(chan int)       // 无缓冲(同步)
ch := make(chan int, 10)   // 有缓冲(异步, 缓冲区大小 10)

// 发送和接收
ch <- 42       // 发送
value := <-ch  // 接收

// 关闭 channel
close(ch)

// range 遍历 channel(close 后自动退出)
for v := range ch {
    fmt.Println(v)
}

// 单向 channel -- 用于函数签名, 限制调用方的操作
func producer(out chan<- int) {  // 只能发送
    out <- 42
}
func consumer(in <-chan int) {   // 只能接收
    v := <-in
    fmt.Println(v)
}
```

**有缓冲 vs 无缓冲:**
- 无缓冲 `make(chan T)`: 发送方阻塞直到接收方就绪 = 同步通信
- 有缓冲 `make(chan T, n)`: 缓冲区未满时发送不阻塞, 缓冲区为空时接收阻塞 = 异步队列

**channel 状态总结:**

| 操作 | nil channel | 已关闭 channel | 正常 channel |
|------|-------------|----------------|--------------|
| 发送 | 永久阻塞 | panic | 阻塞或成功 |
| 接收 | 永久阻塞 | 返回零值(不阻塞) | 阻塞或成功 |
| 关闭 | panic | panic | 成功 |

> 发送方负责关闭 channel, 接收方不应关闭。往已关闭的 channel 发送会 panic。

### 6.3 select -- 多路复用

```go
select {
case v := <-ch1:
    fmt.Println("从 ch1 收到:", v)
case ch2 <- 42:
    fmt.Println("向 ch2 发送成功")
case <-time.After(1 * time.Second):
    fmt.Println("超时")
default:
    fmt.Println("没有就绪的 channel")
}
```

`select` 的语义:
- 多个 case 同时就绪 -> 随机选一个(防止饿死)
- 所有 case 都阻塞 -> 走 default(如果有), 否则 select 本身阻塞
- 没有 case -> `select {}` 永久阻塞(常用于 main 函数防止退出)

### 6.4 经典并发模式

**扇出(Fan-out) -- 一个生产者, 多个消费者:**

```go
func fanOut(in <-chan int, workers int) []<-chan int {
    outs := make([]<-chan int, workers)
    for i := 0; i < workers; i++ {
        ch := make(chan int)
        outs[i] = ch
        go func(out chan<- int) {
            defer close(out)
            for v := range in {
                // 处理 v
                out <- v * 2
            }
        }(ch)
    }
    return outs
}
```

**扇入(Fan-in) -- 多个生产者, 一个消费者:**

```go
func fanIn(channels ...<-chan int) <-chan int {
    out := make(chan int)
    var wg sync.WaitGroup
    for _, ch := range channels {
        wg.Add(1)
        go func(c <-chan int) {
            defer wg.Done()
            for v := range c {
                out <- v
            }
        }(ch)
    }
    go func() {
        wg.Wait()
        close(out)
    }()
    return out
}
```

**Pipeline -- 流水线模式:**

```go
// stage1: 产生数字
func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for _, n := range nums {
            out <- n
        }
    }()
    return out
}

// stage2: 平方
func square(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for n := range in {
            out <- n * n
        }
    }()
    return out
}

// 串联
c := generate(1, 2, 3, 4)
out := square(c)
```

### 6.5 sync 包 -- 传统同步原语

channel 不是万能药, 有些场景用锁更清晰:

```go
// Mutex -- 互斥锁
var mu sync.Mutex
var counter int

func increment() {
    mu.Lock()
    counter++
    mu.Unlock()
}

// RWMutex -- 读写锁(多读单写)
var rw sync.RWMutex
func read() int {
    rw.RLock()
    defer rw.RUnlock()
    return counter
}

// WaitGroup -- 等待一组 goroutine 完成
var wg sync.WaitGroup
for i := 0; i < 5; i++ {
    wg.Add(1)
    go func(n int) {
        defer wg.Done()
        // 工作...
    }(i)
}
wg.Wait()  // 等待所有 goroutine 完成

// Once -- 只执行一次
var once sync.Once
once.Do(func() { ... })  // 并发安全, 全局只执行一次
```

**选择建议:** 优先用 channel 做通信, 用 Mutex 保护共享状态。不是"只用 channel", 而是"用对工具"。

## 七、包管理与模块

### 7.1 包的基本规则

```go
package mypackage  // 每个文件第一行

import (
    "fmt"                     // 标准库
    "github.com/user/pkg"     // 第三方
    "./local"                 // 相对路径(不推荐)
```

- 同一目录下的所有 `.go` 文件必须属于同一个 package
- 首字母大写 = 导出(公开), 小写 = 包内私有
- `main` 包中的 `main()` 函数是程序入口
- `init()` 函数在包初始化时自动执行, 先于 `main()`

### 7.2 Go Modules(Go 1.11+)

```bash
go mod init github.com/user/project  # 初始化模块

go mod vendor                         # 创建 vendor 目录
```

`go.mod` 文件示例:

```

    github.com/gin-gonic/gin v1.9.1

    ...

```

`go.sum` 记录每个依赖的哈希值, 保证构建可重现。两个文件都应提交到版本控制。

## 八、错误处理 -- 没有异常的世界

### 8.1 基本模式

```go
func doSomething() error {
    data, err := readFile("config.json")
    if err != nil {
        return fmt.Errorf("读取配置失败: %w", err)
    }
    // 处理 data...
    return nil
}
```

### 8.2 错误包装与解包(Go 1.13+)

```go
// 包装错误 -- 用 %w 保留错误链
err := fmt.Errorf("步骤1失败: %w", originalErr)

// 解包 -- errors.Unwrap
unwrapped := errors.Unwrap(err)

// 判断错误类型
if errors.Is(err, os.ErrNotExist) {
    // 错误链中某个环节是 os.ErrNotExist
}

// 提取特定错误类型
var pathError *os.PathError
if errors.As(err, &pathError) {
    fmt.Println("路径:", pathError.Path)
}
```

### 8.3 panic 和 recover

```go
// panic -- 类似"崩溃退出", 但可以被 recover 捕获
func riskyOperation() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("从 panic 中恢复:", r)
        }
    }()
    panic("出大事了!")  // 触发 panic
}
```

**使用场景:**
- `panic`: 只应用于不可恢复的错误(如程序启动时配置文件损坏), 类似 Java 的 `Error`
- `recover`: 少数场景使用 -- 如 HTTP handler 中捕获单个请求的 panic 防止整个服务崩溃
- **业务错误永远用 error 返回值, 不要用 panic/recover 当异常处理用**

## 九、泛型(Go 1.18+)

### 9.1 基本语法

```go
// 泛型函数
func Max[T int | float64](a, b T) T {
    if a > b {
        return a
    }
    return b
}

// 泛型结构体
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(item T) {
    s.items = append(s.items, item)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T
        return zero, false
    }
    item := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return item, true
}
```

### 9.2 类型约束

```go
// 预定义约束
func Print[T any](v T) { ... }          // any: 任何类型
func Sum[T comparable](s []T) { ... }  // comparable: 可比较的类型

// 自定义约束
type Number interface {
    int | int32 | int64 | float32 | float64
}

func Add[T Number](a, b T) T {
    return a + b
}
```

> Go 泛型的设计哲学: 只解决参数多态问题, 不引入 C++ 模板那样的元编程能力。泛型主要用于数据结构和算法的复用, 不应为了"酷"而滥用。

## 十、内存管理与 GC

### 10.1 栈与堆 -- 逃逸分析

Go 的编译器会做**逃逸分析**(escape analysis), 自动决定变量分配在栈还是堆上:

```go
func stackAlloc() int {
    x := 42
    return x  // x 分配在栈上(没有逃逸)
}

func heapAlloc() *int {
    x := 42
    return &x  // x 逃逸到堆上(函数返回后指针仍被使用)
}
```

编译器比你更了解该分配在哪里。可以用 `go build -gcflags="-m"` 查看逃逸分析结果。

### 10.2 垃圾回收

Go 的 GC 是**并发三色标记-清除**, 主要特点:
- 与用户代码并发执行, 停顿极短(通常 <1ms)
- 自动触发, 不需要手动 `malloc/free`
- 通过 `GOGC` 环境变量控制触发阈值(默认 100, 即堆大小翻倍时触发 GC)

```bash
GOGC=200 go run main.go   # 降低 GC 频率(更占内存)
GOGC=50 go run main.go    # 提高 GC 频率(更节省内存)
```

## 十一、编译与部署

### 11.1 交叉编译

Go 的一大优势: 一个命令编译到任何平台:

```bash
GOOS=linux   GOARCH=amd64 go build          # 编译到 Linux 64 位
GOOS=windows GOARCH=amd64 go build          # 编译到 Windows 64 位
GOOS=darwin  GOARCH=arm64 go build          # 编译到 macOS ARM(M1/M2)
GOOS=linux   GOARCH=arm   go build          # 编译到 Linux ARM
```

编译产物是**单一静态二进制文件**, 没有依赖, 复制过去就能跑。

### 11.2 常用构建命令

```bash
go build             # 编译
go build -o name     # 指定输出文件名
go build -ldflags "-s -w"  # 去掉调试信息, 减小体积
go run .             # 编译并运行
go install           # 编译并安装到 $GOPATH/bin
go fmt ./...         # 格式化所有代码
go vet ./...         # 静态分析
go test ./...        # 运行所有测试
go test -bench=.     # 运行基准测试
go test -cover       # 测试覆盖率
go test -race        # 竞态检测
```

### 11.3 条件编译(Build Tags)

```go
//go:build linux
// +build linux

package main

// 仅在 Linux 下编译的代码
```

也可以通过文件名后缀: `file_linux.go` 只在 Linux 下编译, `file_386.go` 只在 32 位 x86 下编译。

## 十二、Go 的"没有" -- 被刻意移除的特性

| 没有的特性 | 替代方案 | 设计理由 |
|-----------|---------|---------|
| 类继承 | Struct 嵌入 + 接口 | 避免深层继承链, 组合更灵活 |
| 方法重载 | 不同函数名 | 重载让代码行为取决于参数类型, 降低可读性 |
| 默认参数 | 函数选项模式(Functional Options) | 默认参数引入隐式行为 |
| 异常(try-catch) | 多返回值 error | 显式错误处理, 控制流可见 |
| 泛型(Go 1.18 前) | interface{}/代码生成 | 保持语言简洁(已通过泛型补上) |
| 注解(Annotation) | 结构体字段 tag | 编译时处理, 不引入运行时反射开销 |
| 构造函数 | NewXxx() 工厂函数 | 约定优于机制 |
| 三元运算符 `?:` | `if-else` | 三元容易写出难以阅读的嵌套表达式 |
| 隐式类型转换 | 显式转换 | 避免意外的精度丢失/溢出 |

## 十三、编写习惯与惯用法

### Go Proverbs(Go 谚语)

- **"Don't communicate by sharing memory; share memory by communicating."** -- 用 channel 传递数据, 而不是用锁保护共享内存。
- **"The bigger the interface, the weaker the abstraction."** -- 接口要小(单方法接口是常态), 接口越大抽象越弱。
- **"interface{} says nothing."** -- `interface{}` 不传达任何类型信息, 能不用就别用。
- **"A little copying is better than a little dependency."** -- 少量复制好过引入新依赖。
- **"Clear is better than clever."** -- 清晰优于聪明。
- **"Errors are values."** -- 错误就是普通值, 像处理其他值一样处理它。
- **"Don't just check errors, handle them gracefully."** -- 不要只是检查错误, 要优雅地处理。
- **"Gofmt's style is no one's favorite, yet gofmt is everyone's favorite."** -- gofmt 的风格谁都不喜欢, 但 gofmt 本身大家都喜欢。(因为消除了风格争论)

### 常见惯用法

```go
// "comma ok" 模式
if v, ok := m["key"]; ok {
    // key 存在
}

// 函数选项模式
type Server struct {
    timeout time.Duration
    maxConn int
}
type Option func(*Server)
func WithTimeout(d time.Duration) Option { return func(s *Server) { s.timeout = d } }
func NewServer(opts ...Option) *Server {
    s := &Server{timeout: 30 * time.Second, maxConn: 100}
    for _, opt := range opts { opt(s) }
    return s
}

// 循环中的 goroutine 闭包陷阱
for _, item := range items {
    item := item  // 在循环体内重新声明! 否则所有 goroutine 共享同一个 item
    go func() {
        process(item)
    }()
}
```

## 记忆要点

- **25 个关键字** -- 极简语法, 半天可上手
- **goroutine + channel** -- Go 并发模型的灵魂, 轻量协程 + CSP 通信
- **隐式接口** -- 解耦设计的神器, 不需要提前声明 implements
- **零值机制** -- 没有未初始化变量, 消除一类常见 bug
- **error 返回值** -- 异常用 error, 崩溃用 panic, 不用 try-catch
- **组合优于继承** -- struct 嵌入 + 接口, 不用类继承体系
- **`:=` 短声明** -- 类型推断让代码简洁但不失类型安全
- **defer** -- 资源清理写在一起, 代码整洁且安全
- **单一二进制编译** -- 交叉编译, 无运行时依赖, 部署简单
- **清晰优于聪明** -- Go 代码读起来"无聊", 但易懂、易维护、团队协作成本低
